## 1. 源 → 组件结构映射(`tree.js` 的命令式建 DOM → 递归组件)

源 `createLiElement` / `renderNode` 的产物(以 treeData 为例):

```html
<ul class="tree">
  <li class="node node_folder" style="--depth:0" data-id="1">      <!-- 根:depth 0 -->
    <div class="row primaryRow" style="padding-left:0px">
      <div class="leftTrapezoid"></div>
      <span class="literal">根文件夹名称</span>
    </div>
    <ul class="children">
      <li class="node node_folder isCollapsed" style="--depth:1" data-id="2">  <!-- 文件夹:depth≥1 默认折叠 -->
        <div class="row folderRow" style="padding-left:21px">
          <i class="iconfont icon-icon-right"></i>                  <!-- ← 源 icon-right -->
          <span class="literal">子文件夹A名称</span>
        </div>
        <ul class="children">
          <li class="node node_file" style="--depth:2" data-id="3"> <!-- 文件 -->
            <div class="row fileRow" style="padding-left:42px">
              <i class="iconfont icon-icon_file"></i>               <!-- ← 源 icon-file -->
              <span class="literal">文件A-1名称</span>
            </div>
          </li>
        </ul>
      </li>
    </ul>
  </li>
</ul>
```

> ↑ 是**源**的命令式产物(根 `<li>` 主类是源里的 `node`);Vue 版几处不同:① 根类 `node` → `tree-node`(对齐组件名,见 §4);② 行缩进**不写行内 `padding-left`**,改由 CSS `calc(var(--depth) * var(--tree-indent))` 算(`--depth` 仍写在 `<li>`)。各**多词**内部类同样按本项目「CSS 类名用连字符连词」习惯改写:`node_folder`/`node_file` → `node-folder`/`node-file`、`isCollapsed` → `is-collapsed`、`primaryRow`/`folderRow`/`fileRow` → `primary-row`/`folder-row`/`file-row`、`leftTrapezoid` → `left-trapezoid`(源里如上,仍为下划线/驼峰)。

**三种 row 的规则**(源 `createLiElement`):

| 条件 | row 类 | 内容 |
|---|---|---|
| `depth === 0`(根) | `row primaryRow` | `.leftTrapezoid` 梯形 + `.literal` 文字(**无图标**) |
| `depth > 0` 且 `type==='folder'` | `row folderRow` | `<i class="iconfont icon-icon-right">` + `.literal` |
| `depth > 0` 且 `type==='file'` | `row fileRow` | `<i class="iconfont icon-icon_file">` + `.literal` |

其它不变量:
- `<li>` 类名 = `tree-node node-${type}`(根类 `tree-node` 对齐组件名 `TreeNode`,同 `catalogue-tree`/`article-pane` 规则;`node-${type}` 是节点类型修饰类、语义独立,不随之改);`--depth` 写在 `<li>`(连线 CSS 用);`data-id`(Step 2 点击用,静态先带上);
- folder 折叠时 `<li>` 加 `is-collapsed`;
- `.row` 左缩进 = `depth × --tree-indent`:Vue 版**改由 CSS `calc(var(--depth) * var(--tree-indent))` 算**(不像源那样 JS 写行内 `padding-left`),与连接线 `--branch-x` 同源,`21px` 只在 `--tree-indent` 出现一次;
- 有 children → 追加 `<ul class="children">` 递归。

## 2. 节点类型枚举 + 数据(扩充 `lib/enum.js` + 新建 `treeData.js`)

### 2.1 扩充 `src/lib/enum.js`:`CatalogueNodeType` + `RenderPhase`

本份往**已存在的** `src/lib/enum.js`(已有 `ActionType`/`HoverPhase`/`FocusPhase`)新增**两个**枚举,都沿用同一写法(`Object.freeze` + `@typedef`,文件内用小写 `{string}` + `- 说明`)。

#### `CatalogueNodeType`(节点类型)

`CatalogueNode.type` 的取值收敛成一个枚举:

```js
/**
 * @typedef {Object} CatalogueNodeType 本枚举项用于标识目录树节点的类型
 * @property {string} folder - 标识节点为文件夹(可含子节点)
 * @property {string} file - 标识节点为文件(叶子,无 children)
 * */
const CatalogueNodeType = Object.freeze({
    folder: 'folder',
    file: 'file',
})
```

**⚠ 枚举值必须等于后端下发的字符串(`'folder'`/`'file'`)——这是关键:**
- 后续数据走 `axios` 拿、**结构不变**,线上 `type` 就是裸字符串 `'folder'`/`'file'`。枚举值取成同样的串,**原始响应能直接当 `CatalogueNode` 用**:所有 `node.type === CatalogueNodeType.folder` 比较、以及 ``` `node-${node.type}` ``` 拼 CSS 类(`node-folder`/`node-file`)都零转换生效。
- 反之若把枚举映射成数字/Symbol,就得在每次请求后加一层「字符串→枚举」的转换,既多机关又和「结构不变」矛盾——不做(YAGNI)。
- 枚举真正的价值:把散落在代码里的魔法串 `'folder'`/`'file'` 收成**一个命名出处**;万一后端改了拼写,改这一处(+ 类型里的字面量联合)即可。

> 命名用 `CatalogueNodeType` 而非 `NodeType`:`nodeType` 是 DOM 既有概念(`Node.ELEMENT_NODE` 那套返回数字),避开重载词,且与 `CatalogueNode` 同源。

#### `RenderPhase`(渲染相位)

文章区「激活 / 非激活」由**选中节点是否为叶子**决定:选中文件(叶子)→ 渲染 Markdown 正文(激活);选中文件夹(非叶)或初始未选中 → 渲染节点简介(非激活)。这个相位被 `CatalogueTree`(目录宽窄)与 `ArticlePane`(正文切换)**共用**,Step 2 还会升格成 `store.phase` 让两栏宽度联动,故同样收敛成枚举:

```js
/**
 * @typedef {Object} RenderPhase 本枚举项用于标识文章区当前渲染的相位(由选中节点是否为叶子决定)
 * @property {string} leaf - 渲染叶子节点(文件):展示 Markdown 正文(激活态)
 * @property {string} nonLeaf - 渲染非叶节点(文件夹)或初始未选中:展示节点简介(非激活态)
 * */
const RenderPhase = Object.freeze({
    leaf: 'leaf',
    nonLeaf: 'nonLeaf',
})
```

- **对齐项目既有的 `HoverPhase`/`FocusPhase`**:三者都是「一个 `phase` ref 跟一组固定状态比较」的同款模式(`stores/focus.js`、`stores/hover.js` 即如此用),故同样用 `*Phase` 命名;取值也用**状态式**名词 `leaf`/`nonLeaf`,不用动词(与 `FocusPhase` 的 `idle`/`focusing`/… 一致)。
- **消魔法串 + 防大小写漂移**:源 `render.js` 的 `state.phase` 是裸串 `'renderLeaf'`/`'renderNonleaf'`(源里是小写 `l` 的 `nonleaf`,落地极易手滑写成 `renderNonLeaf`——本项目已发生)。收成枚举后只剩**一个出处**,比较/赋值都走 `RenderPhase.leaf`/`.nonLeaf`,漂移不再可能。
- **取值不被后端约束(与 `CatalogueNodeType` 相反)**:phase 是**纯前端**状态,不随响应下发,故自由取最干净的 `leaf`/`nonLeaf`(正好对应 file 叶 / folder 非叶),不必沿用源里带动词的 `render*`。

#### 加进文件底部已有的 `export { … }`

```js
export {
    ActionType,
    HoverPhase,
    FocusPhase,
    CatalogueNodeType,   // ← 新增
    RenderPhase,         // ← 新增
}
```

### 2.2 新建 `src/data/treeData.js`(搬数据 + 类型)

把源 `universeBlogContent/src/structure/tree.js` 里的 **`tree` 对象**原样搬过来,改成命名导出;并按本项目既有约定(`stores/hover.js`、`three/planet/*.js` 等都用 `@typedef`)给它配一个 `@typedef` + `@type`:

```js
// src/data/treeData.js  （路径按你项目习惯;Step 2 的 stores/article.js 也会 import 它)

/**
 * @typedef {Object} CatalogueNode 目录树节点(文件夹或文件),children 自引用 → 递归树
 * @property {Number} id 节点唯一 ID
 * @property {'folder' | 'file'} type 节点类型(取值见 `CatalogueNodeType` 枚举;字面量联合即枚举的两个值)
 * @property {String} name 节点显示名称
 * @property {String} createdAt 创建日期(YYYY-MM-DD)
 * @property {String} [intro] 简介,仅文件夹有(文件节点无此字段)
 * @property {CatalogueNode[]} [children] 子节点,仅文件夹有(文件为叶子)
 * */

/**
 * 目录树静态数据(单根)
 * @type {CatalogueNode}
 * */
export const treeData = {
    id: 1,
    type: 'folder',
    name: '根文件夹名称',
    intro: '根文件夹的简介',        // intro / createdAt 给文章区(第 3 份)用
    createdAt: '2025-12-31',
    children: [ /* …源文件里那一整棵,照搬… */ ],
}
```

**为什么值得加 `@typedef`(而非只顶一行注释):**
- **递归**:`children` 是 `CatalogueNode[]`,自引用——只有具名类型能干净表达;
- **多处复用**:`treeData` → `TreeNode` 的 `node` prop → Step 2 的 `stores/article.js` 与 DFS 查找函数都吃这个形状。源里它们全被写成 `@param {Object} node`(丢了真实结构);具名后下游可用 `import('@/data/treeData.js').CatalogueNode` 复用(本项目 `three/interaction/hover.js` 已用 `import('@/stores/hover.js').HoverStore` 这种写法,有先例);
- **合群**:项目已大量用 `@typedef` 命名领域类型(`Pointer`/`Planet`/`OrbitConfig`…),目录节点配一个正好一致。

**两个取舍(已替你定,附理由):**
- **命名用 `CatalogueNode`,不用 `Node`**:`Node` 是 DOM 全局类型,`@type {Node}` 在编辑器里会与它撞、解析有歧义,也违背「避免重载词」。`CatalogueNode` 与 `CatalogueTree` 同源、零歧义。
- **扁平一个类型 + 可选字段,不拆 `FolderNode | FileNode` 联合**:文件节点没有 `intro`/`children`,标 `[intro]`/`[children]` 可选即可。`jsconfig.json` 为 `checkJs:false`(类型只供编辑器提示、不参与构建校验),且消费方运行时都用 `Array.isArray(children)` / `type==='folder'` 兜底,判别联合收益很小、机关更多——YAGNI;日后想要严格判别再拆不迟。

> 写法对齐 `stores/hover.js`:`@typedef {Object} 名 说明` + `@property {T} 名 说明`,基元用首字母大写的 `Number`/`String`,块以 ` * */` 收尾。数据内容直接从源文件复制,无需改结构;验证时也可只留前几个节点先跑通。

> **`treeData` 里仍写字面量 `type: 'folder'`,不引枚举**:这份数据是**后端 axios 响应的临时替身**(线上是裸 JSON 字符串,引用不了 JS 常量),保持字面量才忠实模拟载荷;且它用完即弃。**枚举只用在「消费 `type`」的代码处**(§4 的 TreeNode、Step 2 的 DFS/store)——那些代码切到 axios 后依然保留,才是枚举发力的地方。

## 4. 新建 `src/components/article/TreeNode.vue`(递归节点)

```vue
<template>
    <li
        class="tree-node"
        :class="[`node-${node.type}`, { 'is-collapsed': isCollapsed }]"
        :style="{ '--depth': depth }"
        :data-id="node.id"
    >
        <!-- depth 0:根行(梯形 + 文字,无图标) -->
        <div v-if="depth === 0" class="row primary-row">
            <div class="left-trapezoid"></div>
            <span class="literal">{{ node.name }}</span>
        </div>

        <!-- depth>0 文件夹:箭头 + 文字 -->
        <div v-else-if="node.type === CatalogueNodeType.folder" class="row folder-row">
            <i class="iconfont icon-icon-right"></i>
            <span class="literal">{{ node.name }}</span>
        </div>

        <!-- depth>0 文件:文件图标 + 文字 -->
        <div v-else class="row file-row">
            <i class="iconfont icon-icon_file"></i>
            <span class="literal">{{ node.name }}</span>
        </div>

        <!-- 子节点:递归自身 -->
        <ul v-if="hasChildren" class="children">
            <TreeNode
                v-for="child in node.children"
                :key="child.id"
                :node="child"
                :depth="depth + 1"
            />
        </ul>
    </li>
</template>

<script setup>
import { computed } from 'vue'
import { CatalogueNodeType } from '@/lib/enum.js'

/**
 * @typedef {import('@/data/treeData.js').CatalogueNode} CatalogueNode 目录树节点
 * */

defineOptions({
    name: 'TreeNode',
})

const props = defineProps({
    // PropType 转型:在类型层把 Object 构造器窄化成 CatalogueNode,
    // 这样 props.node.xxx / 模板里的 node.xxx 都有补全;PropType 是纯类型导入,不进运行时。
    node: {
        type: /** @type {import('vue').PropType<CatalogueNode>} */ (Object),
        required: true,
    },
    depth: { type: Number, required: true },
})

/**
 * @type {import('vue').ComputedRef<Boolean>} 本派生量用于标识节点是否有子节点(决定是否递归渲染子级 <ul>)
 * */
const hasChildren = computed(() =>
    Array.isArray(props.node.children) && props.node.children.length > 0
)

/**
 * @type {import('vue').ComputedRef<Boolean>} 本派生量用于标识 folder 节点是否处于折叠态
 * - ⚠ 静态规则:根(depth0)展开、depth≥1 的 folder 折叠(对应源 initCollapsed);Step 2 改读 store.isCollapsed(node.id) 并接点击切换
 * - 临时想看展开后的深层样式:暂时让它 return false 即可
 * */
const isCollapsed = computed(() =>
    props.node.type === CatalogueNodeType.folder && props.depth >= 1
)
</script>

<!-- 本组件刻意不写 <style>:节点样式全部来自 CatalogueTree 的非 scoped tree.css
     (递归组件 + .tree/.tree-node/.node-* 后代选择器无法走 scoped) -->
```

> **递归自引用**:`<script setup>` 里组件可用文件名 `TreeNode` 自引用,`defineOptions({name:'TreeNode'})` 让它显式可靠。

> **`node` prop 的类型提示**:纯 JS 的 `<script setup>` 用不了 `defineProps<{…}>()` 泛型,改用 JSDoc 把 `type: Object` 转型成 `PropType<CatalogueNode>` —— `props.node.xxx`、模板里的 `node.xxx` 就都有补全、`Unresolved variable` 消失。`import('vue').PropType` 与 `import('@/data/treeData.js').CatalogueNode` 都是**纯类型导入**,编译后不进运行时,零开销。顶部 `@typedef … CatalogueNode` 只是给长路径起个本地别名,后面写 `PropType<CatalogueNode>` 更短。
> 若日后把本组件改成 `<script setup lang="ts">`,可换成更直接的 `defineProps<{ node: CatalogueNode; depth: number }>()` —— 那是另一回事,现在不用动。

> **行缩进为何不在 JS 里算**:`--depth` 已写在 `<li>`、`--tree-indent` 已在 `.catalogue-tree`,行缩进直接用 CSS `calc(var(--depth) * var(--tree-indent))`(见 §5 `.tree-node > .row`)即可——`21px` 只在 `--tree-indent` 出现一次,连接线 `--branch-x` 也读它,天然同源。比「JS 定常量」(仍与 CSS 双份)或「`getComputedStyle` 读回 JS」(运行时往返、时序脆弱)都干净,故删掉 `rowPad` 计算 + 三处 `:style="rowPad"`。`--depth` 仍由 `:style` 写在 `<li>`(它是数据,理应来自 JS)。

## 8. 留松 / 接缝(Step 2 再接)

- **折叠/展开点击、`isCollapsed` 动画**:`TreeNode` 现在 `isCollapsed` 是静态规则;Step 2 改读 `store.isCollapsed(id)` + 点击 `toggleFolder`(源 `interaction/toggleFolder.js` 的高度动画)。
- **选中/联动**:`phase` 现在两个组件各自硬编码;Step 2 都读 `store.phase`,目录 ↔ 文章宽度联动(`catalogue-active` ↔ `article-inactive`)。
- **`ensureNodeVisible`**:开启文章后滚动定位,Step 2 在 `CatalogueTree` 用 `nextTick` + `.simplebar-content-wrapper` 实现。
- **SimpleBar recalculate**:静态内容固定,只 `new SimpleBar`;Step 2 内容变更后要 `recalculate()`。
- **节点类型比较走枚举**:Step 2 的 `initCollapsed`、DFS(`dfsFindNodeWithPath`/`dfsFirstLeaf`)、store 里所有 `node.type === 'folder'|'file'` 都换成 `CatalogueNodeType.folder`/`.file`(枚举值即 axios 下发的字符串,无需转换)。
- **按类名查 DOM 认准 `.tree-node`**:源 `toggleFolder.js` 用 `querySelector('.tree li.node[data-id="…"]')` 定位节点,Step 2 迁这段时根类已是 `.tree-node`(`li.node` → `li.tree-node`);更稳的是直接用 `[data-id="…"]`(不带类名,对类名改名免疫)。
