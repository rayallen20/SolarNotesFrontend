# 太阳系尺度修订 — 需求修正方案(√幂律压缩距离 + 太阳锚点化 + 场景内导航)

> **背景:两个"非 bug"的产品设计问题,根都在"按真实比例等比缩放"这条需求上。**
>
> 1. **太阳与天体比例不对**:行星之间是真实比例,但太阳真实半径 ≈ 109× 地球,真实比例的太阳半径 ≈ 142 世界单位 —— 会把水/金/地/火(现都在 15–59)连小行星带一起吞掉。被迫缩小后,现在太阳可见半径只有 ≈2(`scale.size:4`/`hover.radius:2.0`),**比木星(8)、土星(12)还小**,失去了"中心最大天体"的观感。
> 2. **外行星太远不好操作**:轨道 `semiMajorAxis = 真实AU × 38.86`(线性),海王星甩到 **1166**、水星才 **15**,动态范围 **77:1**。必须把镜头拉到看不清才能框住外行星,而外行星体积又小,拉远后更难悬停/点击。
>
> **结论:真实比例在数学上就和"可用"互斥(所有真实产品都在作弊)。本产品是"用太阳系做导航隐喻的笔记应用"(每颗行星挂 `title+intro+聚焦按钮`),真实比例只是美术主题,真正的需求是「认得出 + 够得着 + 点得中」。**
>
> **方案定调:A 的骨架(可用性优先)+ B 的一点点梯度(保留可信感)。** 三件事:
> 1. **距离 √幂律压缩**(核心布局修复,改 `config.js` 的 `semiMajorAxis`):把 77:1 压到 ~9:1,海王星 1166→213。
> 2. **太阳锚点化**(问题①,改 `sun.js` 的 `scale.size`):放大成"明显最大、又不吞水星"的中心锚点,理直气壮地非真实。
> 3. **场景内导航**(交互兜底,复用现有 focus,**不加任何画面 UI**):**最小屏幕尺寸**(远/小行星不缩成看不见的点、随之可点)+ **键盘循环聚焦**(`←/→` 飞抵任意天体、`Esc` 返回)。

## 2. 设计原则:把需求从"真实等比"改成"有序·可识别·可达"

**为什么必须改(用本项目的数字):**

- 轨道:`Neptune 1166` vs `Mercury 15` = **77:1**,内行星挤成一团、外行星在空旷处。
- 太阳:真实比例半径 ≈ `地球可见半径 1.3 × 109 ≈ 142`,而内行星在 15–59 —— **半径 142 的太阳会物理性吞掉四颗内行星**。"既真实又可用"在数学上不成立。

**保留(够"认得出是太阳系"即可):**

- 八颗行星的**顺序**与辨识(贴图、土星环);
- 椭圆轨道(`eccentricity`)、轨道倾角(`dipAngle`);
- **行星之间**的真实尺寸梯度(巨行星明显大于岩石行星);
- "内密外疏"的**趋势**(√幂律保留了这个味道,只是压缩)。

**丢弃:**

- 真实 AU **线性**距离;
- 太阳的真实半径比(明确改为"刻意的中心锚点尺寸")。

## 3. 距离:√幂律压缩(核心布局修复)

### 3.1 公式

以**地球(1 AU)为支点**,对真实 AU 开平方再线性放大:

```
新 semiMajorAxis = 38.86 × √(真实AU)
等价闭式(直接拿现值算): 新值 = √(38.86 × 旧值)
```

地球 √1 = 1 → 仍是 38.86(**地球轨道不变**,改动以它为中心向两侧收拢)。

### 3.2 新值表

| 行星 | 真实AU | 现状(线性) | **新值(√幂律)** | 位移 |
|---|---:|---:|---:|:--|
| 水星 | 0.39 | 15 | **24.14** | 外移(内行星太挤,撑开是好事) |
| 金星 | 0.72 | 28 | **32.99** | 外移 |
| 地球 | 1.00 | 38.86 | **38.86** | 不变(支点) |
| 火星 | 1.52 | 59.21 | **47.97** | 内移 |
| 木星 | 5.20 | 202.227 | **88.65** | 大幅内移 |
| 土星 | 9.54 | 370.611 | **120.02** | 大幅内移 |
| 天王星 | 19.19 | 745.773 | **170.24** | 大幅内移 |
| 海王星 | 30.00 | 1165.91 | **212.85** | 1166→213,压 ~5.5× |

> **这些是轨道"距离/位置",与模型大小无关**:`semiMajorAxis` 只决定 `root` 组离太阳多远,哪怕把所有 GLTF 换成别的尺寸也不用改。只有下面 §3.3 的防撞校验会用到"可见尺寸",而可见尺寸同样**不需要翻原模型**(原因见 §3.3)。

### 3.3 为什么用 √(而不是对数 / 等距)

- **不重叠(已按可见半径核验)**:`scaleModel()` 把模型最大边归一化到 `scale`,所以**可见半径 ≈ `scale/2`,从 config 即可算出,无需翻原模型**(`hover.radius` 当初也照此设)。各天体可见半径:水 0.5 / 金 1.25 / 地 1.3 / 火 0.7 / **木 14.65**(包围盒最大边;实心球约 8.14)/ 土 12.35 / 天 5.25 / 海 5.1。用这组保守半径核对 §3.2 新值,**相邻间隙全为正**,最紧的是木–土:`120.02 − 88.65 − 14.65 − 12.35 = 4.37 > 0` ✓。
  - 反例:纯**对数**会把木星(~78)、土星(~92)压到只差 ~14,而二者可见半径合计 ≈ 27(即便按木星实心球也 ~20)→ **重叠**,除非同时缩小巨行星,故不用。
- **保序、保"内密外疏"趋势**:√ 以地球为支点,<1AU 的撑开、>1AU 的收拢,既解决"内行星挤"又解决"外行星远"。
- **等距(rank spacing)**更易用但更不真实(像地铁图);本方案要"一点 B 梯度",故选 √。若实测仍嫌外圈偏远,可把系数 38.86 调小整体再缩,或对外圈单独再压。

### 3.4 派生影响(改 config 即自动跟随的 / 需手动复核的)

- **自动跟随**:`createOrbitPath()` 与 `initOrbitalGroupPosition()` 都从 `planet.config.orbit` 派生 —— 改了 `semiMajorAxis`,**渲染的轨道环和行星初始位置自动更新**,无需额外改。`eccentricity` 不变 → 椭圆形状不变,只是整体缩小。
- **需手动复核(§10 汇总)**:太阳 `shadow.camera.far`(现 1200,按 Neptune 1166 设的;压缩后 Neptune 213,可收到 ~260,**顺带提升阴影精度**)、`controls` 的 `min/maxDistance`、相机初始位与 `far` 裁剪面、天空球半径。

## 4. 太阳:锚点化(问题①)

### 4.1 现状与目标

- 现状:`scale.size: 4` → 可见半径 = `scale/2` = 2(`scaleModel` 把最大边归一化到 `scale` 所致;与 `hover.radius: 2.0` 一致),**比木星、土星还小** → 看起来不像"中心恒星"。
- 目标:太阳成为**明显最大**的天体(≥ 土星 12),但**不能吞掉压缩后的水星(新轨道 24.14)**。

### 4.2 取值

```
目标可见半径 ≈ 14   (≥ 土星 12.35;距水星新轨道 24.14 仍留 ~9.6 间隙)
scale.size = 2 × 可见半径 = 28   (精确值: scaleModel 归一化, 球体可见半径 = scale/2; 验: 现 scale 4 → 半径 2)
hover.radius 同步到 ≈ 14          (否则 label 投影/粘滞仍按旧的 2 算)
```

- 取值带:可见半径 **[10, 18]** 区间任选(下限 ≥ 木星 8,上限留出水星间隙,硬上限 < ~22)。本方案推荐 **~14**,既"明显最大"又不喧宾夺主 —— 这就是"一点 B 梯度":朝真实(太阳最大)**点一下**,而非照搬 109×。
- **理直气壮地非真实**:这是刻意的锚点尺寸,不是"缩水的真实值",不必再纠结比例。

### 4.3 派生影响

- **聚焦取景距离**:`tickFocus` 让镜头停在天体前方的距离若依据 `hoverRadius`,放大太阳后镜头会自动停得更远(不会扎进太阳);务必同步 `hover.radius`(§4.2)。
- **辉光**:太阳是 emissive + bloom,放大后辉光更强,`postProcess` 的 bloom 阈值/强度可能要回调一点。
- 光源在原点(0,0,0)不随模型尺寸变,**光照本身不受影响**,只是视觉上太阳更大。

## 5. 行星尺寸:保留真实梯度(只动太阳)

行星之间已是真实比例(水星 `scale 1` … 木星 `29.3`),这是"对"的部分,**保留**——它正是我们想要的"一点 B 梯度"。

> 不对行星尺寸做压缩。"远处小行星不好点"的问题,**用 §6 的交互层解决,而不是改尺寸**——否则会破坏好不容易对的行星比例。

## 6. 交互:最小屏幕尺寸 + 键盘循环聚焦(不加任何画面 UI)

> 目标:解决"外行星太远 + 太小 → 难悬停/点击",但**画面上只保留太阳和行星**,不加列表/HUD/dock。两个手段都**只依赖会长期保留的天体本身**(不碰 `OrbitPath` 或任何画面 UI),且都**复用现有 `requestFocus` 流水线**。

### 6.1 先厘清一个事实(它决定了 ② 为什么有效)

**拾取(hover 进入 + 点击聚焦)都是对模型网格 raycast 的**:`pickHoveredBody()` 打的是 `pickableMeshes`(`hover.js:95`、`focus.js:92` 都用它)。而 `hoverRadius` 只在 `calcProjection()`(`projection.js:159`)里用于 label 投影与粘滞判定。

由此推论(② 正好用上,但藏着一个**黑屏雷**):

- 放大 `hover.radius` **不会**放大命中目标;但**放大网格本身会** —— 所以 ② 把整颗行星(`root.scale`)放大时,其下可拾取网格一并变大,**命中目标自动变大**,无需额外的命中代理球。
- **label 投影与聚焦取景的半径都由 `getWorldRadius()` 算 = `radiusLocal × 物体世界缩放(getWorldScale)`**(`calcProjection`→`projection.js:90`、`focus.js:121`)。其中 `radiusLocal` 取自 `userData.hoverRadius`、**首次读取后即被缓存(`__hoverLocalSphere`)不再刷新**,且 `hoverRadius` 非正数时 `radiusLocal` 置 **0**。于是:
  - ② 缩放 `root` 后,投影/取景半径**会自动乘上这个缩放**(`getWorldScale` 每帧实时读)—— **不需要、也不应该手动改 `userData.hoverRadius`**。
  - 手动改 `hoverRadius` 既无效(`radiusLocal` 已缓存)又危险:一旦写进 `NaN`(如 `baseHoverRadius` 未定义),首次缓存把 `radiusLocal` 冻结成 0 → 聚焦距离塌成 ~0 → **相机扎进天体中心 → 黑屏**(详见 §6.2 末)。

### 6.2 方案②:最小屏幕尺寸(只托底)

让每颗行星**在屏幕上不小于 N 像素**:够大就不动(保留真实梯度),太小才整体放大到刚好 N 像素(**只托底,不缩小**)。拉远看全景时远行星不再缩成看不见的点,hover/点击都好操作;靠近/聚焦时 boost 自然回到 1,显示真实尺寸。

**a. `createPlanet()`(`planet.js`)存一个基准值** —— 在 return 的对象里加(**只要 `baseVisibleRadius`;不要 `baseHoverRadius`** —— 原因见 §6.1:不应手动改 `hoverRadius`):

```js
    return {
        config,
        axis,
        root,
        spin,
        model: null,
        orbitRad: 0,
        pickableMeshes: [],
        // 新增:最小屏幕尺寸托底用的基准(行星真实可见半径)
        baseVisibleRadius: config.scale / 2,   // 可见半径 = scale/2(scaleModel 归一化所致)
    }
```

并**同步给 `@typedef {Object} Planet` 补一条 `@property`**(否则 `minScreenSize.js` 里以 `Planet` 类型访问 `planet.baseVisibleRadius` 会是"未声明字段"):

```js
 * @property {Number} baseVisibleRadius 行星真实可见半径(= config.scale / 2),供最小屏幕尺寸托底使用
```

**b. 新增 `src/three/planet/helper/minScreenSize.js`:**

```js
import * as THREE from 'three'

/** @type {Number} 行星屏幕最小半径(像素),小于它就托底放大;口味参数 */
const MIN_SCREEN_RADIUS_PX = 11

/** @type {Number} 托底放大上限,防止极度拉远时内行星被放得过大而互相重叠 */
const MAX_BOOST = 4

/** @type {import('three').Vector3} 复用的世界坐标向量,避免每帧 new */
const worldPosition = new THREE.Vector3()

/**
 * 逐帧维护"最小屏幕尺寸"托底缩放(只托底:够大不动,过小才放大)
 * Tips: 缩放施加在 planet.root 上 —— root 是行星位置层,缩放它 = 以行星中心为锚等比放大整颗行星,
 *       且连带放大其下的可拾取网格 ⟹ hover/点击的命中目标也变大(见 §6.1),无需命中代理球
 * Tips: 只改 root.scale、不碰 userData.hoverRadius —— label 投影与聚焦取景的 getWorldRadius() 已经
 *       × getWorldScale,会自动反映本缩放;手动改 hoverRadius 既无效(radiusLocal 已缓存)又会黑屏(见 §6.1)
 * Tips: 被聚焦的行星强制 boost=1 —— 聚焦近景本就该真实大小,且取景的 getWorldRadius 会反映 root.scale,
 *       放大会导致取景偏大(见本节末"与聚焦的配合")
 * @param {Array<import('@/three/planet/planet.js').Planet>} planets 行星实例列表
 * @param {import('three').PerspectiveCamera} camera 相机
 * @param {Number} viewportHeightPx 视口高度(CSS 像素)
 * @param {import('three').Object3D|null} focusedEntity 当前被聚焦的锚点(focusStore.focusedEntity)
 * */
export function tickMinScreenSize(planets, camera, viewportHeightPx, focusedEntity) {
    // 透视投影:世界半径 r、距相机 d 的物体,屏幕像素半径 ≈ (r / d) * pxPerWorldUnitAtUnitDist
    const fovRad = THREE.MathUtils.degToRad(camera.fov)
    const pxPerWorldUnitAtUnitDist = viewportHeightPx / (2 * Math.tan(fovRad / 2))

    for (const planet of planets) {
        // 被聚焦的行星保持真实尺寸(boost=1)
        if (planet.root === focusedEntity) {
            planet.root.scale.setScalar(1)
            continue
        }

        // 行星中心世界坐标 → 与相机的距离
        planet.root.getWorldPosition(worldPosition)
        const distance = worldPosition.distanceTo(camera.position)

        // 真实尺寸下的屏幕半径(像素)
        const trueScreenRadiusPx = planet.baseVisibleRadius / distance * pxPerWorldUnitAtUnitDist

        // 只托底:≥ N 则 boost=1;< N 则放大到刚好 N,并夹在 MAX_BOOST 内
        let boost = 1
        if (trueScreenRadiusPx < MIN_SCREEN_RADIUS_PX) {
            boost = Math.min(MIN_SCREEN_RADIUS_PX / trueScreenRadiusPx, MAX_BOOST)
        }

        // 整颗行星等比放大;投影/取景半径经 getWorldScale 自动随之放大(见 §6.1),不要手动改 hoverRadius
        planet.root.scale.setScalar(boost)
    }
}
```

**c. `engine.js` 每帧调用 —— 放在 `tickFocus()` 之前**(关键:聚焦取景用 `getWorldRadius`,要先把被聚焦行星复位为真实尺寸,再让 `tickFocus` 算取景):

```js
import { tickMinScreenSize } from '@/three/planet/helper/minScreenSize.js'
// planets / camera 在 engine.js 里已 import / 持有

function startAnimation() {
    // …前略(天空球、太阳自转)…

    // 维护行星最小屏幕尺寸(远/小行星不消失、命中目标随之放大);
    // 必须在 tickFocus 之前:被聚焦行星在此复位为 boost=1,聚焦取景才不偏大
    tickMinScreenSize(planets, camera, renderer.domElement.clientHeight, focusStore.focusedEntity)

    // 维护聚焦状态机(原有)
    tickFocus(now, focusStore, camera, controls)

    // …后略(tickHover / updatePlanets / controls.update / renderBloomFrame)…
}
```

> **与聚焦的配合(为什么这样排)**:聚焦取景距离 = `getWorldRadius(target) / tan(fov/2) × ZOOM_FACTOR`(`focus.js:121-124`),而 `getWorldRadius = radiusLocal × getWorldScale`(`projection.js:122`)—— **确实会反映 `root.scale`**。若被聚焦的远行星仍带托底放大,取景就按放大尺寸算 → 镜头停得过远、近景偏小。所以:① `tickMinScreenSize` 里**跳过被聚焦行星并复位 scale=1**;② 在 `engine.js` 把它排在 `tickFocus` **之前**,确保 `initFocusAnimation` 读到的世界缩放是 1。(代价:用上一帧位置算距离,单帧误差对"屏幕像素半径"影响可忽略。)
>
> ⚠️ **不要手动改 `userData.hoverRadius`(否则黑屏)**:`getWorldRadius` 里的 `radiusLocal` 取自 `userData.hoverRadius`,但**首读后被缓存(`__hoverLocalSphere`)不再刷新**,且 `hoverRadius` 非正数时 `radiusLocal` 被置 **0**。早期版本让 `tickMinScreenSize` 写 `hoverRadius = baseHoverRadius × boost`:一旦 `baseHoverRadius` 为 `undefined` → 写入 `NaN` → 首次缓存把 `radiusLocal` 冻结成 0 → 聚焦距离 ≈ 0 → **相机扎进天体中心 → 黑屏**。正解是**只缩放 `root.scale`、完全不碰 `hoverRadius`**:投影/取景半径经 `getWorldScale` 已自动随 boost 走。**改完需硬刷新**(缓存的 `radiusLocal=0` 存在 userData 里,不刷新不清)。

> **性质(为什么不突兀)**:apparent 尺寸随相机接近**单调不减**(远处恒为 N、靠近后才按真实透视增大),不会"先大后小"地抖;聚焦飞入时行星从 N 平滑长到真实近景尺寸。`MAX_BOOST` 是保险,防极度拉远时内行星互相重叠。太阳不参与托底(在中心、半径已 ~14,任何视角都够大)。

> **实测取值 `MIN_SCREEN_RADIUS_PX = 11` / `MAX_BOOST = 4`(由 14 / 5 下调)**:初值 14/5 把内行星托得过大 —— 金、地放大后世界半径都到 ~4.6,而二者轨道间距仅 5.87(地−金最挤),半径和 9.23 > 间距 → **视觉上相互覆盖**。直接放大内行星长半轴治标但会撞天花板(火星外移会扎进木星 ~14.65 的大盘),故改为**从根上调小托底目标**:11px 仍可见可点,放大后半径降到 ~3.6、半径和 ~7.3 < 间距,内行星分开;实测无异常。

### 6.3 方案④:键盘循环聚焦(零 DOM)

`←/→`(或 `Esc`)在 太阳→八行星 间循环聚焦/返回,**不渲染任何 DOM**,纯键盘驱动,复用 focus。

**新增 `src/composables/useKeyboardFocusNav.js`:**

```js
import { onMounted, onBeforeUnmount } from 'vue'
import { planets } from '@/three/planet/index.js'
import { sunAxis } from '@/three/sun.js'
import { useFocusStore } from '@/stores/focus.js'

// 循环顺序:太阳 + 八行星;行星 anchor 取 root(与 resolveAnchor / focusedEntity 一致)
// 放模块级安全:planets/sunAxis 在本模块求值前已初始化,且各 p.root 引用稳定
const orderedAnchors = [sunAxis, ...planets.map(p => p.root)]

/**
 * 按偏移量循环聚焦
 * @param {Number} offset +1 下一个 / -1 上一个
 * */
function focusByOffset(offset) {
    // 惰性取 store:本函数只在按键时(挂载后)执行,Pinia 已激活;
    // 切勿把 useFocusStore() 提到模块顶层 —— import 期 Pinia 可能尚未创建,会抛 "no active Pinia"
    const focusStore = useFocusStore()
    const count = orderedAnchors.length
    // 与鼠标聚焦同步:用当前被聚焦的 anchor 反查序号(未聚焦为 -1)
    const currentIndex = orderedAnchors.indexOf(focusStore.focusedEntity)
    // 未聚焦时:正向从太阳(0)起、反向从末位起;否则环形步进
    let nextIndex
    if (currentIndex === -1) {
        if (offset > 0) {
            nextIndex = 0
        } else {
            nextIndex = count - 1
        }
    } else {
        // + count 保证 offset 为负时取模仍落在 [0, count)
        nextIndex = (currentIndex + offset + count) % count
    }

    focusStore.requestFocus(orderedAnchors[nextIndex])
}

/**
 * @param {KeyboardEvent} event
 * */
function onKeydown(event) {
    switch (event.key) {
        case 'ArrowRight':
            focusByOffset(1)
            event.preventDefault()
            break
        case 'ArrowLeft':
            focusByOffset(-1)
            event.preventDefault()
            break
        case 'Escape':
            useFocusStore().requestClear()
            break
    }
}

/**
 * 键盘循环聚焦:←/→ 在 太阳→八行星 间循环聚焦,Esc 退回总览
 * 不渲染任何 DOM,纯键盘驱动,复用 focus 流水线
 * Tips: 本 composable 只做生命周期接线;逻辑在模块级的 focusByOffset/onKeydown 上
 * Tips: onMounted/onBeforeUnmount 必须留在这里 —— 它们要登记到当前组件实例,只能在 setup 期调用
 * */
export function useKeyboardFocusNav() {
    onMounted(() => window.addEventListener('keydown', onKeydown))
    onBeforeUnmount(() => window.removeEventListener('keydown', onKeydown))
}
```

**挂载**(`SolarCanvas.vue` 的 `<script setup>`,**无模板改动、无 DOM**):

```js
import { useKeyboardFocusNav } from '@/composables/useKeyboardFocusNav.js'
useKeyboardFocusNav()
```

为什么正确:`focusStore` 是 Pinia 单例,与引擎同一实例;`requestFocus(anchor)` 改状态 → 引擎 `tickFocus` 接管飞行;从已聚焦切到另一颗时 `shouldCaptureHome` 为 false,**`Esc` 始终回到最初的总览位**;`requestFocus` 对同一 anchor 幂等。

> - **可发现性**:键盘操作没有可见入口 —— 用一个"看过即可关闭"的提示层解决(两档关闭 + `localStorage` 记住"永久关"),见 **§6.4**。
> - **Tab 取舍**:上面只用 `←/→`(最稳)。若也想 `Tab` 循环,注意它会**接管页面默认的 Tab 焦点切换**;本项目全屏 canvas、可聚焦元素少一般无碍,但若 panel 按钮要键盘可达就别接管 `Tab`,只留方向键。
> - **模块级 vs 组件内**:这里把 `focusByOffset`/`onKeydown` 提到了模块级,`useKeyboardFocusNav()` 只剩生命周期接线 —— 所以 `useFocusStore()` 必须**惰性取**(别提到模块顶层,import 期 Pinia 未必就绪)。代价:`onKeydown` 是模块级单一引用,**单实例没问题**(add/remove 配对干净);但若将来有两个组件实例同时用,浏览器按"同引用同选项"去重,先 unmount 的会把监听整个摘掉 → 另一个失效。需多实例就把这俩函数挪回 composable 内部(各自闭包、各自监听)。

### 6.4 键盘提示层(可发现性 · localStorage 开关)

§6.3 的键盘操作没有可见入口,加一个**一次性引导提示**:默认在底部居中显示「← → 聚焦/切换天体 · Esc 取消聚焦」。**两档关闭**:

- **关闭图标(× 字体图标 `icon-a-closeicon-close`)** —— 只关**本次会话**,不写 `localStorage`,下次访问仍会显示("这次不想看")。
- **"不再提示"** —— 写 `localStorage`,**下次访问不再出现**("以后别来了")。

它是会被关掉的引导层,不属于常驻 UI,不破坏"只有太阳和行星"的画面。

### 6.5 为什么不用"列表"或"点轨道"(决策记录)

- **不用 DOM 列表/dock**:会在画面上叠 UI,破坏"只有太阳和行星"的简洁感。
- **不用"点轨道环聚焦"**:那会把导航这个**核心交互**耦合到 `OrbitPath` 上,而轨道**未来可能删除**(画面只留太阳+行星)。②+④ 只依赖**会长期保留的天体本身**,轨道删了也一行不改 —— 依赖方向更稳。

## 10. 风险与未尽事项(尺度联动复核清单)

压缩了整体尺度(外圈 ~5.5× 收拢)+ 放大了太阳,以下"按旧尺度调好的"参数都需复核重调:

| 位置 | 现值 / 现状 | 复核方向 |
|---|---|---|
| `sun.js` `light.principal.shadow.camera.far` | `1200`(按 Neptune 1166 设) | 收到 ~260(Neptune 新 213 + 余量);**顺带提升阴影分辨率** |
| `controls` `minDistance` / `maxDistance` | 假设外圈 ~1166 | `maxDistance` 大幅调小(能看全 213 即可);`minDistance` 配合放大后的太阳 |
| `camera` 初始位置 / `far` 裁剪面 | 按旧尺度 | 初始机位拉近;`far` 可调小(更好的深度精度) |
| 天空球半径 | 需包住整个场景 | 只要仍 > 外圈即可,通常无需改,确认一下 |
| bloom 阈值/强度 | 按旧太阳大小 | 太阳放大后辉光更强,回调避免过曝 |
| 聚焦取景距离 | `getWorldRadius` = `radiusLocal`(取自 `userData.hoverRadius`,**首读后缓存**)× `getWorldScale` | **太阳:`hover.radius` 必须随 `scale.size` 一起放大(§4.2),否则取景按旧小半径算 → 相机扎进放大后的太阳 → 黑屏**;行星:② 的 `root.scale` 经 `getWorldScale` 自动计入,故被聚焦行星复位 scale=1、且**不手动改 `hoverRadius`**(§6.2) |

- **系数可调**:若实测外圈(海 213)仍偏远,把 §3.1 的 38.86 整体调小即可同比再缩(地球也会随之内移,属可接受)。
- **小行星带**(若有,木星 hover 注释提到"含行星带 14.65"):其半径若也按真实 AU 线性放置,需一并按 √幂律重算。
- **最小屏幕尺寸的 `MIN_SCREEN_RADIUS_PX` / `MAX_BOOST`**:口味/保险参数,**当前实测定为 11 / 4**(由 14 / 5 下调以消除内行星视觉覆盖,见 §6.2)。若内行星仍嫌挤,继续调小 `MIN_SCREEN_RADIUS_PX`/`MAX_BOOST`,或改成"按最近邻轨道间距的一半封顶"。
- **键盘导航可发现性**:`←/→`·`Esc` 没有可见入口,可加一个"看过即消失"的一次性浅提示(属可选润色,见 §6.3)。
