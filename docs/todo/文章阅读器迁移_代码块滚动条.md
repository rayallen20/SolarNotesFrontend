# 文章阅读器迁移 · 正文横向滚动条(代码块 + 表格)

> **背景**:文章区收窄(专注目录态 ~30% 宽)时,md 正文里**会横向溢出的元素**弹出横向滚动条。代码块那条灰条的**真凶是 highlight.js 主题给 `code.hljs` 自带的 `overflow-x:auto`**(不是 `<pre>`、也不是 SimpleBar):`code` 这层自己把横向溢出吃掉、在自己身上滚出**原生灰条**,且溢出传不到挂在 `<pre>` 上的 SimpleBar(那条对横向是空转的)。表格 `<table>` 则在窄区塞不下、要横滚。
>
> **为什么不是纯 CSS(方案 A)**:`::-webkit-scrollbar` 在 macOS Chrome 正常,但 **Windows 11 Chrome 的 Fluent 滚动条**在 hover / 拖拽时无视作者交互态样式、回退默认灰,且 Fluent 是访客侧默认 + flag 级开关,作者 CSS 无法规避。实测纯 webkit 块仍变灰 → A 到顶。详见记忆 `project_scrollbar_simplebar`。
>
> **方案 B(本文)**:会横向溢出的元素各挂一个 SimpleBar,复用项目既有全局滚动条皮肤(蓝 / 青主题色),跨 OS 一致。
>
> **两个收口决策**:
> - **表格**:`<table>` 不能直接挂 SimpleBar(它重排子节点会破坏 `thead/tbody`),先用 `<div class="table-scroll">` 包一层、挂在 `div` 上。
> - **专注态横条照显(themed)**:专注目录态文章区收窄,代码块 / 表格该出横条就出——阅读态(70%)既然有这条横条,收窄后凭空消失反而割裂。统一走 SimpleBar 的主题色横条、两态一致。(早先"专注态藏横条"方案已弃,理由见 §3。)
>
> **触及**:`src/assets/markdown.css`、`src/assets/scroll/horizontalScroll.css`、`src/components/article/ArticlePane.vue`、`src/lib/treeQuery.js`(临时测试桩)。依赖 SimpleBar `^6.3.3`(`unMount()` 可用)。

## 1. `markdown.css`:撤回 A + 表格基础样式

### 1.1 撤回方案 A

把上一轮 A 试验加的两块**全删**(Firefox 的 `@supports` 块 + `::-webkit-scrollbar` 块),`.markdown-body pre` 回到最初:

```css
.markdown-body pre {
    margin: 20px 0;
    padding: 16px;
    border-radius: 8px;
    background: rgba(7, 32, 51, 0.95);
}
```

- **`<pre>` 上不要写 `overflow`**:横向滚动交给 SimpleBar;`<pre>` 自己带 `overflow:auto` 会多冒一条原生横条。(真正现在还在冒灰条的是 `code.hljs` 那层——见 §1.3。)
- **不需要为滚动条写任何 CSS**:皮肤白送——见下。

> **皮肤白送**:全局选择器(`scroll/common.css` / `horizontalScroll.css`)是 `.article-pane .article-body .simplebar-track.simplebar-horizontal …`,按后代匹配。代码块 `<pre>` 与表格的 `.table-scroll` 都在 `.article-pane .article-body` 之内,给它们挂的 SimpleBar 生成的 track 天然命中 → 直接拿到正文那条一致的 12px / 渐变 / 圆角 / hover 提亮。**零新增滚动条 CSS。**

### 1.2 表格基础样式(原先没有)

`markdown.css` 里没有任何 `table` 样式,裸表既难看也不便测。补一组最简、贴主题色的(加在 `pre code` 规则之后即可)。其中 **`white-space: nowrap` 是让表格"窄区不缩、改出横滚"的关键**——单元格不换行,表格才保持自然宽度溢出、交给 SimpleBar 横滚;不加则单元格换行、表格缩到容器宽,既不溢出也就不滚:

```css
.markdown-body table {
    margin: 20px 0;
    border-collapse: collapse;
    /* 不设 width:100%,让表格按内容自然宽,超出由 .table-scroll 接管横滚 */
}

.markdown-body th,
.markdown-body td {
    padding: 8px 14px;
    border: 1px solid rgba(33, 170, 255, 0.35);
    text-align: left;
    white-space: nowrap;
}

.markdown-body th {
    background: rgba(33, 170, 255, 0.15);
    font-weight: 700;
}

/* 表格滚动容器(由 ArticlePane 在挂 SimpleBar 前包出来) */
.markdown-body .table-scroll {
    margin: 20px 0;
}

.markdown-body .table-scroll table {
    /* 容器已负责外边距,内层表去掉自身外边距 */
    margin: 0;
}
```

### 1.3 摁掉 `code.hljs` 自带的横向滚动(灰条真凶)

代码块结构是 `<pre><code class="hljs language-xx">`。highlight.js 主题 `atom-one-dark.css` 开头就给 `code` 套了一层自己的横向滚动容器:

```css
pre code.hljs {
    display: block;
    overflow-x: auto;   /* ← 这条就是那根原生灰条 */
    padding: 1em
}
```

后果一串:

- 长代码行先被 `code` 这层 `overflow-x:auto` 吃掉、在它自己身上横滚 → **原生灰条**。
- 溢出被 `code` 内部消化、传不出来 → 挂在 `<pre>` 上的 SimpleBar 量出"没有横向溢出"、自定义横轨**不渲染** → `<pre>` 的 SimpleBar 对横向是**空转**的。
- 阅读态(70%)示例代码太短没溢出 → `code` 不出条 → 之前"没东西可测"也是同一个根因。

**修法:把 `code` 这层的 `overflow-x` 摁成 `visible`**,让溢出继续往外冒、交给 `<pre>` 的 SimpleBar 接管。加到 `markdown.css`(放在 `.markdown-body pre code` 规则附近):

```css
/* highlight.js 主题给 code.hljs 自带 overflow-x:auto,会自己滚出一条原生灰条,
 * 且把横向溢出截在 code 内、传不到 <pre> 的 SimpleBar。
 * 摁成 visible,让溢出冒到 <pre>、由 SimpleBar 接管横滚。 */
.markdown-body pre code.hljs {
    overflow-x: visible;
}
```

- **选择器必须带 `.hljs`**(`pre code.hljs`,特异性 0,0,2,2)才压得过主题。`ArticleReader.vue` 里 `markdown.css`(第 20 行)在主题(第 21 行)**之前**导入,同特异性时后导入的主题赢——只写 `.markdown-body pre code`(0,0,1,2)平特异性、压不过主题的 `pre code.hljs`(0,0,1,2)。(同理你现有的 `.markdown-body pre code { padding:0 }` 其实早被主题 `padding:1em` 盖掉、没生效;不是本 bug 重点,先放着。)
- 修完:阅读态溢出 → `<pre>` 的 SimpleBar 出**主题色横条**;`code` 不再自己滚、原生灰条消失。

## 2. `ArticlePane.vue`:逐元素的 SimpleBar 生命周期

### 2.1 import 补 `onBeforeUnmount`

```js
import {computed, nextTick, onBeforeUnmount, onMounted, useTemplateRef, watch} from "vue";
```

### 2.2 实例容器 + 挂 / 卸两个函数

放在现有 `let scrollbar = null` 之后(先定义,2.3 再调用):

```js
/**
 * @type {SimpleBar[]} 正文内会横向溢出的元素(代码块 / 表格)各自的SimpleBar实例
 * */
let overflowScrollbars = []

/**
 * 本函数用于给正文内会横向溢出的元素挂载SimpleBar,使其横向滚动条复用全局自定义样式:
 *      - 代码块<pre>: 直接挂
 *      - 表格<table>: 先包一层<div class="table-scroll">再挂(SimpleBar会重排子节点,直接挂在<table>上会破坏thead/tbody结构)
 * */
function mountOverflowScrollbars() {
    const preElements = bodyRef.value.querySelectorAll('.markdown-body pre')
    preElements.forEach(preElement => {
        overflowScrollbars.push(new SimpleBar(preElement))
    })

    const tableElements = bodyRef.value.querySelectorAll('.markdown-body table')
    tableElements.forEach(tableElement => {
        const wrapper = document.createElement('div')
        wrapper.className = 'table-scroll'
        tableElement.parentNode.insertBefore(wrapper, tableElement)
        wrapper.appendChild(tableElement)
        overflowScrollbars.push(new SimpleBar(wrapper))
    })
}

/**
 * 本函数用于卸载所有横向溢出元素的SimpleBar实例,清理其事件监听与observer,防止切换文章时泄漏
 * */
function unmountOverflowScrollbars() {
    overflowScrollbars.forEach(instance => instance.unMount())
    overflowScrollbars = []
}
```

> 正文经 `v-html` 注入、对 Vue 不透明,在其内部包 `.table-scroll`、增删 SimpleBar 都不会和 Vue 的 diff 打架;切文章时 Vue 整段重写 innerHTML,这些 wrapper 随之被清掉,只需在重写前把 SimpleBar 实例 `unMount()` 干净即可(见 2.3)。

### 2.3 onMounted / watch / onBeforeUnmount

`onMounted`:body 级 SimpleBar 之后,补挂首屏的溢出元素(默认初态是非叶节点、通常此处为空,保留以防初态即叶子):

```js
onMounted(() => {
    // 为.article-body挂载SimpleBar
    scrollbar = new SimpleBar(bodyRef.value)
    // 为首屏已存在的代码块 / 表格挂载SimpleBar
    mountOverflowScrollbars()
})
```

既有 `watch(activeNode)` 改造成"切文章前卸旧、切完挂新"。关键是 **Vue `watch` 默认 `flush: 'pre'`**:回调里 `await nextTick()` 之前的代码跑在 DOM patch **之前**,此刻旧文章的元素还在 DOM 里,能干净卸载;`await` 之后 DOM 已是新文章,再挂新实例:

```js
// Tips: 从store中读到的Proxy对象会自动解包,因此在组件中拿到的就是一个普通对象,无法被watch
// Tips: 因此要使用getter()函数的形式,才能被watch()函数监听
watch(() => articleStore.activeNode, async () => {
    // Tips: watch默认flush:'pre',await之前跑在DOM更新之前,此刻旧元素仍在DOM中,可干净卸载
    unmountOverflowScrollbars()

    await nextTick()

    if (scrollbar !== null) {
        scrollbar.recalculate()
    }

    // DOM已更新为新文章,为新代码块 / 表格挂载SimpleBar
    mountOverflowScrollbars()
})
```

组件卸载时兜底清理:

```js
onBeforeUnmount(() => {
    unmountOverflowScrollbars()
})
```

> 切换文章 N 次后,`overflowScrollbars.length` 应始终等于"当前文章的代码块数 + 表格数",不堆积——这是没泄漏的判据。

## 3. 删掉"专注态藏横条"规则(改为两态都显 themed 横条)

> **决策变更(选 X)**:早先在 `horizontalScroll.css` 加了一条"专注态隐藏所有横向 track"。现按**一致性优先撤掉它**——阅读态既然有横条,收窄后凭空消失反而割裂(即便专注态不可操作,消失也奇怪)。`.hljs` 一修(§1.3),代码块 / 表格在两态都走 SimpleBar 的主题色横条,统一。

把上一版加进 `src/assets/scroll/horizontalScroll.css` 的这条**整段删掉**(选择器 + `display:none` + 注释):

```css
/* ↓↓↓ 删掉这一整条 ↓↓↓ */
.article-pane.has-mask .article-body .simplebar-track.simplebar-horizontal {
    display: none;
}
```

- 删完 `horizontalScroll.css` 只剩 track 高度、滑块高度、滑块渐变那三条全局皮肤(`.catalogue-tree …` / `.article-pane .article-body …`),专注态不再特殊处理。
- 灰条由 §1.3 的 `.hljs` override 根治,**不再靠隐藏遮**;表格横条本就是主题色 → 删规则后专注态照常显示主题色横条。

## 5. 落地验证

- [ ] **阅读态(70%)**:宽代码块、宽表格各自**本地横滚**,横条是主题色;整篇文章**不**跟着横移(即不是 body 级横滚)。
- [ ] **专注目录态(30%,蒙版)**——**本次核心验收点**:读到表格 / 代码块处点「专注目录」收窄后,代码块 / 表格的横条**仍在、且是主题色**(不是灰条);纵向滚动条仍在。
- [ ] **两态一致**:同一个代码块 / 表格的横条,70% 与 30% 下都在、都是主题色,不忽闪、不变灰。
- [ ] **无双滚动条**:`<pre>` / 表格不再同时出现原生条 + SimpleBar 条。
- [ ] **无灰条**:任何状态都看不到原生灰色横条——尤其专注态代码块(之前 `.hljs` 漏网的那条)。
- [ ] **多次切文章**:`overflowScrollbars.length` = 当前文章(代码块数 + 表格数),不堆积;切到非叶节点无报错(`querySelectorAll` 命中 0 个,挂载为空)。
- [ ] **嵌套无冲突**:body 纵向滚 + 元素横向滚,不同轴,滚轮 / 拖拽不互抢、无 recalc 抖动。
- [ ] **无回归**:reduced-motion、三态切换、面包屑、日期一切照旧。

### 5.1(可选)代码块横条贴底微调

`<pre>` 的 `padding: 16px` 会让横条浮在距底边 16px 处(SimpleBar 的 track 以 `<pre>` 内边距盒底缘定位)。若想让横条贴住代码块底边,把内边距从 `<pre>` 移到 SimpleBar 内容层:

```css
.markdown-body pre {
    margin: 20px 0;
    border-radius: 8px;
    background: rgba(7, 32, 51, 0.95);
    /* padding: 16px 去掉 */
}

.markdown-body pre .simplebar-content {
    padding: 16px;
}
```

表格那侧 `.table-scroll` 无内边距,横条天然贴底,不用处理。先按默认看一眼,不顺眼再启用本节。
