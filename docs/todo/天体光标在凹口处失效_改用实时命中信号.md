# 天体光标在凹口处失效 — 修复方案(射线提顶复用 + 光标信号与 phase 解耦)

> 现象(实测):鼠标悬停在天体**非凹口部分**时光标为 `cursor-pointer.png`、点击可聚焦;但悬停在**天体∩凹口重合部分**时,光标回落 `cursor-default.png`,而点击**仍可聚焦**。
>
> **根因:`shouldUseClickableCursor` 取的信号错了。** 它现在等于 `phase === HoverPhase.body`,而 `phase` 会被"邻近 label 锁定"故意改写——鼠标进入凹口(= 进入 label 矩形的 `enterDistancePx` 范围)时,`isNearLabel → isActiveLocked → handleBody` 把 `phase` 切成 `label`,于是 `shouldUseClickableCursor` 变 false,光标回落默认。而点击走的是另一条**独立**链路(`onPointerUp` 自己 `resolveFocusAnchor`,不看 `phase`),凹口又是穿透的,所以点击照常聚焦。两个信号在凹口处分了岔。
>
> **修复:把光标信号从 `phase` 解耦成"实时是否命中可聚焦天体"。** 在 `tickHover` 顶部每帧投射一次射线得到 `hitObject`,据此维护一个新的响应式标量 `isPointerOverBody`(谓词与点击一致:`resolveAnchor(hitObject) !== null`),并让 `shouldUseClickableCursor` 改取它。`hitObject` 同时**透传给各 handler 复用**,一帧只投一次射线。**状态机的锁定/防抖逻辑完全不动**,所以"鼠标在 label 上不触发状态机变化"原样成立。

## 2. 根因链路(为什么凹口处光标是默认、点击却能聚焦)

鼠标移到"天体∩凹口"时,它已进入 label 矩形的 `enterDistancePx`(8px)范围:

1. `tickHover` 维护 `isNearLabel`:`isNearRect(...)` → `setNearLabel(true)`
2. `isActiveLocked = isLabelHover || isNearLabel` → **true**
3. `handleBody` 优先级1:`if (store.isActiveLocked) { store.enterLabel(); return }` → **`phase` 变 `label`**
4. `shouldUseClickableCursor = (phase === body)` → **false** → canvas 去掉 `is-clickable` → 光标回落默认

点击仍聚焦,是因为 `onPointerUp` 自己调 `resolveFocusAnchor(ndc, camera)` 重新投射(**不看 phase**),凹口穿透(label `pointer-events:none` + `.shape` 把凹口 clip 掉),canvas 收得到 pointerup → `requestFocus`。

**结论:光标用 `phase`、点击用实时射线命中,两者在凹口处不一致。把光标也改成实时射线命中即可对齐。**

### 3.1 `src/stores/hover.js`

**(a) 新增响应式标量**(放在 PART3 鼠标相关信息附近,`hover.js:76-89` 之后):

```js
 * @type {import('vue').Ref<Boolean>} 本标量用于标识鼠标当前是否压在某个可聚焦天体上
```

**(b) 重定义光标派生量**(`hover.js` getters 区,把原先 `phase === HoverPhase.body` 的实现替换掉):

```js
/**
```

**(b) `PhaseHandler` typedef 补形参**(`hover.js:6-9`):

**(c) `tickHover` 提顶投射**:在原 step3(`isNearLabel` 维护)之后、分发之前,插入"投射一次 + 维护信号";分发时把 `hitObject` 透传。step1/step2/step3 内容**保持不变**,仅原 step4(分发)顺延为 step5:

```js

    // step2. 刷新当前激活天体的屏幕投影 (保持不变)
    // step3. 维护isNearLabel的滞后判定(严进宽出) (保持不变)

    // step4. 每帧投射一次射线,得到命中的叶子节点Mesh
    // Tips: 投射提到此处只做一次,既用于维护下面的光标信号,也透传给各handler复用,避免一帧内重复投射

    // 维护"鼠标是否压在可聚焦天体上"的信号(供光标派生量shouldUseClickableCursor使用)
```

### 3.3 四个 handler — 签名加 `hitObject`、删掉各自的 `pickHoveredBody`

各 handler 的**判定逻辑、注释、优先级顺序全部保持不变**,只把"自己投射"换成"用透传进来的 `hitObject`"。

**`handleIdle`**:

```js
function handleIdle(nowMs, store, camera, _domElement, hitObject) {
    if (hitObject !== null) {
        store.enterBody(hitObject)
    }
}
```

**`handleBody`**(优先级1 锁定判定不变;优先级2 改用 `hitObject`;`const pointer` 下移到优先级3,因为它只剩 `pointer.screenPx` 一处用到):

```js
function handleBody(nowMs, store, camera, domElement, hitObject) {
    // 优先级1. 若激活天体当前处于锁定状态 则说明鼠标:
    // - case1. 靠近label
    // - case2. 在label上
    // 此时直接进入label状态即可
    if (store.isActiveLocked) {
        store.enterLabel()
        return
    }

    // 优先级2. 仍然命中某个天体
    // 此时让enterBody()内部判断命中的天体是否发生改变即可
    if (hitObject !== null) {
        store.enterBody(hitObject)
        return
    }

    // 优先级3: 进入粘滞区
    // 若鼠标和当前激活天体的投影之间的距离小于进入粘滞区的距离时,则进入sticky状态
    const pointer = store.pointer
    const projection = store.activeProjection
    const sticky = store.sticky
    const distance = distanceToProjectionEdgePx(pointer.screenPx, projection.centerPx, projection.radiusPx)
    if (distance > 0 && distance < sticky.enterEdgeDistancePx) {
        store.enterSticky(nowMs)
        return
    }

    // 优先级4: 进入idle状态
    // 若以上3个优先级都不满足,则说明鼠标移动到了空白区域,进入idle状态即可
    store.enterIdle()
}
```

**`handleSticky`**(删掉 `const hitObject = pickHoveredBody(...)` 一行;`const pointer = store.pointer` 保留,优先级4 仍用 `pointer.screenPx`):

```js
function handleSticky(nowMs, store, camera, domElement, hitObject) {
    // 防御性措施: ... (保持不变)
    if (store.activeEntity === null) {
        store.enterIdle()
        return
    }

    // 优先级1: ... (保持不变)
    if (store.isActiveLocked) {
        store.enterLabel()
        return
    }

    // 优先级2: 鼠标从粘滞区移动到了天体上,此时应进入body状态
    // Tips: 这里检测是否靠近label或悬停在label上,是为了防止鼠标既在label上或者在label附近,且又命中了天体
    if (hitObject !== null && !store.isActiveLocked) {
        store.enterBody(hitObject)
        return
    }

    // 优先级3 / 优先级4: ... (保持不变,内部继续用 store.sticky / store.activeProjection / pointer.screenPx)
    const pointer = store.pointer
    // ... 原优先级3、优先级4 代码原样保留
}
```

**`handleLabel`**(删掉 `const pointer` 与 `const hitObject = pickHoveredBody(...)` 两行,本函数其余处不再用到 `pointer`):

```js
function handleLabel(nowMs, store, camera, _domElement, hitObject) {
    // 优先级1: 鼠标仍停留在label上或仍在label附近,则保持label状态不变即可,不需要做任何处理
    if (store.isActiveLocked) {
        return
    }

    // 优先级2: 鼠标离开label后,命中了天体,则进入body状态
    if (hitObject !== null) {
        store.enterBody(hitObject)
        return
    }

    // 优先级3: 鼠标离开label后,没有命中任何天体,则进入idle状态
    store.enterIdle()
}
```

## 4. 行为等价性 + 验收矩阵

**状态机行为不变**:`pickHoveredBody` 是 ndc + camera + pickableMeshes 的纯函数,一帧内值固定;提顶只投一次再透传,各 handler 拿到的 `hitObject` 与它们原先自己投射的结果完全相同,所有分支判定、状态流转一字不差。唯一新增的是每帧维护的 `isPointerOverBody` 信号(仅供光标)。

**位置 × 光标矩阵**(修复后):

| 鼠标位置 | `isPointerOverBody` | 顶层命中元素 | 实际光标 |
|---|---|---|---|
| 天体(非凹口) | true | canvas | pointer ✓ |
| 天体∩凹口 | true | canvas(穿透) | **pointer ✓(修复点)** |
| 空凹口(无天体) | false | canvas | default ✓ |
| 半透明面板(背后有天体) | true | `.shape` | default(面板赢,与"点不动"一致)✓ |
| 粘滞区(天体外) | false | canvas | default ✓ |
| 空白星空 | false | canvas | default ✓ |

> 倒数第三行:面板后即使 `isPointerOverBody` 为 true,`.shape` 是顶层命中元素、其 default 光标会赢,所以那里仍是 default——和"点击穿不过面板"自洽,无害。

## 7. 风险与未尽事项

### 7.1 每帧恰好一次射线投射(这正是选方案二的理由)

提顶后,无论哪个状态、是否锁定,每帧**恰好 1 次** `pickHoveredBody`(原先各 handler 是 0–1 次不定,锁定路径 0 次)。相比"方案一"(顶部专投一次 + handler 再各投一次,最多 2 次/帧),方案二零冗余射线。`resolveAnchor` 每帧多调 1 次(祖先回溯,开销可忽略)。

> 注:`enterBody(hitObject)` 内部仍会再 `resolveAnchor` 一次(仅发生在状态转换帧),与顶部的 `resolveAnchor` 有一次轻微重复。要彻底去掉需改 `enterBody` 改收"锚点"而非"叶子 Mesh",属更大的接口改动,本方案不做——昂贵的**射线投射**已做到每帧一次,这点 `resolveAnchor` 重复可忽略。

### 7.2 `!hasEverMoved` 早返回路径

`tickHover` step1 在鼠标从未移动时会 `return`,此时不会跑到 step4,`isPointerOverBody` 维持初值 `false`(页面刚加载、光标本就该是 default),无需特殊处理。若想显式,可在该早返回分支补一句 `store.setPointerOverBody(false)`,非必须。

### 7.3 `handleSticky` 优先级2 的 `!store.isActiveLocked` 现已冗余

该函数优先级1 已在 `isActiveLocked` 时 `return`,故优先级2 的 `&& !store.isActiveLocked` 恒为真、是死条件。本次为保持改动聚焦**未动它**;若后续想清理,可单独提一个小改动删除该冗余判断。

### 7.4 信号谓词与点击保持同源

光标信号用 `resolveAnchor(hitObject) !== null`,与点击的 `resolveFocusAnchor(...) !== null` 是同一谓词,保证"光标显示可点 ⟺ 真的能点"。将来若点击的可聚焦判定逻辑有变,记得让二者同步(理想情况下应抽到同一处)。
