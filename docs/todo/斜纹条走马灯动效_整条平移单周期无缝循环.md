# 斜纹条走马灯动效 — 实现方案(整条平移 + 单周期无缝循环)

> 需求:给 `OuterDecorLayer.vue` 的 `.stripe-chip`(斜纹条)加一个走马灯动效——整条斜纹条作为一个整体**匀速向右漂移**,右端滑出后消失,左端不断有新的平行四边形补入,形成**无缝无限循环**。
>
> **核心洞察:图案是空间周期性的,周期就是相邻平行四边形的水平间距 `pitch = 底边长度 7px + 间隙 5px = 12px`。** 因此只要让整条斜纹条 `translateX` 平移**恰好一个 pitch**(12px)再循环,末态画面就与初态**逐像素重合**,循环点的"跳回"完全不可见——这就是无缝的本质,不需要把整条内容复制两份做"首尾相接"那种重 marquee。
>
> **落地思路(三个支点):**
> 1. **窗口是现成的**:`.stripe-chip` 自带 `clip-path`(右倾平行四边形),它会把超出窗口的内容(连同子元素)一起裁掉。所以"滑出即消失、滑入即出现"这层遮罩**免费**,无需 `overflow:hidden`。
> 2. **加一条"传送带"**:在 chip 内部包一层 `.stripe-track`,让所有 `.stripe` 挂在传送带上;**chip 当固定窗口、track 当皮带**,动画只加在 track 上(chip 不能动,一动窗口就跟着跑了)。
> 3. **补根**:左侧多放一根"喂入根"(`--i = -1`),并把根数补到能填满窗口,否则循环接缝处会露空/跳变(详见 §3)。
>
> 只改 `OuterDecorLayer.vue` 一个文件,且全部在它的 `<style scoped>` 与模板里完成。

## 2. 当前结构回顾(改造前的基线)

`.stripe-chip` 是个 `85px × 5px` 的窗口,自带 `clip-path` 把它裁成右倾平行四边形。里面 6 个 `.stripe` 靠 `--i` 静态定位:

| 量 | 来源 | 取值 |
|---|---|---|
| 斜纹条宽 `--chip-width` | `OuterDecorLayer.vue:91` | `85px` |
| 斜纹延伸 `--chip-slope-run-length` | `= --chip-height × --notch-run-x / --notch-depth = 5 × 48/16` | `15px` |
| 平行四边形底边 `--stripe-bottom-line-length` | `OuterDecorLayer.vue:98` | `7px` |
| 平行四边形间隙 `--stripe-gap` | `OuterDecorLayer.vue:100` | `5px` |
| **水平间距(pitch)** | `底边 + 间隙` | **`12px`** |
| 平行四边形外接盒宽 | `底边 + 斜纹延伸 = 7 + 15` | `22px`(但 `clip-path` 后实际只是一根 `7px` 粗的斜杠) |

当前 6 根 `left = i × 12`(`i = 0..5`)→ 占据 `0..~67`,**窗口右侧约 1/3 是空的**。这对静态装饰无所谓,但做连续走马灯时必须填满(见 §8.1)。

> 斜率(15px 的水平延伸)只让每根斜杠和窗口一起向右倾斜,**不影响水平周期**——周期完全由 `left` 的间距 `pitch` 决定。所以纯水平平移时,斜杠与窗口的斜边始终对齐,移动过程视觉上不会"错位"。

## 3. 核心原理:为什么"平移一个 pitch"就无缝

### 3.1 周期性论证

把动画设为 `translateX: 0 → +pitch(12px)`,`linear`、`infinite`。下表列出各根的锚点 `left`(改造后 `i ∈ [-1, 7]`,共 9 根):

| `--i` | 初态 `left`(`translateX=0`) | 末态 `left`(`translateX=+12`) |
|---:|---:|---:|
| `-1`(喂入) | `-12`(窗口左外) | `0` |
| `0` | `0` | `12` |
| `1` | `12` | `24` |
| `2` | `24` | `36` |
| `3` | `36` | `48` |
| `4` | `48` | `60` |
| `5` | `60` | `72` |
| `6` | `72` | `84` |
| `7` | `84` | `96`(窗口右外) |

窗口 `[0, 85)` 内"**有根的 `left` 集合**":

- **初态**:`{0, 12, 24, 36, 48, 60, 72, 84}`(`i = 0..7`,`i=-1` 在左外被裁)
- **末态**:`{0, 12, 24, 36, 48, 60, 72, 84}`(`i = -1..6`,`i=7` 在右外被裁)

**两帧窗口内的图案完全相同**,只是承载它的 DOM 元素换了一批。所以动画从 `100%` 跳回 `0%` 时,画面逐像素一致,**接缝隐形**。

### 3.2 接缝正确性的两个条件

上面"末态≡初态"成立,依赖两根"边界根",缺一不可:

- **左侧喂入根 `i=-1`**:初态它在 `left=-12`(窗口外),末态滑到 `left=0`,顶上初态 `i=0` 的位置 → **左边缘不空**。少了它,末态左边缘 `0..12` 会空出来,循环时左边一跳。
- **右侧填满到 `i=7`**:初态它在 `left=84`(贴右边缘),保证初态右边缘也"有根";末态由 `i=6` 滑到 `84` 接班 → **右边缘前后一致**。少了它,初态右边缘没根、末态有根,循环时右边一跳。

> 一句话:**窗口要被填满,且左边再多挂一根在窗口外候着。** 这正是"右移时新根从左边补入"的来源。

### 3.3 根数公式

```
根数 = ⌈chip-width / pitch⌉ + 1(左侧喂入根)
     = ⌈85 / 12⌉ + 1 = 8 + 1 = 9
索引 i ∈ [-1, 7]
```

- `⌈85/12⌉ = 8` 根(`i=0..7`,`left = 0..84`)填满窗口;
- `+1` 根(`i=-1`)做左侧喂入。

**多渲染几根无害**(超出窗口的会被 chip 的 `clip-path` 裁掉,只是几个空跑的节点);**少渲染会在边缘/接缝露馅**。所以 9 是"刚好",取 10、11 也行,别少于 9。

## 4. 文件改动详情

### 4.1 模板 — 包一层传送带 + 扩根

`OuterDecorLayer.vue:11-22`。

**改前**:

```vue
<!-- 斜纹条开始 -->
<div class="stripe-chip">
    <!-- 平行四边形开始 -->
    <div
        class="stripe"
        v-for="n in 6"
        :key="n"
        :style="`--i: ${n - 1}`">
    </div>
    <!-- 平行四边形结束 -->
</div>
<!-- 斜纹条结束 -->
```

**改后**:

```vue
<!-- 斜纹条开始 -->
<div class="stripe-chip">
    <!-- 传送带(承载所有平行四边形, 整体平移的图层)开始 -->
    <div class="stripe-track">
        <!-- 平行四边形开始 -->
        <div
            class="stripe"
            v-for="n in 9"
            :key="n"
            :style="`--i: ${n - 2}`">
        </div>
        <!-- 平行四边形结束 -->
    </div>
    <!-- 传送带结束 -->
</div>
<!-- 斜纹条结束 -->
```

> `n in 9` → `n = 1..9` → `--i = n - 2` → `i = -1, 0, 1, …, 7`,正好覆盖 §3.3 的 `[-1, 7]`。可见图案的左边缘仍从 `left=0`(`i=0`)起,只是右侧补满、左侧多挂一根喂入根,**静态左对齐不变**。

### 4.2 `.stripe-chip` — 提取周期变量 + 速度旋钮

`OuterDecorLayer.vue:98-100` 附近,在 `--stripe-gap` 之后追加:

```css
/* 平行四边形底边长度 */
--stripe-bottom-line-length: 7px;
/* 平行四边形间隙 */
--stripe-gap: 5px;
/* 平移周期: 相邻平行四边形的水平间距 = 底边 + 间隙;
   它既是 .stripe 的定位步长, 也是走马灯单次循环的平移距离 —— 两者同源是无缝的前提 */
--stripe-pitch: calc(var(--stripe-bottom-line-length) + var(--stripe-gap));
/* 走马灯单次循环时长(平移一个 pitch 的耗时), 唯一的速度旋钮: 越小越快 */
--marquee-duration: 1.6s;
```

> 把 `pitch` 抽成单一变量是**无缝的保险**:将来若调底边长度或间隙,`.stripe` 的 `left`(§4.3)和 `@keyframes` 的平移量(§4.5)会**同时**跟着变,二者永远相等,不会出现"排布步长"和"平移距离"对不上导致的跳变。

### 4.3 `.stripe` — `left` 改用周期变量

`OuterDecorLayer.vue:130-131`。

**改前**:

```css
/* 水平方向位置 = i * (平行四边形宽度 + 平行四边形间隙) */
left: calc(var(--i) * (var(--stripe-bottom-line-length) + var(--stripe-gap)));
```

**改后**:

```css
/* 水平方向位置 = i * 平移周期 */
left: calc(var(--i) * var(--stripe-pitch));
```

> 纯粹是把行内重复的 `底边 + 间隙` 收敛到 `--stripe-pitch`,**数值不变**(仍是 `i × 12px`),只是与平移量同源。

### 4.4 新增 `.stripe-track` 规则 — 传送带

放在 `.stripe-chip` 规则之后、`.stripe` 规则之前(`OuterDecorLayer.vue:119` 之后):

```css
/* 传送带开始 */
.outer-decor-layer .stripe-chip .stripe-track {
    position: absolute;
    /* 与 chip 同坐标系(inset:0 铺满窗口), 故 .stripe 的 left 取值无需改动 */
    inset: 0;
    /* 整条斜纹条作为一个整体水平平移; linear 保证匀速, infinite 无限循环 */
    animation: stripe-marquee var(--marquee-duration) linear infinite;
}
/* 传送带结束 */
```

> - `.stripe-track` 设 `position:absolute; inset:0`,它成为 `.stripe` 新的定位参照(offsetParent),但因为铺满整个 chip,坐标原点与原来(chip)重合,`.stripe` 的 `left` 不用动。
> - 动画只加在 track 上——**chip 保持不动,继续当固定窗口**。

### 4.5 新增 `@keyframes` — 平移一个 pitch

放在 `<style scoped>` 内(同组件即可,见 §5.2):

```css
@keyframes stripe-marquee {
    from {
        transform: translateX(0);
    }
    to {
        /* 正好平移一个 pitch: 末态与初态逐像素重合, 循环点无缝(论证见 §3) */
        transform: translateX(var(--stripe-pitch));
    }
}
```

> `translateX` 为正 = 向右;`from→to` 即 `0 → +12px`,符合"整条向右漂移"。

### 4.6 新增 `@media` — 尊重"减少动态效果"

```css
/* 系统开启"减少动态效果"时, 停掉走马灯, 退化为一条静态(已填满)的斜纹条 */
@media (prefers-reduced-motion: reduce) {
    .outer-decor-layer .stripe-chip .stripe-track {
        animation: none;
    }
}
```

## 5. 几个关键点说明

### 5.1 `clip-path` 会裁掉"平移后的子元素"吗?——会

`clip-path` 加在祖先 `.stripe-chip` 上,它对**整棵子树**(含 track、stripe)在 chip 的坐标系里裁剪。子元素即便自己带 `transform`(track 的平移),**仍然被祖先的 `clip-path` 裁**,不会"逃出"窗口。所以滑出窗口的斜杠一定被切掉、滑入的才显形——这正是我们要的遮罩,且斜杠是沿着窗口的**斜边**进出的,观感自然。

### 5.2 scoped 里的 `@keyframes` 安全吗?——安全

Vue 的 `<style scoped>` 会把 `@keyframes stripe-marquee` 的名字连同 `animation` 里对它的引用**一起重写**(加组件哈希),所以**只要 `@keyframes` 和用它的 `.stripe-track` 在同一个 SFC 的 scoped 块里**就万无一失,也不会和别的组件同名动画冲突。不要从别的文件去引用这个 keyframe。

### 5.3 `@keyframes` 里的 `var(--stripe-pitch)` 能解析吗?——能

`--stripe-pitch` 定义在 `.stripe-chip` 上,自定义属性会**继承**给子元素 `.stripe-track`;keyframe 的 `var(--stripe-pitch)` 是针对被动画的元素(track)求值的,所以解析为 `12px`,`transform` 在 `0 → 12px` 间插值。**前提**:`--stripe-pitch` 必须定义在 track 的某个祖先上(现在在 chip,满足)。

### 5.4 速度 / 方向 / 缓动

- **速度**:只调 `--marquee-duration`(§4.2)。可视速度 = `pitch / duration`,`1.6s` 时约 `7.5px/s`,一根斜杠扫过 85px 窗口约 11s——克制、适合装饰。想更快就调小,如 `1.2s`。
- **方向**:`translateX` 取正即向右;若要向左,改 `to { transform: translateX(calc(-1 * var(--stripe-pitch))); }`,**喂入根则要改放到右侧**(对称地把 `--i` 上限 +1)。
- **缓动**:**必须 `linear`**。用 `ease` 会让每个循环"快—慢—快"地脉动,匀速感全失。

## 8. 风险与未尽事项

### 8.1 静态外观从"约 2/3 填充"变为"填满"(设计取舍)

改造前 6 根只占窗口左侧约 2/3、右侧留白;改造后为了让走马灯"连续不断"必须填满窗口(否则会有一大段空白周期性地扫过,很怪)。所以**静止/暂停时**的斜纹条会比现在"更满"。这是把它从"静态短条"升级成"连续皮带"的必然结果。若你其实想保留稀疏留白的观感,需要另一套思路(比如固定一段图案整体平移再整体淡入淡出),不在本方案内——请确认是否接受"填满"。

### 8.2 动画常驻

若 label 是用 `opacity` 淡出(DOM 常挂、不 `v-if` 卸载),则 label 隐藏期间这条走马灯仍在后台跑。尺寸仅 `85×5`、`transform` 走合成层,开销可忽略;真要极致省电,可在 label 的隐藏态加一个 class 给 `.stripe-track` 置 `animation-play-state: paused`。当前不必做。

### 8.3 性能

动画只动 `transform`(不动 `left`/不触发重排),由合成器处理,代价极低。可选在 `.stripe-track` 加 `will-change: transform` 提示分层;但动画常驻时浏览器本就会分层,加不加差别不大,**默认不加**,避免无谓的常驻图层内存。

### 8.4 备选:不加 `.stripe-track`,逐根加同一动画

也可以不包传送带,直接给每个 `.stripe` 挂同一条 `animation`——它们同规则、同时间线,天然同步,效果等价。优点是模板少一层嵌套;缺点是 9 个动画实例 vs 1 个、且"皮带"的心智模型没那么直观。本方案取**加一层 track**(单一平移图层、概念清晰)为主推,逐根动画作为等价备选。
