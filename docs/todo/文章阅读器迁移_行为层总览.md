# 文章阅读器迁移 · 行为层(Step 2)总览

> **范围**:静态三件套(布局壳 / 目录树 / 文章区)之后的「行为层」总设计。把源 `state` + `ui/render.js` + `interaction/toggleFolder.js` + `structure/tree.js` 的命令式交互,迁为**一个 Pinia store(`stores/catalogue.js`)+ 响应式组件接线 + 少量命令式 DOM 副作用**。
>
> **定位**:本份是 Step 2 的**总览 / 地基**,只定 ① 状态模型 ② store API ③ 纯函数 ④ 布局矩阵 ⑤ 副作用归属 ⑥ 子步拆分。各步(2a–2d)的**可照抄实现另起文档**(见 §6),本份是它们共同的参照。
>
> **关联**:doc《目录树》§2.1(`RenderPhase` / `CatalogueNodeType` 枚举,本层直接复用)、§8(留松);doc《文章区》§6(留松:phase / 联动、按钮行为、蒙版、真实正文);`stores/focus.js` / `stores/hover.js`(store 写法范式)。
>
> **决策记录**:store 取「**精简派生**」模型 —— 只存 3 个不可推导量(`activeNodeId` / `collapsedIdSet` / `focusedPane`),其余(`renderPhase` / 路径 / 面包屑 / 两栏宽度 / 蒙版)全部 getter 派生。与 `focus.js` / `hover.js`「存最小状态、`computed` 派生」的写法一致,根治冗余状态的同步漂移(我们已踩过 `renderNonleaf`/`renderNonLeaf` 那类 bug)。

## 0. 源行为 → 迁移去向(蒸馏)

| 源(命令式) | 迁移去向(响应式) |
|---|---|
| `state.phase`(`renderLeaf`/`renderNonleaf`) | **派生** getter `renderPhase`:由 `activeNode.type` 算 → `RenderPhase` |
| `state.activeNode` | **派生**:由 `activeNodeId` 查树(索引) |
| `state.rootToActivePath` | **派生**:索引取路径 |
| `collapsedIdSet`(模块级 `Set`) | store `collapsedIdSet: ref(Set)` |
| 隐式 focus(`concentrateCatalogue` 写行内样式) | store `focusedPane: ref(FocusedPane 枚举)`(用状态 + class,**不写行内样式**) |
| `initCollapsed` / `dfsFindNodeWithPath` / `dfsFindFirstLeafNode` | 搬成纯函数(`lib/treeQuery.js`,§3) |
| `changeActiveNode(targetId)` | action `selectNode(id)` |
| `openArticle` / `concentrateCatalogue` / `resetToArticleActive` | action `openArticle()` / `focusCatalogue()` / `focusArticle()` |
| `clickHandle`(事件委托 + `closest('.row')` + `dataset.id`) | `TreeNode` 各自 `@click` 自己的 `.row`,直接拿到本节点 `node`(无需委托/查 DOM) |
| `renderCatalogue/Article/PageTitle`、`renderActive*`(`replaceChildren`/`classList`/`innerHTML`) | **整体蒸发**,化为组件模板的 `v-if` / `:class` / `v-html` + getter |
| `renderTree` / `createLiElement` | 已被 doc《目录树》的 `TreeNode` 取代 |
| `mountSimpleBar`(内容变后重挂) | `onMounted` 挂载 + 内容变后 `nextTick` → `recalculate()` |

**中心原则**:源那套「命令式重建 DOM」绝大部分**蒸发**,变成组件读 store getter 的声明式绑定。**store 只管数据,组件负责渲染**,只有 3 处不可避免的副作用保留命令式。

**保留命令式的 3 处副作用**(它们不是 store 状态,是 DOM 宿主组件的事,详见 §5):
1. 文件夹展开/折叠的**高度动画**(源 `toggleFolder` 的 `0↔scrollHeight` + `transitionend`);
2. **`ensureNodeVisible`**(在 SimpleBar 容器内把目标节点滚进视口);
3. **SimpleBar `recalculate`**(内容随状态变后重算滚动条尺寸)。

**保留的一个源 UX**:源 `clickHandle` 对任意行**同时**做 `toggleFolder`(仅 folder 有效)+ `changeActiveNode`(选中渲染)。即:
- **点文件夹行** = 展开/折叠 **且** 文章区显示它的简介(非激活态);
- **点文件行** = 文章区显示它的 markdown(激活态)。

迁移默认**保留**这个耦合。

## 1. 状态模型:精简派生

store 只存「**不可再推导**」的 3 个量,其余全是它们 + 树的纯函数:

| state | 类型 | 含义 / 默认 |
|---|---|---|
| `activeNodeId` | `ref(Number)` | 当前选中节点 id。默认 = 根 id(`1`),对应源 `activeNode: tree` |
| `collapsedIdSet` | `ref(Set<Number>)` | 折叠的文件夹 id 集。由 `initCollapsedIdSet` 种入(根展开、depth≥1 folder 折叠) |
| `focusedPane` | `ref(String)` | 当前被聚焦(宽 70%)的面板:`FocusedPane.catalogue` / `.article`,默认 catalogue(浏览态)。**nonLeaf 下恒为 catalogue**(聚焦文章只能在阅读态) |

> **为什么 `renderPhase` 不存而派生**:`renderPhase` / 路径 / 面包屑都是「选中节点 + 树」的纯函数,**存了就要手动同步、极易漂移**。`focus.js` 的 `shouldShowPanel`/`inFocusMode`、`hover.js` 的 `shouldShowLabel` 同样是 `computed` 派生,不进 state —— 本 store 与之一致。
>
> **`collapsedIdSet` 用 `ref(new Set())` 即可**:Vue 3 对 `Set`/`Map` 有响应式集合处理,`set.add/delete` 会触发依赖;组件里 `collapsedIdSet.value.has(id)` 在渲染期访问即被追踪,集合变更会重渲染。无需 `reactive` 或重新赋值。

## 2. store API(`stores/catalogue.js`)

> 写法对齐 `focus.js` / `hover.js`:`defineStore('article', () => {…})` setup 式,分 PART 注释,`return` 分组导出,文件尾 `@typedef {ReturnType<typeof useArticleStore>} ArticleStore`。**完整可照抄代码在 2a 文档**;此处只列 API 形状。

**Getters(全派生)**

| getter | 公式 / 行为 |
|---|---|
| `activeNode` | `computed` —— 索引查 `activeNodeId`(兜底根节点,保证恒非空) |
| `renderPhase` | `computed` —— `activeNode.type === CatalogueNodeType.file ? RenderPhase.leaf : RenderPhase.nonLeaf` |
| `rootToActivePath` | `computed` —— 索引取「根→activeNode 父」的节点数组(不含 activeNode 自身) |
| `breadcrumb` | `computed` —— 遍历 `rootToActivePath` 收集 `name`,末尾补 `activeNode.name`,`'/'` 连(HeaderBar 用;路径空时即根名) |
| `isCatalogueActive` | `computed` —— `focusedPane === FocusedPane.catalogue`(聚焦目录即宽) |
| (文章列 class) | 由 `renderPhase` 驱动:leaf→`article-active`;专注态仍 active、靠 `.has-mask` 收窄(细化见 2c《文章联动》§1) |
| `hasMask` | `computed` —— `renderPhase===leaf && focusedPane===catalogue` |
| `articleHtml` | `computed` —— `renderPhase===leaf ? renderMarkdownToHtml(getLeafContent(activeNode)) : ''`(非叶不算,省开销) |
| `isCollapsed(id)` | **函数**(非 computed,带参)—— `collapsedIdSet.value.has(id)`,`TreeNode` 用 |

**Actions**

| action | 行为 |
|---|---|
| `initCollapsed()` | `collapsedIdSet.value = initCollapsedIdSet(treeData)`(种入初始折叠集);store 初始化时调一次 |
| `selectNode(id)` | `activeNodeId.value = id`;焦点按节点类型移交(file→`article`、folder→`catalogue`;专注态蒙版自然消失 —— 忠实源 `clickHandle` 清 `hasMask`) |
| `toggleCollapsed(id)` | `collapsedIdSet` 中 `has` 则 `delete` 否则 `add`(**仅改数据**,高度动画在组件侧) |
| `expandFolders(ids)` | 对一组 id 逐个 `collapsedIdSet.delete`(强展开,`openArticle` 展开路径用;无动画) |
| `openArticle()` | 见下「openArticle 流程」 |
| `focusCatalogue()` | `focusedPane = catalogue`(阅读 → 专注;浏览态本就聚焦目录,幂等) |
| `focusArticle()` | `focusedPane = article`(专注 → 阅读;**带 leaf 守卫**——`(nonLeaf, article)` 是非法组合,nonLeaf 下调用忽略) |

**`openArticle()` 流程**(源 `render.js` `openArticle`):
```
const leaf = dfsFindFirstLeafNode(treeData, activeNodeId.value)   // 当前(文件夹)下首个叶子
if (leaf === null) return
const { path } = nodeIndex.get(leaf.id)        // 叶子的根→父 路径
expandFolders(path.map(n => n.id))             // 展开路径上所有文件夹
selectNode(leaf.id)                            // 选中叶子(renderPhase 自动变 leaf)
pendingRevealId.value = path.at(-1)?.id ?? null // 交给 CatalogueTree 滚动(见 §5)
```

> **`focusCatalogue`/`focusArticle` 为何如此之薄**:源用行内样式 + `classList` + 重建按钮一大坨;本层全交给 §4 的布局 getter + 模板,action 只改一个枚举值。这是「无行内样式」改造的红利。

## 3. 纯函数(`lib/treeQuery.js`)

把源 `structure/tree.js` 的查询逻辑搬成纯函数(`treeData.js` 保持纯数据)。供 store 与组件使用,可单测:

| 函数 | 签名 / 行为 |
|---|---|
| `buildNodeIndex(root)` | `→ Map<Number, { node, path }>`。一次 DFS 建索引,`path` = 根→父(不含自身)。`activeNode`/`rootToActivePath`/openArticle 取路径全走它,O(1) 查。数据是静态桩,建一次即可;接 axios 后数据变更时重建 |
| `dfsFindFirstLeafNode(root, nodeId)` | `→ CatalogueNode \| null`。先定位 `nodeId` 节点,再 DFS 取其下首个 `file`;非 folder / 无 children 返回 `null`(源同名函数) |
| `getLeafContent(node)` | `→ String`。`node.content` 非空则用之,否则返回一份长示例 md(源 `getLeafMarkdownContent`,用于联调滚动/样式)。**接 axios 后换 `node.content`** |
| `initCollapsedIdSet(root)` | `→ Set<Number>`。DFS 收集所有 `type==='folder' && depth>=1` 的 id(源 `initCollapsed` 规则),返回集合交给 store 持有 |

> `dfsFindNodeWithPath` 作为 `buildNodeIndex` 的内部递归构件(或保留为独立工具);对外主用索引。节点类型比较一律走 `CatalogueNodeType.folder`/`.file`(枚举值 = axios 下发串,零转换)。

## 4. 布局 / 按钮矩阵(renderPhase × focusedPane 的 3 个合法态)

| 态 | 目录列 | 文章列 | 内容 | 蒙版 | 底部按钮 |
|---|---|---|---|---|---|
| **浏览** `nonLeaf` | active 70% | inactive 30% | 简介 `intro` | 无 | `开启文章`(`.bottom-button`)→ `openArticle()` |
| **阅读** `leaf, article` | inactive 30% | active 70% | markdown | 无 | `专注目录` + 图标 → `focusCatalogue()` |
| **专注** `leaf, catalogue` | active 70% | **active + `.has-mask`**(收窄) | markdown(仍在) | 有 | `开启文章`(`.has-mask-button`)→ `focusArticle()` |

**布局由 `renderPhase` + `isCatalogueActive` + `hasMask` 驱动 class,无行内样式**(对齐 doc《文章区》§6):
- 目录列:`isCatalogueActive` → `catalogue-active` / `catalogue-inactive`;
- 文章列:`renderPhase` → `article-active`(leaf)/ `article-inactive`(nonLeaf);专注态仍 `article-active`、靠 `.has-mask` 收窄(见 2c);
- 蒙版:`hasMask` → `.has-mask`。

⚠ **迁移最易写错的源细节**:「浏览」与「专注」两栏宽度、按钮文案**都相同**,但**同样「开启文章」四个字是两种行为**:
- 浏览态点它 = `openArticle`(选首叶、进阅读),按钮类 `.bottom-button`;
- 专注态点它 = `focusArticle`(焦点还文章、回阅读),按钮类 `.has-mask-button`,文章仍是 markdown + 蒙版。

按钮三态由模板按 `renderPhase` + `focusedPane` 决定(文案 / 类名 / `@click` 三者一起切),**不要复用同一个 `@click`**。

> **首屏不变**:默认 `activeNodeId = 根`、`focusedPane = catalogue` → `renderPhase = nonLeaf` → 目录 active 70% + 文章 inactive 30% + 根简介,正好重现当前静态默认。行为层接上去首屏零差异。

## 5. 命令式副作用归属(store 纯数据,3 处副作用落组件 / composable)

| 副作用 | 宿主 | 触发 |
|---|---|---|
| **折叠高度动画** | `TreeNode` 内(可抽 `composables/useCollapseTransition`) | 监听本节点 `isCollapsed` 变化,做 `ul` 高度 `0↔scrollHeight` 动画。**技法(`<Transition>` JS 钩子 vs 手动 `watch`+height)留到 2b 定** |
| **`ensureNodeVisible`** | `CatalogueTree`(方法 / composable) | `openArticle` 后 `nextTick` 在 SimpleBar 容器内把目标滚进视口 |
| **SimpleBar `recalculate`** | `CatalogueTree` / `ArticlePane` | 内容随状态变后 `nextTick` 重算 |

**跨组件滚动的接线**(`openArticle` 按钮在 ArticlePane,要滚的却是 CatalogueTree):store 暴露一个**瞬时信号** `pendingRevealId: ref(Number|null)`;`openArticle()` 写入目标文件夹 id;`CatalogueTree` `watch(pendingRevealId)`,变更时 `nextTick → ensureNodeVisible → 清空`。这是 Vue 里跨组件 DOM 副作用的解耦通道,**最终形态在 2c 定**。

> **不要在每次 `selectNode` 都滚动**:源只在 `openArticle` 滚(直接点目录里的节点不滚 —— 它本就可见)。故用 `pendingRevealId` 信号区分「openArticle 触发的选中」与「直接点击的选中」。

## 7. 接缝 / 各步再定(本总览不锁死)

- **折叠动画技法**:`<Transition>` + JS 钩子 vs `TreeNode` 内 `watch(isCollapsed)` 手动 height —— 2b 定。源是后者(`transitionend` + `scrollHeight`),Vue 化后可更干净。
- **`expandFolders` 的「无动画强展开」**:`openArticle` 展开路径时若沿用动画会有多段 height 过渡;源 `forceExpandFolderLiElement` 是直接置 `height:auto`。2b/2c 决定是否给一个「跳过动画」的展开路径。
- **`recalculate` 时序**:内容变 → `nextTick` → `recalculate`;与折叠动画的 `transitionend` 是否需要协调,2b/2c 实测定。
- **axios 化**:`treeData` 现为静态桩,接后端后结构不变(`CatalogueNodeType` 枚举值 = 下发串);届时 `buildNodeIndex` 在数据到达后重建一次,其余不动。
- **`pendingRevealId` 信号**:是否需要扩成 `{ id, behavior, block }` 以复用源 `ensureNodeVisible` 的 `center`/`nearest` —— 2c 定。
