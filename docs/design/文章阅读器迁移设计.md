# universeBlogContent → SolarNotesFrontend 文章阅读器迁移设计

> 源项目:universeBlogContent(原生 JS + Webpack,命令式 DOM 的「目录树 + Markdown 文章」阅读器)
> 目标项目:SolarNotesFrontend(Vue 3 + Vite + vue-router + Pinia)
> 落点:本项目已存在的 `/article` 路由(懒加载 `src/pages/ArticleReader.vue`,当前是占位 stub)
> 姊妹文档:`迁移规划.md`(3D 太阳系迁移)、`字体迁移.md`(字体审计与迁移),本文沿用其审计 + 分阶段 + 验收的写法。

---

## 1. 总览

源项目是一个**纯前端阅读器**:左侧目录树(可折叠/展开),右侧文章区(目录节点简介 / 文件节点 Markdown 正文),外加"专注目录"蒙版模式与 SimpleBar 自定义滚动条。它用命令式 DOM(`document.createElement` + `innerHTML` + 行内 `style`)实现,核心是一台渲染状态机。

目标项目是 Vue 3 + Vite,已经用 Pinia 管理跨组件状态(`stores/focus.js`、`stores/hover.js`),并已为文章阅读器预留了 `/article` 路由。**迁移即把这台命令式状态机改写成「Pinia 状态 + Vue 响应式组件」,落到 `ArticleReader.vue` 及其子组件**。

### 1.1 关键决策(已确认)

| 维度 | 决策 | 理由 |
| --- | --- | --- |
| 状态管理 | **Pinia store**(新增 `stores/article.js`) | 与本项目既有 `stores/focus.js`、`hover.js` 一致,可在 devtools 检视 |
| 字体图标冲突 | **iconfont.cn 合并重导出**为单一字体 | 两套同名 `iconfont` 字体合一,最干净;代价是一次仓库外手动操作 |
| 组件拆分粒度 | **中等粒度(约 5 个组件)** | 清晰且文件量适中(YAGNI),避免源设计文档里 ~10 组件的过度拆分 |

### 1.2 核心原则

1. **纯逻辑 → JS 模块 / store**:树遍历(DFS)、Markdown 渲染是纯函数,直接迁移为 `lib/` 模块;状态机的"状态"进 Pinia。
2. **命令式 DOM → Vue 响应式**:`renderTree` / `createLiElement` / `replaceChildren` 这类手工建节点,改写为递归组件 + `v-for` / `v-if` / 绑定。
3. **DOM 测量/动画留在组件,不进 store**:`getBoundingClientRect`、折叠高度动画、SimpleBar 挂载属于视图副作用,放组件的 `onMounted` / `nextTick` / `ref`;store 只存纯状态。
4. **CSS 分层**:全局重置 / 字体声明 / 页面布局 / 内容主题(Markdown、滚动条)分开处理,尤其注意 `v-html` 与 SimpleBar 注入的 DOM **拿不到 scoped 属性**(见 §8)。

### 1.3 不迁移的东西(由 Vite/Vue 接管)

| 源文件 | 处理 |
| --- | --- |
| `webpack.config.js` | 废弃,Vite 已是本项目构建器 |
| `public/index.html` | 废弃,其 `header + articleWrap + catalogue + article` 骨架改写为 `ArticleReader.vue` 模板 |
| `src/index.js` | 废弃,其「全局 CSS import + `initRender()`」分别落到 `App.vue`(全局 CSS 已就位)、`ArticleReader.vue`(主题 CSS 懒加载 + 初始化 store) |

### 2.1 源模块清单

### 2.2 状态机审计(`render.js`)

源状态机的真实"状态"只有三组,其余都是从它们派生的视图:

- `phase`:`'renderNonleaf'`(文件夹,显示简介)/ `'renderLeaf'`(文件,显示 Markdown)
- `activeNode`:当前激活节点对象
- `rootToActivePath`:根 → 当前节点父级的祖先数组(不含当前节点)
- (模块作用域)`collapsedIdSet`:折叠中的文件夹 id 集合
- "专注目录"蒙版:源里是命令式行内样式,没有显式状态字段 —— 迁移时显式化为 `isFocusMode`

> **可约简**:`phase`、`activeNode`、`rootToActivePath`、页头路径标题**都能由 `activeNodeId` 派生**(`dfsFindNodeWithPath` 一次返回节点 + 路径,节点 `type` 决定 phase)。因此真正的状态只有 `activeNodeId` + `collapsedIdSet` + `isFocusMode`,其余做成 getter,避免冗余状态(对齐本项目"不引入不必要中转变量"的约定)。

## 4. 状态层设计 —— `stores/article.js`

**纯状态原则**:store 只存"无法从别处派生的最小状态",视图副作用一律不进 store。

```js
// 形状示意(非最终实现)
export const useArticleStore = defineStore('article', {
    state: () => ({
        activeNodeId: rootId,          // 唯一的"选中"真源
        collapsedIdSet: new Set(),     // 折叠中的文件夹 id(Vue 3 reactive 支持 Set)
        isFocusMode: false,            // "专注目录"蒙版
    }),
    getters: {
        activeNode,        // dfsFindNodeWithPath(treeData, activeNodeId) 派生
        rootToActivePath,  // 同上,取 path
        phase,             // activeNode.type === 'file' ? 'renderLeaf' : 'renderNonleaf'
        pageTitle,         // [...path, activeNode].map(n => n.name).join('/')
        isCollapsed,       // (id) => collapsedIdSet.has(id)
    },
    actions: {
        initCollapsed(),       // 加载时按"根展开、其余折叠"播种 collapsedIdSet
        selectNode(id),        // 切换选中(点击节点)
        toggleFolder(id),      // 翻转 collapsedIdSet
        expandPath(ids),       // 从 collapsedIdSet 移除一组 id(强制展开路径)
        openFirstLeaf(),       // 从当前文件夹进入首个叶子:selectNode + expandPath
        setFocusMode(on),      // 切换蒙版
    },
})
```

**不进 store(视图副作用,放组件)**:

| 源逻辑 | 落点 |
| --- | --- |
| 折叠/展开高度动画(`scrollHeight` + `transitionend`) | `TreeNode` 的 `ref` + `watch(isCollapsed)`,或 `<Transition>` |
| `ensureNodeVisible`(`getBoundingClientRect` + 滚动 `.simplebar-content-wrapper`) | `CatalogueTree` 方法,`openFirstLeaf` 后经 `nextTick` 调用 |
| SimpleBar 挂载 / `recalculate` | `useSimpleBar` composable,`onMounted` + 内容变更后 `nextTick` 调 |
| Markdown → HTML | `ArticlePane` 用 `lib/markdown.js` 算出再 `v-html` |

> 源 `clickHandle` 里"清除专注模式留下的行内 `style`"那段(`articleElement.style = ''`)在 Vue 里**自然消失** —— 宽窄/透明度都由 `isFocusMode` 驱动 class,不再有手写行内样式需要清理。

## 5. 组件拆分(中等粒度)

### 5.1 组件职责

| 组件 | 对应源结构 | 职责 |
| --- | --- | --- |
| `ArticleReader.vue` | `public/index.html` 骨架 + `src/index.js` | 页面壳:`.articleWrap` 左右布局、页面背景(§8 的 `body` 规则挂这)、懒加载主题 CSS、`onMounted` 播种 store;装配下面三个 |
| `HeaderBar.vue` | `.header` | 显示 `store.pageTitle`;"返回太阳系" → `<router-link>` |
| `CatalogueTree.vue` | `.catalogue` + `renderTree` | SimpleBar 宿主;渲染根 `<TreeNode>`;承接节点点击 → `store.selectNode/toggleFolder`;`ensureNodeVisible` |
| `TreeNode.vue` | `renderNode` / `createLiElement` + `toggleFolder` 动画 | **递归组件**:一行 row(图标 + 文字,`--depth` 缩进)+ 子 `<ul>`(递归自身);读 `store.isCollapsed/activeNode`;折叠动画 |
| `ArticlePane.vue` | `renderActiveArticle` / `renderInactiveArticle` + 按钮 + 蒙版 | 按 `store.phase` 切激活/非激活视图;激活=标题 + `.markdown-body` v-html + 日期 + "专注目录"按钮;非激活=简介 + "开启文章"按钮;`isFocusMode` 蒙版;SimpleBar 宿主 |

> 若 `ArticlePane` 因激活/非激活两套结构变臃肿,可再拆 `ArticleActiveView` / `ArticleInactiveView` 两个纯展示子组件 —— 但中等粒度下先用一个组件 + `v-if` 分支,够清晰再说(YAGNI)。

### 5.2 数据流约定

- **单向**:子组件只发事件 / 调 store action,不直接改全局状态;状态集中在 `stores/article.js`。
- **读**:各组件按需读 store 的 state/getter(`activeNode`、`phase`、`isCollapsed`…),响应式自动重渲染。
- **写**:点击节点 → `selectNode`/`toggleFolder`;"开启文章" → `openFirstLeaf`;"专注目录"/"恢复文章" → `setFocusMode`。

### 5.3 源 → 目标映射

| 源 | 目标 | 备注 |
| --- | --- | --- |
| `structure/tree.js`(数据) | `data/treeData.js` | 纯数据,原样 |
| `structure/tree.js`(DFS / initCollapsed) | `lib/treeTraversal.js` | 纯函数,原样 |
| `structure/tree.js`(renderTree 等命令式 DOM) | `TreeNode.vue` / `CatalogueTree.vue` | 改写为递归组件 |

## 8. CSS 收敛策略(最关键)

迁移最大的坑是 **Vue scoped CSS 的边界**:`v-html` 注入的 Markdown 内容、SimpleBar 运行时注入的滚动条 DOM,都**没有** Vue 编译期加的 `[data-v-xxx]` 属性,因此 scoped 样式对它们**静默失效**。策略按"作用域能否覆盖"分四层:

1. **全局重置层** —— `reset.css` 已与本项目一致,不动。
2. **字体声明层** —— `font.css` 追加 500;`@font-face` 不参与级联,顺序无所谓。
3. **页面布局层** —— `articleWrap/header/catalogue/article(布局部分)` 跟随各自组件(scoped 或 `:deep()`)。
   - 例外 **`tree.css`**:大量 `.tree .children .node` 后代选择器 + 递归 `TreeNode`,scoped 会因子组件根元素只带一层 scope 属性而断 → **作为页面级非 scoped 样式引入,或全程 `:deep()`**。
   - 例外 **`index.css` 的 `body`**:源把背景图/flex/100vh 写在 `body`,本项目 `body` 是 3D 场景的全局根 → 这些规则**改挂 `.article-reader` 页面根**,`--tree-*` 变量与 `button { border:none }` 同样收到页面根作用域,杜绝泄漏到 `/solar`。
4. **内容主题层(必须全局 / `:deep()`)** —— `markdown.css`(`.markdown-body`)、`scroll/*` 与 `simplebar.css`(`.simplebar-*`)、highlight 主题。这层**不能 scoped**,因为它们作用的 DOM 是 `v-html` 或 SimpleBar 运行时产物。靠类名前缀(`.markdown-body` / `.simplebar-*`)隔离,而非 scoped。

> 落地口径:内容主题层在 `ArticleReader.vue` 顶部 `import`(§6);布局层尽量进组件 `<style scoped>`,触及注入 DOM 时用 `:deep()`;`tree.css` 走页面级。

## 12. 风险与边界

1. **`v-html` × scoped CSS**:Markdown 与 SimpleBar 注入的 DOM 拿不到 scope 属性 → 内容主题层必须全局 / `:deep()`(§8)。**本次迁移最易踩的坑**。
2. **递归组件 × 后代选择器**:`tree.css` 走页面级非 scoped 或 `:deep()`,否则递归层级的样式会断。
3. **DOM 测量进组件、不进 store**:`ensureNodeVisible` / 折叠高度动画 / SimpleBar 都依赖真实 DOM 尺寸,放 `onMounted` / `nextTick` / `ref`;内容变更后统一 `nextTick` → `simpleBar.recalculate()`。
4. **iconfont 是仓库外手动步骤**:你在 iconfont.cn 操作,属基础工作(已完成);做完前图标是豆腐块,属预期。
5. **`body` 背景不可泄漏到 3D 路由**:源的 `body { background }` 改挂 `.article-reader` 页面根。
6. **mock 数据 / 无后端**:`treeData.js` 与"叶子无 `content` 时生成示例 Markdown"都是 mock。`treeData` 结构预留后端替换点(将来按 id 拉真实 Markdown 即可),本次不接后端。
7. **测试**:源与本项目都无测试设施;仅建议对纯函数(`treeTraversal` / `markdown`)补可选最小单测,不在本次硬性范围内。
8. **折叠动画移植**:源用 `transitionend` + 手动设 `height` 实现高度过渡,可在 `TreeNode` 内以命令式 `ref` 忠实移植,或改用 Vue `<Transition>` + JS 钩子;两者皆可,step2 决定。
