# 太阳光源设计

> 太阳负责整个场景的"亮"——既是**直接光源**(4 盏 Light)又是**视觉光晕主体**(辉光后期效果)。
>
> 两条线本质不同:**Light** 是 Three.js 的光照计算节点(影响材质着色),**辉光** 是图像后处理(影响最终上屏的 2D 像素)。本文档把这两条线分开讲。

代码位置:`src/three/sun.js` 与 `src/three/postProcess.js`。

---

## 1. 太阳光的设计

太阳侧挂载 4 盏光源,合成一个 `lightGroup` 加到 `sunRoot` 上(详细分层见 sun 设计文档,这里只关心"为什么需要这 4 盏")。

> **设计动机**:太阳系尺度跨度极大——水星距太阳 15 单位,海王星 1166 单位(差 ~78 倍)。Three.js 的 PBR 材质受光衰减影响,**单一 PointLight 无法同时照亮内行星和外行星**(强度调到能照亮海王星 → 水星过曝;调到水星合适 → 外行星完全黑)。
>
> 解决方案:把"照明任务"拆成**主光 + 3 盏专为外行星服务的补光**,后三者通过 Three.js Layer 系统**只对外行星生效**,互不干扰。

### 1.1 主光源 `principalLight`

|   类型   |                    `THREE.PointLight`                     |
|:--------:|:---------------------------------------------------------:|
|   颜色   |              `0xFFF0C9`(暖白,接近太阳表面色)              |
|   强度   |                          `25000`                          |
|   衰减   |  `distance: 0`(无穷距离),`decay: 2`(物理正确的平方反比)   |
|   投影   |         ✅ `castShadow: true`,2048×2048 阴影贴图          |
| 阴影相机 |         `near: 0.5`,`far: 1200`(覆盖到海王星轨道)         |
| 阴影微调 | `bias: -0.00002`,`normalBias: 0.02`,`radius: 2`(柔和边缘) |
|   位置   |              原点 (0, 0, 0) —— 跟随 sunRoot               |
|   图层   |          默认(layer 0,照亮所有未指定图层的物体)           |

**作用**:照亮**内行星(水星 / 金星 / 地球 / 火星)**。`decay: 2` 让光强按 `1/r²` 衰减——这是物理正确的,但同时也意味着外行星收到的光强已极弱(火星距离太阳 59,海王星 1166,后者收到的光只有前者的 ~1/385)。

**为什么 `decay: 2` 不调成 0/1?** 因为内行星依赖这个衰减来产生**自然的"近日点亮、远日点暗"**视觉效果(火星比水星暗一截)。如果调成 0,内行星亮度差异会被抹平,失去真实感。外行星亮度问题留给"补光体系"解决,不动主光。

### 1.2 远距离补光 `fillLight`

|   类型   |            `THREE.PointLight`             |
|:--------:|:-----------------------------------------:|
|   颜色   |            `0xFFF0C9`(同主光)             |
|   强度   |                    `6`                    |
|   衰减   | `distance: 0`,**`decay: 0`**(关键!不衰减) |
|   投影   |          ❌ `castShadow: false`           |
|   位置   |            原点(跟随 sunRoot)             |
| **图层** |  **`layers.outerPlanets`**(只照亮外行星)  |

**作用**:为**外行星(木 / 土 / 天 / 海)**的**向阳面**提供照明。

**为什么 `decay: 0`?**——这是这盏光的灵魂。`decay: 0` 表示光强**不随距离衰减**,无论距离 200 还是 1200,外行星收到同样亮度。这是物理上"作弊",但视觉上必要:实拍的太阳系图片里,外行星向阳面就是清晰可见,而不是按 `1/r²` 算出来的"几乎全黑"。

**为什么不投影?** 外行星离太阳太远,补光本来就是"作弊"出来的均匀照明,**没有合理的投影方向**;同时阴影计算开销巨大,不必要。

**Layer 隔离**:`layers.set(layers.outerPlanets)` 让这盏光**只对** outerPlanets 图层的物体生效。内行星不在该图层,完全不受这盏光影响——避免了"内行星过曝"。

### 1.3 阴影色调光 `shadowToneLight`

|   类型   |               `THREE.HemisphereLight`               |
|:--------:|:---------------------------------------------------:|
|  天空色  |                 `0x223344`(冷蓝调)                  |
|  地面色  |                  `0x000000`(纯黑)                   |
|   强度   |            `0.35`(建议范围 [0.12, 0.35])            |
|   位置   | 原点(HemisphereLight 位置不影响照明,放原点保持一致) |
| **图层** |              **`layers.outerPlanets`**              |

**作用**:让外行星的**背光面**不要纯黑,而是带一点冷色调,模拟"星际背景的微弱散射"。

**为什么用 `HemisphereLight`?**——这是 Three.js 里专门做"天空+地面双向环境光"的光源。对每个被照点,它根据法线朝向在 skyColor 和 groundColor 之间插值。在我们这里,`groundColor` 取黑色等于"半球光退化成只从上方来",刚好模拟"宇宙背景从行星轨道上方均匀洒下一点冷光"的视觉。

**为什么外行星才需要?**——内行星已经被强主光照亮,任何弱环境光都会被淹没,没意义。外行星只靠补光照亮一面,背光面如果纯黑会失去立体感,这盏光就是用来在背光面填一点冷色,让球体仍然能"看出是个球"。

### 1.4 黑位提升光 `blackLiftLight`

|   类型   |     `THREE.AmbientLight`      |
|:--------:|:-----------------------------:|
|   颜色   |    `0x0B1520`(极深的冷蓝)     |
|   强度   | `0.06`(建议范围 [0.01, 0.06]) |
|   位置   | 原点(AmbientLight 位置无意义) |
| **图层** |   **`layers.outerPlanets`**   |

**作用**:给整个外行星表面加一个**极微弱的全局底色**,**消除"完全 0 黑"的像素**。

**名字的来源**:`blackLift` 是电影调色术语 **"lift the blacks"** —— 把画面最低亮度从纯黑稍微抬一点点,让画面阴影部分仍然有细节(土星环的暗面、木星条纹的阴影),不会成片纯黑。

**为什么强度这么低(0.06)?**——它的目的不是"照亮",而是"防止黑成块"。0.06 这个量级在视觉上几乎察觉不到亮度变化,但在很暗的像素上,它能把 RGB 从 (0,0,0) 抬到 (3, 6, 9) 一类的值,在贴图压缩 / 后期 tone mapping 链路里就保住了暗部细节。

**和阴影色调光的区别**:

|          |  shadowToneLight   |     blackLiftLight     |
|:--------:|:------------------:|:----------------------:|
| 作用方向 | 半球(天空 vs 地面) |       全方向均匀       |
| 主要受益 |   背光面的立体感   | 暗部贴图细节不糊成黑色 |
|   类比   | "微弱的背景反射光" |   "感光片的本底噪声"   |

### 1.5 4 盏光的协同(总览图)

```
内行星照明                外行星照明
───────────                ───────────
principalLight             principalLight (但因 decay=2 已极弱)
                           +
                           fillLight       (decay=0 强行均匀照亮)
                           +
                           shadowToneLight (背光面冷色微光)
                           +
                           blackLiftLight  (全局底色 / 防黑)

(无补光)                   (3 盏补光叠加)
```

> **两端对接**:fillLight / shadowToneLight / blackLiftLight 的 **`layers.set(layers.outerPlanets)`** 是**发送端**(只对该 layer 的物体生效);行星侧由 `markOuterPlanetsLayer()`(`planet/index.js`)在初始化末尾把外行星 axis 子树 enable 同一 layer,作为**接收端**。两端必须都到位才能闭环——少了任何一端,要么补光打不到外行星,要么外行星不被补光识别。`engine.js` 里把 `markAsBloomObject(sunAxis)` 和 `markOuterPlanetsLayer()` 并排放在初始化末尾,正是「两条接收端配置」的对称体现。

## 2. 后期处理管线(辉光)

代码位置:`src/three/postProcess.js`。

> 辉光是**图像后处理**,不是 Light——它直接在最终 2D 帧上做模糊和叠加,让"足够亮的像素"向周围扩散光斑,模拟相机/眼睛面对强光的眩光感。
>
> 太阳的发光来自**材质的 emissive 自发光**(在 `setEmissive` 函数里给所有支持的 material 设 `emissive: 0xFFF2D6, emissiveIntensity: 3.5`),自发光让太阳本身在屏幕上很亮——但若没有辉光后处理,只是"中心亮边缘暗"的圆盘,缺少"刺眼感"。辉光把这个亮区扩散成柔和光晕。

### 2.1 为什么需要"选择性辉光"

`UnrealBloomPass` 的默认行为是:**所有**亮度超过阈值的像素都泛光。但场景里:

- 太阳(emissive 自发光,非常亮) → 应该泛光 ✓
- 行星表面的高光、白色贴图局部 → **不应该**泛光 ✗

所以必须实现 **selective bloom**——告诉 bloom pass「只对太阳子树作用」。

### 2.2 双 Composer + 临时变黑材质

工程采用 **两个 EffectComposer + Layer 区分** 的方案:

```
                  ┌── ① 把"非太阳"的所有 Mesh 临时换成黑色材质(darkMaterial)
                  │
bloomComposer ────┤   ② RenderPass 渲染这个"只剩太阳还亮"的场景
(辉光 composer)   │
                  │   ③ UnrealBloomPass 只在亮像素(=太阳)上泛光
                  │
                  └── ④ 输出到离屏纹理(renderTarget2.texture)
                       —— 这张纹理只有太阳的光晕,其他全黑

                  ┌── ⑤ 恢复所有 Mesh 的原材质
                  │
shaderComposer ───┤   ⑥ RenderPass 正常渲染整个场景(太阳+行星+天空球)
(合成 composer)   │
                  │   ⑦ ShaderPass:base + bloom(加法叠加,黑+任色=任色)
                  │
                  └── ⑧ 输出到屏幕
```

每一帧的 4 步(在 `renderBloomFrame()` 函数里):

```js
scene.traverse(darkenNonBloomed)   // 1. 非太阳变黑
bloomComposer.render()              // 2. 渲染纯太阳辉光纹理
scene.traverse(restoreMaterial)     // 3. 恢复材质
shaderComposer.render()             // 4. 正常渲染 + 加法叠加 → 上屏
```

> 顺序不能错——若步骤 3 错位到 4 之后,屏幕上看到的就是「整个场景全黑+一个会发光的太阳」。

### 2.3 太阳如何被识别为"辉光对象"

通过 **Three.js Layer 系统**:

```js
// engine.js 初始化阶段:
markAsBloomObject(sunAxis)
```

`markAsBloomObject` 内部:

```js
function markAsBloomObject(object3D) {
    object3D.traverse(obj => {
        obj.layers.enable(layers.bloom)      // bloom = 图层 1
    })
}
```

这会让 sunAxis 及其所有后代(sunRoot / sunModel / 4 盏光源)都**额外启用** bloom 图层(layer 1)。注意是 `enable` 不是 `set`——保留原有 layer 0,**额外**加上 layer 1。

`darkenNonBloomed` 判断时:

```js
const bloomLayer = new THREE.Layers()
bloomLayer.set(layers.bloom)           // 这个 Layers 对象只关心 bloom 层

function darkenNonBloomed(obj) {
    if (obj.isMesh && !bloomLayer.test(obj.layers)) {
        // 不在 bloom 层 → 变黑
    }
}
```

行星、天空球都没标记过 bloom 层,所以会被变黑。太阳标记过,跳过变黑。

### 2.4 辉光参数

```js
const config = {
    bloomPass: {
        resolution: new THREE.Vector2(window.innerWidth, window.innerHeight),
        strength: 2.2,    // 辉光强度
        radius: 0.55,     // 辉光半径(扩散范围)
        threshold: 0.88,  // 亮度阈值,只有 >0.88 的像素才泛光
    }
}
```

`threshold: 0.88` 是关键——足够高,排除掉行星表面的高光像素;但又比太阳的 emissive 亮度低,让太阳能稳定泛光。

### 2.5 生命周期对接

|                  时机                  |                                      动作                                      |
|:--------------------------------------:|:------------------------------------------------------------------------------:|
|          `initEngine` 初始化           |                       `initComposers()` 搭建双 composer                        |
| `initEngine` 初始化(在 `initSun` 之后) |               `markAsBloomObject(sunAxis)` 给太阳子树打 bloom 层               |
|                  每帧                  |              `renderBloomFrame()` 替代普通的 `renderer.render()`               |
|              窗口 resize               |         `resizeBloom(width, height)` 同步两个 composer 的渲染目标尺寸          |
|               `dispose`                | `disposeBloom()`(在 `renderer.dispose()` 之前)释放两个 composer + darkMaterial |

> **依赖陷阱**:`markAsBloomObject(sunAxis)` 必须在 `initSun()` 完成之后调用。原因是太阳的 Mesh 是异步从 GLTF 加载到 sunAxis 子树的——加载前 traverse 不到任何 Mesh,标记会落空。

## 3. 小结

|    主题    |         角色         |        数量         |                关键决策                 |
|:----------:|:--------------------:|:-------------------:|:---------------------------------------:|
|   主光源   |    内行星照明主力    |   1 (PointLight)    | `decay: 2` 物理衰减,`castShadow: true`  |
| 远距离补光 |   外行星向阳面照明   |   1 (PointLight)    | `decay: 0` 不衰减,层隔离到 outerPlanets |
| 阴影色调光 | 外行星背光面冷色微光 | 1 (HemisphereLight) |              半球光,层隔离              |
| 黑位提升光 |   全局防"纯黑"底色   |  1 (AmbientLight)   |            极弱(0.06),层隔离            |
|  辉光后期  |     太阳视觉光晕     |   post-processing   |   双 composer + Layer + darkMaterial    |

设计的核心思想:

1. **照明分级**:主光走物理衰减照内行星,3 盏图层隔离的补光照外行星——避免"调一边亮另一边就过曝"
2. **辉光与照明解耦**:辉光是图像后处理,只影响 2D 像素;不参与 Light 系统的着色计算
3. **Layer 系统是这两条线的桥**:`outerPlanets` Layer 把光源限定到外行星,`bloom` Layer 把辉光限定到太阳——同一套机制,两种用途
