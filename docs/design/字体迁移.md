# 字体迁移

> 把原项目 `universeBlog` 中的 `Source Han Serif CN` 字体迁移到本 Vite + Vue 3 项目中。
> 本文档先做使用情况审计,再给出迁移步骤,最后列出验收方式。

---

## 1. 字体使用情况审计

### 1.1 原项目目录结构

```
universeBlog/
├── assets/
│   ├── fonts/                                  ← 字体文件
│   │   ├── SourceHanSerifCN-ExtraLight.otf     (200)
│   │   ├── SourceHanSerifCN-Light.otf          (300)
│   │   ├── SourceHanSerifCN-Regular.otf        (400)
│   │   ├── SourceHanSerifCN-Medium.otf         (500)
│   │   ├── SourceHanSerifCN-SemiBold.otf       (600)
│   │   ├── SourceHanSerifCN-Bold.otf           (700)
│   │   └── SourceHanSerifCN-Heavy.otf          (900)
│   └── css/
│       └── font.css                            ← 7 个 @font-face 声明
└── src/
    └── index.js                                ← 在第 3 行 import '../assets/css/font.css'
```

`font.css` 把 7 个 OTF 文件分别声明给 7 个权重,但**声明 ≠ 使用**——下面看实际引用。

### 1.2 实际引用情况(grep 结果整理)

对 `universeBlog/assets/css/` 与 `src/` 全量 `grep` `font-weight` 与 `font-family: "Source Han Serif CN"`:

| 文件 | font-family | font-weight | 对应 OTF |
| --- | --- | --- | --- |
| `panel/shortContentWrap.css:9-12` | Source Han Serif CN | **900** | Heavy |
| `panel/shortContentWrap.css:34-37` | Source Han Serif CN | **400** | Regular |
| `panel/longContentWrap.css:35-38` | Source Han Serif CN | **700** | Bold |
| `label/contentLayer.css:20-23` | Source Han Serif CN | **900** | Heavy |
| `label/contentLayer.css:44-47` | Source Han Serif CN | **400** | Regular |
| `common/bottomButton.css:25-26` | **PingFang SC**(系统字体) | 400 | —(系统字体,不需要迁移) |

> `PingFang SC` 是 macOS 系统字体,不需要打包;Windows 上会自动 fallback 到 `serif`,这是原项目就有的行为,本次迁移不动它。

### 1.3 修正用户初始假设

用户在需求里列出需要迁移的 4 个权重是 **Regular / Medium / Bold / Heavy**,但全量审计后发现:

| 权重 | OTF | 用户假设是否使用 | 实际是否使用 | 结论 |
| --- | --- | --- | --- | --- |
| 400 | Regular | ✓ | ✓ | 必须迁移 |
| 500 | **Medium** | ✓ | **✗(未使用)** | **可不迁移** |
| 700 | Bold | ✓ | ✓ | 必须迁移 |
| 900 | Heavy | ✓ | ✓ | 必须迁移 |

`Medium` (500) 在 `font.css` 中有 `@font-face` 声明,但**没有任何业务 CSS 用 `font-weight: 500`**,因此实际渲染从未触发它。

### 1.4 迁移文件清单建议

提供两种取法,自选:

| 方案 | 字体文件数 | 说明 |
| --- | --- | --- |
| **A(精简,推荐)** | **3 个**(Regular / Bold / Heavy) | 只搬实际用到的;包体积约 38 MB → 减到约 39 MB(实际是 ~38.4 MB) |
| B(用户原列表) | 4 个(Regular / Medium / Bold / Heavy) | 多带一份 Medium 备用,日后想用 500 字重不需要再补字体文件 |

每个 OTF 约 12 ~ 13 MB,**Medium 一个文件大约 12.3 MB**;首屏不会加载它(`font-display: swap` + 没有字符触发),所以方案 B 不影响运行时性能,只影响产物体积。**默认按方案 A 写**,下文步骤里的所有列表都按方案 A;若选 B,在每个"复制"步骤里把 Medium 同步带上即可。

## 2. 目标结构

把字体放进 `src/assets/`,与现有 `index.css`、`reset.css` 同级,让 Vite 接管打包(自动哈希、自动 cache-busting、URL 自动重写)。

```
SolarNotesFrontend/
└── src/
    └── assets/
        ├── fonts/                                  ← 新增
        │   ├── SourceHanSerifCN-Regular.otf
        │   ├── SourceHanSerifCN-Bold.otf
        │   └── SourceHanSerifCN-Heavy.otf
        ├── font.css                                ← 新增
        ├── index.css                               (已存在)
        └── reset.css                               (已存在)
```

> **为什么不用 `public/`**:`public/` 适合**不被 Vite 处理**的静态资源(URL 写绝对路径,例如 `/fonts/xxx.otf`)。字体放 `src/assets/` 让 Vite 走打包流水线,生成内容哈希文件名,浏览器缓存策略友好,且不需要在 CSS 里写绝对路径。

## 3. 迁移步骤

### 步骤 1:新建字体目录,拷贝 OTF 文件

```bash
mkdir -p /Users/yanglei/Desktop/SolarNotesFrontend/src/assets/fonts

cp /Users/yanglei/Desktop/universeBlog/assets/fonts/SourceHanSerifCN-Regular.otf \
   /Users/yanglei/Desktop/universeBlog/assets/fonts/SourceHanSerifCN-Bold.otf \
   /Users/yanglei/Desktop/universeBlog/assets/fonts/SourceHanSerifCN-Heavy.otf \
   /Users/yanglei/Desktop/SolarNotesFrontend/src/assets/fonts/
```

> 选方案 B 的话,在 `cp` 命令里再加一行 `SourceHanSerifCN-Medium.otf`。

### 步骤 2:在 `src/assets/` 下新建 `font.css`

新建文件 `src/assets/font.css`,写入下面内容(注意 `url(...)` 是相对于 `font.css` 自身的路径,因此是 `./fonts/...`,而不是原项目的 `../fonts/...`):

```css
@font-face {
    font-family: "Source Han Serif CN";
    src: url("./fonts/SourceHanSerifCN-Regular.otf") format("opentype");
    font-weight: 400;
    font-style: normal;
    font-display: swap;
}

@font-face {
    font-family: "Source Han Serif CN";
    src: url("./fonts/SourceHanSerifCN-Bold.otf") format("opentype");
    font-weight: 700;
    font-style: normal;
    font-display: swap;
}

@font-face {
    font-family: "Source Han Serif CN";
    src: url("./fonts/SourceHanSerifCN-Heavy.otf") format("opentype");
    font-weight: 900;
    font-style: normal;
    font-display: swap;
}
```

> 选方案 B 的话,把原 `font.css` 的 Medium 那段也搬过来,`url` 改为 `./fonts/SourceHanSerifCN-Medium.otf`。

### 步骤 3:在 `App.vue` 中引入 `font.css`

打开 `src/App.vue`,在已有的样式 import 列表中加入 `font.css`:

```vue
<script setup>
// 现有
import '@/assets/reset.css'
import '@/assets/index.css'
// 新增 — 放在 reset 之后、index 之前(语义:先重置浏览器默认,再声明字体,最后写业务样式)
import '@/assets/font.css'
</script>
```

修改后建议的顺序:

```vue
import '@/assets/reset.css'
import '@/assets/font.css'
import '@/assets/index.css'
```

> 三者的相对顺序对最终渲染没有功能性影响(`@font-face` 不参与级联),但语义上"重置 → 字体声明 → 业务样式"读起来最清楚。

### 步骤 4(可选,但强烈建议):在 `index.css` 设置全局默认字体

`index.css` 现在的 `:root` 里只有 `--border` 一个变量,没有为页面设默认字体。建议加一行,让所有未显式指定 font-family 的元素都走 Source Han Serif CN:

```css
:root {
    --border: #20c6d8;
}

body {
    font-family: "Source Han Serif CN", serif;
    /* 默认字重,与原项目一致 */
    font-weight: 400;
}
```

如果不设全局默认,每个用到字体的 Vue 组件都得在自己的 scoped CSS 里写一遍 `font-family: "Source Han Serif CN", serif`(原项目就是这种写法),也可以,只是多写一些样板。

### 步骤 5:验证 Vite 配置

`vite.config.js` 默认就处理 `.otf` 文件(归类为 asset),不需要额外配置。如果出现"Vite 解析不到 .otf"的报错,才需要在 `vite.config.js` 里添加:

```js
export default defineConfig({
    // ...
    assetsInclude: ['**/*.otf'],
})
```

> 一般跑起来不需要,作为兜底方案放在这里。

## 4. 验收清单

启动 `npm run dev` 后在浏览器中:

- [ ] **字体加载成功**:DevTools → Network 面板里能看到 3 个(或方案 B 的 4 个)`SourceHanSerifCN-*.otf` 文件被下载,状态码 200,URL 路径包含 Vite 自动生成的哈希(类似 `/assets/SourceHanSerifCN-Regular-abc12345.otf`)。
- [ ] **没有 FOIT/FOUT 尖叫**:`font-display: swap` 让浏览器先用 fallback 渲染,字体到位后再切换;短暂闪一下属于正常,但不应出现长时间空白。
- [ ] **DevTools → Elements → Computed → font-family** 显示 `"Source Han Serif CN"`(不是 fallback 的 `serif`)。
- [ ] **粗体生效**:任意带 `font-weight: 700` 的元素(label 标题、panel 长内容里的链接)显示为加粗;`font-weight: 900` 的元素更粗;两者视觉可区分。
- [ ] **Console 无 404**:不应该出现 `SourceHanSerifCN-*.otf 404 Not Found`。
- [ ] **生产构建**:`npm run build` 成功,`dist/assets/` 下能看到带哈希的字体文件;`dist/index.html` 或注入的 CSS 中字体 URL 指向打包后的路径。

## 5. 备注 / 后续

- **包体积**:3 个 OTF 合计约 38.4 MB(Regular 12.7 + Bold 13.1 + Heavy 12.6),会全部进 `dist/assets/` 但**只有用到的字符在浏览器解码时才会加载**——只是网络层下载会全量。如果未来需要进一步优化,可以考虑:
    - 用 [`subset-font`](https://www.npmjs.com/package/subset-font) 或 [`fonttools`](https://github.com/fonttools/fonttools) 做子集化(只保留用到的字符,中文站点常见做法,体积可压到 1~3 MB);
    - 改用 WOFF2 格式(同等字符集压缩率比 OTF 高 30~50%);
    - 分页/按需加载(Vue 路由切换时只引入对应页面用到的字重)。
- **原项目还有 `bottomButton.css` 使用 `PingFang SC`**——这是 macOS 系统字体,**不需要迁移文件**,但要注意若新项目最终也用到这个按钮,需要和 PM/UI 确认 Windows 用户的 fallback 是否可接受(原项目让其降级到 `serif`)。
- **若以后想加回 Medium**:把 `SourceHanSerifCN-Medium.otf` 拷到 `src/assets/fonts/`,在 `font.css` 末尾追加一段 `@font-face`(weight: 500),完工。无需改 import。
