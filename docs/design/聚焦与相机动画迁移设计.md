# 点击聚焦 + 相机动画 迁移设计

> 对应 `迁移规划.md` 的**阶段 9**。
> 与 `投射检测与悬停状态机迁移设计.md`(阶段 8)同一思路:把原项目 `interaction/focus.js`、`ui/panel.js`、以及 `index.js` 里点击聚焦的事件,在 Vue + Pinia 下重新组织为 **store(数据)+ tickFocus(算法)+ 组件(IO)** 三件事。
> 本文档详细到可编码粒度。迁移时**顺手修掉原版相机"右方向"在俯视黄道面时退化的 bug**;另外 `panelRatio` 名实不符的命名**不是 bug**——0.5 是正确的调参值、予以保留(见 §2.4 / §6.3),迁移时只改名 + 重写注释消除误导。整体按"先实现,再优化"落地。

## 2. 现状诊断:原 `focus.js` 的问题

### 2.1 共享状态是裸的可变模块单例 + 时间是副作用

`focus.js` 顶部 `const state = { focused, targetObject, elapsedTime, duration, isAnimating, mode }`,且 `updateFocus(dtSeconds)` 内部累加 `elapsedTime`。与阶段 8 同样的问题:无访问控制、无响应式、时间作为内部累加而非输入。

### 2.2 派生量被存为状态

`mode`('' / 'focus' / 'clear')+ `focused` + `isAnimating` 三者其实可由"当前相位"一个枚举推导。原版用三个标量互相约束,改任一处都要顾及其它两个。

### 2.3 ⚠️ bug A:相机"右方向"用世界上方向叉乘,俯视黄道面时退化

```js
// 原 focus.js focusOn():
cameraLeftDirection.copy(worldUp).cross(cameraForwardDirection).multiplyScalar(-1).normalize()
//                        (0,1,0)
```

- **退化**:当相机视线 `cameraForward` 接近平行于世界上方向 `(0,1,0)`(即俯视/仰视黄道面)时,叉乘结果趋近**零向量**,`normalize()` 放大成乱方向(极端为 NaN)→ `controls.target` 错位 → 天体被甩到一边且被裁掉。
- **方向也不对**:`worldUp × forward` 是**世界水平**方向;相机俯视时它投影到屏幕不是纯水平 → 天体斜向漂(实测"右下方")。

修复见 §6.2(改用相机自身右方向)。

### 2.4 命名提示:`panelRatio` 名实不符(**不是 bug,值 0.5 予以保留**)

```js
const panelRatio = 0.5   // 注释写"panel在屏幕横向的占比"
```

原项目 panel 实际是 `width: 60%`(`universeBlog/assets/css/panel/panelWrap.css`),和 0.5 对不上,所以**注释/命名是误导的**:这个常量根本不是 panel 宽度,而是"把天体往右推多少"的相机调参旋钮。

但它**不是 bug**,和 §2.3 的相机右方向退化(那个会真把天体甩出屏幕)性质完全不同:0.5 跑出来的取景完全正常(天体落屏 77.5% 处,稳稳在 panel 右侧可见条带内),正是原项目实际运行的观感;几何上 0.5 与"对齐 panel 宽度的 0.6"关于条带中心 80% 对称、各偏 2.5%,改 0.6 并不更对(推导见 §6.3)。

**结论:值保持 0.5**(强行改 0.6 反而是回退);迁移时只做"改名 + 重写注释"消除误导——见 §5.5 改名为 `PANEL_RATIO` 并注明它是调参旋钮、非 panel 宽度。

### 2.5 每帧重算终点是"为天体会动预留",但本项目聚焦时冻结

原 `updateFocus` 每帧 `getWorldPosition` + 重算 `toCameraPosition`。本项目已确定**聚焦时冻结全部公转**(见 §9),天体世界坐标静止,终点只需在建立动画时算一次(见 §5.5 / §6.1)。

## 3. 重构原则(沿用阶段 8)

| 原则 | 含义 |
| --- | --- |
| 单一职责 | 几何/相机数学、状态数据、状态机推进、事件 IO 分离 |
| 共享状态只走 Pinia | 不再有裸 `export const state`;UI 要消费的(phase / focusedEntity / panel 文案与显隐)放 store |
| 派生量用 computed,不存 | `shouldShowPanel` / `shouldFreezeRevolution` / `inFocusMode` / `panelText` 都是 getter |
| 时间是输入 | `tickFocus(nowMs, ...)`,`nowMs` 由 engine 动画循环喂入(与 tickHover 同源) |
| THREE.Vector3 不进 store | 相机数学的 scratch 向量留在 `three/interaction/focus.js` 模块级(同 projection.js 的缓存) |
| 副作用在边界 | 组件 DOM 事件只做单向写入(requestFocus / requestClear);相机/controls 操作集中在 tickFocus |
| 依赖方向向下 | `interaction/focus.js` 依赖 `lib/projection.js`(getWorldRadius)、`base/raycaster.js`,不反向 |

### 5.2 `src/lib/easing.js`(新)

> 缓动曲线。纯函数 `number → number`(进度 [0,1] → 缓动后进度 [0,1]),不依赖 Three.js、不依赖聚焦状态;从原 `focus.js` 抽出,与 `enum.js` 同属框架无关的 `src/lib/`,供聚焦动画(§5.5 `tickFocus`)及后续任意动画复用。

```js
/**
 * 缓动函数:先慢 → 快 → 慢(easeInOut quad)
 * @param {Number} t 进度 [0,1]
 * @return {Number} 缓动后进度 [0,1]
 * */
export function easeInOut(t) {
    if (t < 0.5) {
        return 2 * t * t
    }
    return 1 - Math.pow(-2 * t + 2, 2) / 2
}
```

### 5.3 `src/three/lib/projection.js`(修改:抽出 `getWorldRadius`)

把 `calcProjection` 里"本地半径 × 世界缩放"这段(现 86-89 行)抽成独立函数并导出。这样聚焦的 fit-distance 用的是**和投影圆完全同一个世界半径**,不重复魔法逻辑。

```js
/**
 * 计算物体包围球在世界坐标系下的半径(本地半径 × 世界缩放的最大分量)
 * @param {import('three').Object3D} object anchor 物体(sunAxis / planet.root),userData 需含 hoverRadius
 * @return {Number} 世界坐标系下的半径;未配置 hoverRadius 时为 0
 * */
function getWorldRadius(object) {
    const {radiusLocal} = getLocalBoundingSphere(object)
    object.getWorldScale(worldScale)
    const maxScale = Math.max(worldScale.x, worldScale.y, worldScale.z) || 1
    return radiusLocal * maxScale
}
```

`calcProjection` 内对应三行改为复用:

```diff
-    // 计算包围球在世界坐标系下的半径
-    object.getWorldScale(worldScale)
-    const maxScale = Math.max(worldScale.x, worldScale.y, worldScale.z) || 1
-    const radiusWorld = radiusLocal * maxScale
+    // 计算包围球在世界坐标系下的半径(与聚焦 fit-distance 共用同一函数)
+    const radiusWorld = getWorldRadius(object)
```

> 注意:`getWorldRadius` 复用模块级 scratch `worldScale`;`calcProjection` 重构后不再直接用 `worldScale`,无并发问题(单线程)。`getLocalBoundingSphere` 维持模块内私有不导出。
> 导出追加 `getWorldRadius`。

### 5.4 `src/stores/focus.js`(新)

> 聚焦状态机的"数据"。组件写入(`requestFocus`/`requestClear`),`tickFocus` 推进相位;`SolarPanel` 读取 `shouldShowPanel` / `panelText` / `durationMs`。

```js
import {defineStore} from "pinia";
import {computed, ref, shallowRef} from "vue";
import {FocusPhase} from "@/lib/enum.js";

/**
 * @typedef {Object} FocusAnimation 聚焦/退出动画的运行时配置与状态(非响应式,仅 tickFocus 读写)
 * @property {Number} durationMs  配置项: 动画总时长(毫秒).⚠️ 必须与 SolarPanel 的 CSS 过渡时长一致,见 §5.8
 * @property {Number} startedAt   运行时: 当前这段动画的起始时间戳(performance.now() 基准),0 表示未开始
 * @property {Boolean} needsInit 运行时: 是否还有"一次性建立(记录起点/算终点/禁用 controls)"待 tickFocus 执行
 * @property {Boolean} shouldCaptureHome  运行时: 本次进入 focusing 是否需要记录 home(仅"从 idle 进入"时为 true)
 * */

/**
 * @typedef {Object} PanelText 显示在 panel 上的文本,从 focusedEntity 的 userData 读取
 * @property {String} title
 * @property {String} intro
 * */

export const useFocusStore = defineStore('focus', () => {
    // PART1. 当前状态
    /** @type {import('vue').Ref<String>} 聚焦状态机当前状态,取值见 FocusPhase */
    const phase = ref(FocusPhase.idle)

    // PART2. 当前聚焦的天体
    /**
     * @type {import('vue').ShallowRef<import('three').Object3D|null>} 当前聚焦的锚点天体(sunAxis / planet.root)
     *      - idle: null
     *      - focusing / focused: 被聚焦的锚点
     *      - clearing: 仍保留上一个锚点,直到 finishClear 才置 null
     *        (这样 panel 滑出动画期间 panelText 不会提前清空,无需像 label 那样做快照)
     *      Tips: 用 shallowRef,理由同 hover store 的 activeEntity
     * */
    const focusedEntity = shallowRef(null)

    // PART3. 动画运行时(非响应式)
    /** @type {FocusAnimation} */
    const animation = {
        durationMs: 600,
        startedAt: 0,
        needsInit: false,
        shouldCaptureHome: false,
    }

    // getters
    /** @type {import('vue').ComputedRef<Boolean>} 是否应显示 panel(滑入/停留时显示;清除时隐藏以触发滑出) */
    const shouldShowPanel = computed(() => {
        return phase.value === FocusPhase.focusing || phase.value === FocusPhase.focused
    })

    /** @type {import('vue').ComputedRef<Boolean>} 聚焦期间是否应冻结公转(非 idle 即冻结) */
    const shouldFreezeRevolution = computed(() => {
        return phase.value !== FocusPhase.idle
    })

    /** @type {import('vue').ComputedRef<Boolean>} 当前是否处于聚焦模式(focusing / focused / clearing) */
    const inFocusMode = computed(() => {
        return phase.value !== FocusPhase.idle
    })

    /** @type {import('vue').ComputedRef<PanelText|null>} panel 应显示的文案,focusedEntity 为 null 时返回 null */
    const panelText = computed(() => {
        const entity = focusedEntity.value
        if (entity === null) {
            return null
        }
        return {
            title: entity.userData.title,
            intro: entity.userData.intro,
        }
    })

    // actions: 外部触发(组件调用)
    /**
     * 请求聚焦到给定锚点天体.仅记录意图,真正的相机建立与动画推进由 tickFocus 完成
     * @param {import('three').Object3D|null} anchor 要聚焦的锚点天体(sunAxis / planet.root)
     * */
    function requestFocus(anchor) {
        if (anchor === null || anchor === undefined) {
            return
        }
        // 仅"从 idle 进入"时记录 home —— re-focus(focusing/focused/clearing → focusing)保留最初的 home
        // 这比原版 mode !== 'focus' 更严谨:修掉"clearing 途中再点天体把 home 记成半路位置"的边界(见 §8.1)
        animation.shouldCaptureHome = (phase.value === FocusPhase.idle)
        phase.value = FocusPhase.focusing
        focusedEntity.value = anchor
        animation.needsInit = true
    }

    /**
     * 请求退出聚焦(相机回到聚焦前的位置).仅记录意图,动画由 tickFocus 执行
     * */
    function requestClear() {
        if (phase.value === FocusPhase.idle) {
            return
        }
        phase.value = FocusPhase.clearing
        animation.needsInit = true
    }

    // actions: tickFocus 推进动画
    /**
     * 标记一段动画正式开始(tickFocus 完成一次性建立后调用)
     * @param {Number} nowMs 动画起始时间戳
     * */
    function markAnimationStart(nowMs) {
        animation.startedAt = nowMs
        animation.needsInit = false
    }

    /** 聚焦动画结束,落定为 focused */
    function settleFocused() {
        phase.value = FocusPhase.focused
    }

    /** 退出动画结束,回到 idle 并清空聚焦天体 */
    function finishClear() {
        phase.value = FocusPhase.idle
        focusedEntity.value = null
    }

    return {
        // state
        phase, focusedEntity, animation,
        // computed
        shouldShowPanel, shouldFreezeRevolution, inFocusMode, panelText,
        // actions: 外部触发
        requestFocus, requestClear,
        // actions: tickFocus 推进
        markAnimationStart, settleFocused, finishClear,
    }
})

/**
 * @typedef {ReturnType<typeof useFocusStore>} FocusStore 聚焦状态机的 store 实例
 * */
```

### 5.5 `src/three/interaction/focus.js`(新)

> 聚焦状态机的"算法"。**不导出 state**,导出 `tickFocus`(逐帧推进)与 `resolveFocusAnchor`(画布点击拾取并解析锚点)。相机数学的 `THREE.Vector3` scratch 留在本模块。

```js
import * as THREE from 'three'
import {FocusPhase} from "@/lib/enum.js";
import {easeInOut} from "@/lib/easing.js";
import {getWorldRadius} from "@/three/lib/projection.js";
import {pickHoveredBody} from "@/three/base/raycaster.js";
import {findAncestorByName} from "@/three/lib/findAncestorByName.js";

/* ---------- 相机数学的配置常量 ---------- */
/** @type {Number} 缩放因子:越小相机离天体越近、天体在屏上越大 */
const ZOOM_FACTOR = 0.75
/** @type {Number} panel 占屏幕横向比例(调相机的旋钮,非 1:1 等于 panel 宽度,见 §6.3).沿用原版 0.5 */
const PANEL_RATIO = 0.5
/** @type {Number} panel 与天体之间的边距比例 */
const MARGIN = 0.05
/** @type {Number} 横向偏移比例上限 */
const MAX_SHIFT_RATIO = 0.85

/* ---------- 模块级 scratch(复用避免每帧 GC,理由同 projection.js) ---------- */
/** @type {THREE.Vector3} 被聚焦天体(锚点)的世界坐标,作为相机终点与轨道中心终点的计算基准 */
const targetPosition = new THREE.Vector3()
/** @type {THREE.Vector3} 本段动画的相机起点位置(进入/退出聚焦共用),lerp 的起始向量 */
const fromCameraPosition = new THREE.Vector3()
/** @type {THREE.Vector3} 本段动画的相机终点位置,lerp 的目标向量 */
const toCameraPosition = new THREE.Vector3()
/** @type {THREE.Vector3} 本段动画起点时刻的轨道中心(即起点时的 controls.target) */
const fromControlsTarget = new THREE.Vector3()
/** @type {THREE.Vector3} 本段动画的轨道中心终点(即终点时的 controls.target) */
const toControlsTarget = new THREE.Vector3()
/** @type {THREE.Vector3} 从被聚焦天体指向相机的单位向量(dolly 轴,保留当前视角、只推近),相机沿它后退 desireDistance 到终点 */
const targetToCameraDirection = new THREE.Vector3()
/** @type {THREE.Vector3} 世界系下相机的右方向单位向量(camera.matrixWorld 第 0 列),恒为屏幕水平、俯视黄道面不退化(bug A 修法) */
const cameraRightWorld = new THREE.Vector3()
/** @type {THREE.Vector3} 相机相对被聚焦天体的偏移(dolly 轴 × desireDistance),相机终点 = 天体世界坐标 + 本偏移;决定"相机从哪儿看" */
const cameraOffset = new THREE.Vector3()
/** @type {THREE.Vector3} 轨道中心相对被聚焦天体的偏移(沿相机右方向反推 targetShift,使天体居屏幕右侧),轨道中心终点 = 天体世界坐标 + 本偏移;决定"相机看向哪儿" */
const targetOffset = new THREE.Vector3()
/** @type {THREE.Vector3} 聚焦前的相机位置(退出聚焦时回到此处) */
const homeCameraPosition = new THREE.Vector3()
/** @type {THREE.Vector3} 聚焦前的轨道中心(退出聚焦时回到此处) */
const homeControlsTarget = new THREE.Vector3()

/**
 * 拾取并解析画布点击命中的锚点天体
 * @param {import('three').Vector2} ndcCoordinate 点击位置的 NDC 坐标
 * @param {import('three').PerspectiveCamera} camera
 * @return {import('three').Object3D|null} 命中则返回锚点(sunAxis / planet.root),否则 null
 * Tips: 解析逻辑(读 anchorPointName + findAncestorByName)与 hover store 的 enterBody 重复,
 *       可选优化(先实现再优化):抽取共享 resolveAnchor(hitObject) 给二者共用,见 §12.5
 * */
function resolveFocusAnchor(ndcCoordinate, camera) {
    const hit = pickHoveredBody(ndcCoordinate, camera)
    if (hit === null) {
        return null
    }
    const anchorName = hit.userData.anchorPointName
    if (typeof anchorName !== 'string' || anchorName === '') {
        return null
    }
    return findAncestorByName(hit, anchorName)
}

/**
 * 一次性建立"进入聚焦"的动画:记录起点、(必要时)记录 home、计算终点、禁用 controls
 * @param {import('@/stores/focus.js').FocusStore} store
 * @param {import('three').PerspectiveCamera} camera
 * @param {import('three/addons/controls/OrbitControls').OrbitControls} controls
 * @param {Number} nowMs
 * */
function initFocusAnimation(store, camera, controls, nowMs) {
    const target = store.focusedEntity
    target.updateWorldMatrix(true, false)
    target.getWorldPosition(targetPosition)

    // 记录本段动画起点
    fromCameraPosition.copy(camera.position)
    fromControlsTarget.copy(controls.target)

    // 仅"从 idle 进入聚焦"时记录 home(re-focus 不覆盖,保证退出时回到最初位置)
    if (store.animation.shouldCaptureHome) {
        homeCameraPosition.copy(camera.position)
        homeControlsTarget.copy(controls.target)
    }

    // dolly 轴:从天体指向相机的方向(保留用户当前视角,只推近)
    targetToCameraDirection.copy(camera.position).sub(targetPosition).normalize()

    // 相机到天体的距离:让半径 radius 的球垂直方向充满屏幕的距离 × 缩放因子
    const radius = Math.max(getWorldRadius(target), 1e-6)
    const fovRad = THREE.MathUtils.degToRad(camera.fov)
    const fitDistance = radius / Math.tan(fovRad * 0.5)
    const desireDistance = fitDistance * ZOOM_FACTOR

    // 让天体居右(给左侧滑入的 panel 让位):相机始终看向"轨道中心"(controls.target),
    // 而轨道中心投影在屏幕正中;把它放到天体的"屏幕左侧",天体相对屏幕中心就偏到了右半边。
    // 下面两步算出"轨道中心相对天体的偏移 targetOffset":① 推多远(targetShift) ② 往哪推(屏幕左)。

    // ① 推移量 targetShift(世界单位)= 聚焦距离处的"半屏宽" × 横向占比:
    // horizontalShiftRatio:推移量占半屏宽的比例 = panel 占比 + 边距,并夹在上限内
    const horizontalShiftRatio = Math.min(PANEL_RATIO + MARGIN, MAX_SHIFT_RATIO)
    // fovX:由垂直 fov 与宽高比反推出的水平视场角(Three.js 的 camera.fov 是垂直向)
    const fovX = 2 * Math.atan(Math.tan(fovRad * 0.5) * camera.aspect)
    // desireDistance · tan(fovX/2) = 该深度(聚焦距离)处的半屏宽,再 × 占比即为推移量
    const targetShift = desireDistance * Math.tan(fovX * 0.5) * horizontalShiftRatio

    // 相机终点 = 天体世界坐标 + 沿 dolly 轴后退 desireDistance
    cameraOffset.copy(targetToCameraDirection).multiplyScalar(desireDistance)

    // ② 推移方向 = 屏幕"水平向右"在世界系下的单位向量(下一步取负号即得"屏幕左")
    camera.updateMatrixWorld()  // 读 matrixWorld 前先刷新,确保下一行拿到的是最新朝向
    // matrixWorld 第 0 列 = 相机本地 +X 轴在世界系下的方向 = 屏幕水平向右(单位向量)
    cameraRightWorld.setFromMatrixColumn(camera.matrixWorld, 0).normalize()
    // 偏移 = 方向 × 大小,取负号 → 沿"屏幕左"推 targetShift(即轨道中心相对天体的位移)
    targetOffset.copy(cameraRightWorld).multiplyScalar(-targetShift)

    // 终点(已选择"聚焦时冻结" → 天体世界坐标静止 → 终点只在此算一次,不每帧重算)
    toCameraPosition.copy(targetPosition).add(cameraOffset)
    // 轨道中心终点 = 天体世界坐标 + 偏移 → 落在天体左侧 targetShift 处;相机看向它,天体即居屏幕右
    toControlsTarget.copy(targetPosition).add(targetOffset)

    controls.enabled = false
    store.markAnimationStart(nowMs)
}

/**
 * 一次性建立"退出聚焦"的动画:从当前位置回到 home
 * @param {import('@/stores/focus.js').FocusStore} store
 * @param {import('three').PerspectiveCamera} camera
 * @param {import('three/addons/controls/OrbitControls').OrbitControls} controls
 * @param {Number} nowMs
 * */
function initClearAnimation(store, camera, controls, nowMs) {
    fromCameraPosition.copy(camera.position)
    fromControlsTarget.copy(controls.target)
    toCameraPosition.copy(homeCameraPosition)
    toControlsTarget.copy(homeControlsTarget)
    controls.enabled = false
    store.markAnimationStart(nowMs)
}

/**
 * 按进度推进相机 / 轨道中心插值
 * @param {import('@/stores/focus.js').FocusStore} store
 * @param {import('three').PerspectiveCamera} camera
 * @param {import('three/addons/controls/OrbitControls').OrbitControls} controls
 * @param {Number} nowMs
 * @return {Number} 当前进度 [0,1]
 * */
function advanceCameraLerp(store, camera, controls, nowMs) {
    const elapsed = nowMs - store.animation.startedAt
    const progress = Math.min(elapsed / store.animation.durationMs, 1)
    const k = easeInOut(progress)
    camera.position.lerpVectors(fromCameraPosition, toCameraPosition, k)
    controls.target.lerpVectors(fromControlsTarget, toControlsTarget, k)
    controls.update()
    return progress
}

/**
 * 逐帧推进聚焦状态机
 * @param {Number} nowMs 当前时间戳(毫秒,performance.now() 基准,由 engine 动画循环喂入)
 * @param {import('@/stores/focus.js').FocusStore} store
 * @param {import('three').PerspectiveCamera} camera
 * @param {import('three/addons/controls/OrbitControls').OrbitControls} controls
 * */
function tickFocus(nowMs, store, camera, controls) {
    if (store.phase === FocusPhase.focusing) {
        if (store.animation.needsInit) {
            initFocusAnimation(store, camera, controls, nowMs)
        }
        const progress = advanceCameraLerp(store, camera, controls, nowMs)
        if (progress >= 1) {
            controls.enabled = true
            store.settleFocused()
        }
        return
    }

    if (store.phase === FocusPhase.clearing) {
        if (store.animation.needsInit) {
            initClearAnimation(store, camera, controls, nowMs)
        }
        const progress = advanceCameraLerp(store, camera, controls, nowMs)
        if (progress >= 1) {
            controls.enabled = true
            store.finishClear()
        }
        return
    }

    // idle / focused:无动画推进
    //  - idle: controls 已在 finishClear 启用,用户自由 orbit
    //  - focused: controls 已在 settleFocused 启用,用户可绕聚焦天体 orbit;tickHover 被 engine gating 跳过 → 无 label
}

export {
    tickFocus,
    resolveFocusAnchor,
}
```

#### 5.5.1 为什么"建立动画"延到 tickFocus,而不在 requestFocus 里做

`requestFocus` 由组件点击事件调用,组件层**拿不到 `controls`**(controls 在 engine 内部创建、不对外暴露)。而建立动画要读 `camera.position` / `controls.target`、要禁用 `controls`、要算 `camera.matrixWorld`。把这些放进 `tickFocus`(engine 每帧喂入 camera + controls)最自然:`requestFocus` 只记录意图(`needsInit = true`),下一帧 `tickFocus` 完成建立。点击与首帧间隔约 16ms,相机未移动,起点照样准确。

## 6. 相机数学详解

### 6.1 整体流程

```
focusOn(锚点) 时(一次性建立):
  targetPos        = 锚点世界坐标
  forward          = normalize(camera.pos - targetPos)          // dolly 轴,保留当前视角
  radius           = getWorldRadius(锚点)                        // 与投影圆同源
  fitDistance      = radius / tan(fov/2)                         // 球垂直充满屏幕的距离
  desireDistance   = fitDistance * 0.75                          // ZOOM_FACTOR,留点边
  cameraOffset     = forward * desireDistance
  cameraRight      = camera.matrixWorld 第 0 列(单位化)         // 屏幕右方向【修复点】
  targetShift      = desireDistance * tan(fovX/2) * 0.55         // 见 §6.3
  targetOffset     = cameraRight * (-targetShift)                // 轨道中心往屏幕左推 → 天体居右
  toCameraPos      = targetPos + cameraOffset
  toControlsTarget = targetPos + targetOffset

每帧:lerpVectors(from, to, easeInOut(progress)) + controls.update()
```

### 6.2 修复 bug A:相机右方向

原版 `cameraLeftDirection = -(worldUp × forward)` 在俯视黄道面时退化(见 §2.3)。改用相机世界矩阵第 0 列:

```js
camera.updateMatrixWorld()
cameraRightWorld.setFromMatrixColumn(camera.matrixWorld, 0).normalize()
targetOffset.copy(cameraRightWorld).multiplyScalar(-targetShift)   // 负号 → 天体落屏幕右
```

它**恒为单位向量、恒为屏幕水平、任意视角都不退化**。`projection.js:92` 早已用同款写法采样投影半径,本项目内一致。

### 6.3 为什么 `panelRatio` 保持 0.5(几何推导)

公式把天体推到屏幕横向 `0.5 + horizontalShiftRatio / 2` 处(`targetShift` 相对的是**半屏宽**,换算到全屏宽要 ÷2):

| panelRatio | hsr = min(panelRatio+0.05, 0.85) | 天体落点(距左) |
| --- | --- | --- |
| **0.5** | 0.55 | **77.5%** |
| 0.6 | 0.65 | 82.5% |

panel 占左 60%,可见右侧条带 60%–100%、中心 80%。**0.5 → 77.5%** 正落在条带内、略偏 panel 一侧,即原项目"天体居右"的实际观感。注意 **0.5 与 0.6 关于条带中心 80% 对称**(分别落 77.5% / 82.5%,各偏 2.5%):0.6 并不比 0.5 更"正确",只是把天体推向右边缘、少了右侧余量。真要正中条带需 `panelRatio = panel宽 − margin = 0.55`,但那是日后凭眼睛微调的事;本次沿用原版 0.5。

```
        +------------------+                 +------------------+
        |  Pinia: hover    |                 |  Pinia: focus    |
        +------------------+                 +------------------+
        | phase/activeEntity|                | phase            |
        | ...               |                | focusedEntity    |
        +------------------+                 | animation        |
              ↑   ↑                          | shouldShowPanel  |
              |   |                          | shouldFreeze...  |
              |   |                          | panelText        |
              |   |                          +------------------+

              |   |               requestClear) |   |        |  panelText / durationMs)
     +--------+   +-----+        +-------------+   +----+   +-----------+
     | SolarCanvas      |        | ContentLayer|        | SolarPanel   |
     |  - pointermove…  |        | 聚焦按钮@click|        |  - :class    |
     |  - pointerdown/up|------->| requestFocus|        |  - panelText |
     |    点击聚焦/清除  |        +-------------+        +--------------+
     |  - initEngine(   |
     |     hover,focus) |
     +--------+---------+
              | (engine 动画循环每帧)

     +--------------------------------+
```

## 8. 状态机转移规则

| 当前 phase | 触发 | 目标 phase | 备注 |
| --- | --- | --- | --- |
| idle | `requestFocus(anchor)`(点击天体 / label 按钮) | focusing | 记录 home |
| focusing | 动画 `progress >= 1` | focused | 启用 controls |
| focusing | `requestFocus(其它天体)` | focusing(重建) | re-focus,**不**重记 home |
| focusing | `requestClear()`(点空白) | clearing | 从半路位置回 home |
| focused | `requestFocus(其它天体)` | focusing | re-focus,不重记 home |
| focused | `requestClear()` | clearing | |
| clearing | 动画 `progress >= 1` | idle | 启用 controls,清空 focusedEntity |
| clearing | `requestFocus(天体)` | focusing | 从半路位置去新天体,**home 仍是最初的**(§8.1) |

### 8.1 home 捕获规则(优于原版)

原版用 `if (state.mode !== 'focus')` 决定是否记录 home。若在 clearing 途中再点天体,`mode` 是 `'clear'`,会把 home 记成**半路位置**。本设计改为 **`shouldCaptureHome = (phase === idle)`** —— 只有真正从未聚焦态进入时才记录,clearing → focusing 不重记,home 始终是最初聚焦前的位置。

| 维度 | 规则 | 落点 |
| --- | --- | --- |
| 优先级 | 聚焦优先:`focusStore.inFocusMode` 为真时,engine **不调** `tickHover` | engine §5.6 |

## 12. 风险与备注

### 12.1 联调依赖:把 SolarPanel 挂进 SolarCanvas
路由结构已就绪(`App.vue` 为 `RouterView` 外壳,`/` → `/solar` → `SolarCanvas`)。聚焦要看到 panel,只差按 §5.7 把 `<SolarPanel>` 挂进 `SolarCanvas`(目前 SolarCanvas 仅 canvas + SolarLabel)。

### 12.2 `camera.matrixWorld` 的时效
建立动画时 `camera.updateMatrixWorld()` 显式刷新一次(虽然每帧渲染后通常已是最新),确保 `setFromMatrixColumn` 取到当前姿态。

### 12.3 `controls.enabled` 的开关时机
动画期间禁用(`initFocusAnimation`/`initClearAnimation` 内 `= false`),`focused`/`idle` 落定时启用(tickFocus 内 `= true`)。聚焦落定后用户可绕天体 orbit,但此时 `tickHover` 被 gating 跳过 → 不出 label。

### 12.4 点击用的 NDC
`onPointerUp` 用最近一次 `pointermove` 写入的 `hoverStore.pointer.ndcCoordinate`(与原版一致)。因 5px 阈值保证点击落点与之相差极小,够用。若日后要绝对精确,可在 `pointerup` 里用 `getNDCCoordinate(event.clientX, event.clientY, canvas, tmp)` 现算。

### 12.5 可选优化(先实现再优化):锚点解析去重
`resolveFocusAnchor` 中"读 `anchorPointName` + `findAncestorByName`"与 hover store `enterBody` 的解析重复。落地后可抽 `resolveAnchor(hitObject)` 共享(放 `three/lib/`),enterBody 与 focus 同用。本次先各写各的,跑通后再合。

### 12.6 panel 文案无需快照
clearing 期间 `focusedEntity` 保留到 `finishClear` 才清,`panelText` 在滑出动画期间一直有效,故 PanelIntro **不需要** ContentLayer 那种淡出快照。

## 13. 一句话总结

把原 `focus.js` 的"一团 state + 模块级相机数学 + 散落 DOM"拆成 **focus store(数据)+ tickFocus(相机算法)+ 组件(点击/渲染 IO)**;沿用阶段 8 的三层范式与"时间是输入";迁移时顺手修掉"相机右方向退化"这个潜伏 bug,并澄清 `panelRatio` 的误导命名(值 0.5 正确、保留),其余忠实复刻原交互。
