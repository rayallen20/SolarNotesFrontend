## 2. 问题 1:右侧梯形与右边框重叠区域颜色不一致

### 2.1 现状(在 label 局部坐标系中复述几何)

```
.outer-decor-layer .right-trapezoid
    top: 0; right: -14px; width: 14px; height: 123px;
    clip-path: polygon(0 0, 14px 15px, 14px 108px, 0 123px);
    → 在 label 中占据 y ∈ [0, 123],x ∈ [width, width + 14]

.outer-decor-layer .right-bar
    top: 110px; right: -6px; bottom: 0; width: 6px;
    → 在 label 中占据 y ∈ [110, 286],x ∈ [width, width + 6]
```

**几何重叠区**:`y ∈ [110, 123]` × `x ∈ [width, width + 6]`(也就是右边框的最上 13 像素)。

### 2.2 根因 —— alpha 叠加

第一轮把垂直渐变改成:

```css
--vertical-grad: linear-gradient(
    180deg,
    rgba(81,188,255,1) 0%,
    rgba(81,188,255,0.1) 50%,
    rgba(81,188,255,1) 100%
);
```

中段 50%(对应 label y ≈ 143)是 alpha = 0.1。在 y = 110~123 区间(label 高度 286,所占百分比 ≈ 38.5% ~ 43%),按线性插值:

| y(label) | 单层 alpha(近似) |
| --- | --- |
| 110 | 1 − 0.9 × (38.5/50) ≈ **0.31** |
| 123 | 1 − 0.9 × (43/50) ≈ **0.23** |

两层堆叠后等效 alpha:

```
α_combined = 1 − (1 − α)²
y=110: 1 − 0.69² ≈ 0.52
y=123: 1 − 0.77² ≈ 0.41
```

**在 13 像素宽的重叠带里,显示的 alpha ≈ 0.41~0.52,而紧邻其上的右侧梯形单层只有 ≈ 0.23,紧邻其下的右边框单层只有 ≈ 0.31。**这就是肉眼看到的"颜色不一样"——重叠带显著更亮。

### 2.3 为什么原项目没有这个问题

原项目 `outerDecorLayer.css` 使用的是 `background: var(--border)`(纯色 `#20c6d8`,不透明)。两块纯色实色叠在一起,渲染结果与单层完全一致;只有引入 alpha 渐变后,叠加才产生差异。

### 2.4 修复方案对比

| 方案 | 思路 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A1(推荐)** | 把 `right-bar` 的 `top` 从 110 改为 123,即让它从右侧梯形终点开始 | 改动最小;不破坏渐变效果;不需要重构结构 | 可能与设计稿"右边框略向上探出 13 像素"的意图不一致(需对照设计稿确认) |
| A2 | 把 `right-trapezoid` 的高度从 123 改为 110(配合调整 clip-path),让它在右边框开始处正好结束 | 改动也很小 | 会失去梯形底部 15 像素的下斜边;视觉与设计稿差距更大 |
| A3 | 把右侧梯形 + 右边框合并为**一个元素**,用一个组合 clip-path 描述完整轮廓 | 几何上彻底消除重叠;只渲染一层,语义最清晰 | 需要重写 DOM 结构;clip-path 顶点最多达到 7~8 个;改动较大 |
| D | 把 `--vertical-grad` 改成不带 alpha 的纯色渐变(如把中段 alpha=0.1 改为某个等效深色) | 不需要调整几何 | 等效深色取决于该元素背后的页面底色,左右两侧装饰件背景不同(label 内部 vs label 外部),很难找到一个值同时正确;且会让水平/垂直渐变的"暗化机理"不一致(水平用 alpha,垂直用混色) |

### 2.5 推荐:方案 A1

```css
/* 修改前 */
.outer-decor-layer .right-bar {
    top: 110px;
    /* ... */
}

/* 修改后 */
.outer-decor-layer .right-bar {
    top: 123px;             /* = 右侧梯形高度 */
    /* ... */
    background-position: 0 -123px;   /* 同步切片偏移 */
}
```

实施时要点:

1. **同步更新 `background-position`**——按照第一轮文档"画布映射"原理,该位移必须等于元素自身在 label 中的 y 偏移。
2. 验证 label 局部坐标系下的视觉:重叠消失后,右上角应只有梯形,梯形结束后才出现右边框,二者衔接处不再有亮带。

### 2.6 如果设计稿确实要求 right-bar 提前 13 像素 → 选方案 A3

把两者合并为单一元素(`right: -14px; width: 14px; top: 0; bottom: 0;`),组合 clip-path 描述完整轮廓:

```css
.outer-decor-layer .right-rail {
    position: absolute;
    top: 0;
    right: -14px;
    width: 14px;
    bottom: 0;

    background-image: var(--vertical-grad);
    background-size: 100% var(--height);
    background-repeat: no-repeat;
    background-position: 0 0;

    /*
        组合轮廓(顶点近似计算,实际值需用 calc 表达):
        - (0,0) → (14,15) → (14,108) → (6, 116.57) :
            梯形上斜 + 中段竖直 + 一段下斜到 right-bar 的右边线 x=6
            116.57 = 108 + (14 − 6) × (123 − 108) / (14 − 0) = 108 + 8 × 15/14
        - (6, 116.57) → (6, 286) :
            沿 right-bar 右边线竖直到底
        - (6, 286) → (0, 286) → (0, 0) :
            底边 + 左边线回到起点
    */
    clip-path: polygon(
        0 0,
        14px 15px,
        14px 108px,
        6px calc(108px + 8px * 15 / 14),
        6px 100%,
        0 100%
    );
}
```

要点:

- 单层渲染,**根本上不可能产生重叠**;
- 顶点 `(6, 116.57)` 是梯形下斜边与 `x=6` 的交点,数学上由斜率 `(0−14)/(123−108) = −14/15` 推导;
- 模板里把原先两个 div 替换为一个 div(用类名 `right-rail` 或类似)。

## 3. 问题 2:斜纹条

### 3.1 问题 2.1 —— clip-path 末尾的尾随逗号

#### 现状

`SolarLabel.vue:573-582`:

```css
clip-path: polygon(
    var(--chip-slope-run) 0,
    var(--chip-width) 0,
    calc(var(--chip-width) - var(--chip-slope-run)) var(--chip-height),
    0 var(--chip-height),    /* ← 尾随逗号 */
);
```

CSS Values Level 4 规范不允许 `<polygon()>` 顶点列表末尾出现逗号。Chrome/Webkit 在严格模式下会**整体忽略该 `clip-path` 声明**。

#### 为什么"右下角看起来像被裁了"

虽然该 polygon 整体被忽略,但你的 chip(85 × 6)右侧一般紧邻 label 右上凹口外侧的视觉边界——当 label 自身 `clip-path`(`label-shape`)裁剪掉右上凹口的"楔形"时,这块区域恰好覆盖到了 chip 的右下角。这其实是 label 容器的裁剪,不是 chip 自己的 clip-path 在工作。

#### 修复

**删掉尾随逗号即可**:

```css
clip-path: polygon(
    var(--chip-slope-run) 0,
    var(--chip-width) 0,
    calc(var(--chip-width) - var(--chip-slope-run)) var(--chip-height),
    0 var(--chip-height)
);
```

修改后 chip 才会真正以平行四边形形态出现(左上 + 右下两角被切掉)。在此基础上才能进一步讨论问题 2.2 / 2.3。

### 3.2 问题 2.2 —— 凹口角度需重新测量

#### 现状

```css
--notch-start-x: 60px;
--notch-depth: 16px;
--notch-run-x: 16px;
```

`run = depth = 16` ⇒ slope = 1 ⇒ 45°。这是目测,凹口的真实角度需以 `label.png` 为准。

#### 测量方法

`label.png` 的像素尺寸与样式中的 426 × 286 不一致,但**斜率(rise / run)与缩放无关**,只要在同一张图上测量两个像素距离就行:

1. 在图像编辑器(Figma / Sketch / Photoshop / 浏览器开发者工具的截图测量)中打开 `label.png`。
2. 找到顶部凹口的左斜边:
   - `P1` = 凹口的起点(label 顶边水平线最右端,即斜边的起点);
   - `P2` = 凹口斜边到达水平段的拐点(斜边的终点)。
3. 读取像素差:
   - `Δx = P2.x − P1.x`(水平延伸量)
   - `Δy = P2.y − P1.y`(深度)
4. **真实斜率 k = Δy / Δx**。
5. 把样式里的两个变量按 `--notch-depth : --notch-run-x = Δy : Δx` 改写。最简单的做法是固定 `--notch-depth = 16px`(保持现有深度),把 `--notch-run-x` 改为 `16px / k`。

> **注意**:label 的左下凹口与顶部凹口在设计稿中是对称的,**改一处必须同步改另一处**。当前实现已经把两处都引用同一对 `--notch-depth` / `--notch-run-x`,因此只要改这两个变量,顶部和底部凹口同时变化。

#### 把斜率抽为共享变量,让 chip 复用

第一轮文档已经指出 chip 斜纹的斜率必须等于凹口的斜率。为了**改一处全局同步**,建议进一步抽变量:

```css
.solar-label {
    --notch-depth: 16px;
    --notch-run-x: 16px;        /* 改这两个值,凹口与 chip 同时变化 */
}

.outer-decor-layer .stripe-chip {
    --chip-height: 6px;
    /* chip 的斜边水平延伸量 = 按凹口同样斜率,放大/缩小到 chip 高度 */
    --chip-slope-run: calc(var(--chip-height) * var(--notch-run-x) / var(--notch-depth));
    /* ... */
}
```

这样:

- 修改 label 凹口的斜率,chip 的左上 / 右下切角自动跟随;
- 后面 3.3 节计算 6 个平行四边形所需的水平间距时,也能直接用同一对斜率变量。

### 3.3 问题 2.3 —— 在 85px 宽的 chip 内放正好 6 个有间隙的平行四边形

#### 现状

```css
background: repeating-linear-gradient(
    -45deg,
    transparent 0,
    transparent 1.2px,
    var(--border) 1.2px,
    var(--border) 9.64px
);
```

参数解读:gap = 1.2 px(垂直于条纹方向),stripe = 8.44 px,周期 P⊥ = 9.64 px。
两个问题:

1. 这些数值没有与 chip 宽度、高度、斜率挂钩,属于盲调;
2. **gap 仅 1.2 px 远小于 stripe 的 8.44 px**,视觉上几乎看不见间隙——这就是"为什么我看不到 6 个独立平行四边形"。

#### 方案对比

| 方案 | 思路 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **方案 A(推荐)** | 在模板里用 `v-for="n in 6"` 渲染 6 个 `<div class="stripe">`,每个 div 独立 clip-path 为平行四边形,用 flex 等距排开 | 几何上"6 个"是确定的;每条平行四边形的宽度、间隙、斜率都是显式参数,易于调试 | 需要往模板加 6 个子元素;CSS 多写一段,但代码量并不大 |
| 方案 B | 继续用 `repeating-linear-gradient`,根据"6 个周期正好填满 chip 中部水平宽度"来算参数 | 不需要改模板 | 数学耦合较深(下文给出公式);"正好 6 个"的视觉强烈依赖参数精度,对斜率变化敏感 |

#### 方案 A 详细做法(推荐)

**几何前提**:chip 宽 W = 85,高 H = 6,左/右切角的水平延伸量 = `--chip-slope-run`(记为 `s`,当前 slope=1 时 s=6;如果按 3.2 改成更平缓斜率,例如 slope=0.5,则 s=12)。

chip 内"可放平行四边形"的有效水平区间:

- 顶边可用范围:x ∈ [s, W],长度 W − s
- 底边可用范围:x ∈ [0, W − s],长度 W − s

(这两段长度相等,因为 chip 整体也是平行四边形。)

设每个内部平行四边形的"顶边宽" = `pw`,**相邻平行四边形顶边之间的水平间距** = `gap`。把 6 个平行四边形依次排开,顶边总占用:

```
6 × pw + 5 × gap = W − s
```

代入 W=85,先采用 slope=1(s=6),则 `6 × pw + 5 × gap = 79`。提供几组示例(按视觉上"间隙清晰"原则):

| pw | gap | 验算 6×pw + 5×gap |
| --- | --- | --- |
| 8 | 6.2 | 48 + 31 = 79 ✓ |
| 9 | 5 | 54 + 25 = 79 ✓ |
| 10 | 3.8 | 60 + 19 = 79 ✓ |

可优先尝试 `pw = 9 / gap = 5` 这类整数组合,再对照设计稿微调。

**模板**(scoped 块外不需要改任何东西):

```vue
<div class="stripe-chip">
    <div class="stripe" v-for="n in 6" :key="n"></div>
</div>
```

**样式**:

```css
.outer-decor-layer .stripe-chip {
    --chip-width: 85px;
    --chip-height: 6px;
    --chip-slope-run: calc(var(--chip-height) * var(--notch-run-x) / var(--notch-depth));

    /* 平行四边形参数(与 6×pw + 5×gap = chip-width − chip-slope-run 相协调) */
    --stripe-pw: 9px;
    --stripe-gap: 5px;

    position: absolute;
    top: 8px;
    right: 80px;
    width: var(--chip-width);
    height: var(--chip-height);

    /* chip 整体也是平行四边形(注意已删尾随逗号) */
    clip-path: polygon(
        var(--chip-slope-run) 0,
        var(--chip-width) 0,
        calc(var(--chip-width) - var(--chip-slope-run)) var(--chip-height),
        0 var(--chip-height)
    );

    /* 子元素水平排列;chip 内部不再用 background */
    display: flex;
    column-gap: var(--stripe-gap);
    /* 让子元素从顶边可用起点开始排;通过 padding-left 把首条 stripe 推到顶边的 x = chip-slope-run */
    padding-left: var(--chip-slope-run);
}

.outer-decor-layer .stripe-chip .stripe {
    flex: 0 0 var(--stripe-pw);
    height: 100%;
    background: var(--border);

    /* 每个内部平行四边形,与凹口同斜率 */
    clip-path: polygon(
        var(--chip-slope-run) 0,
        var(--stripe-pw) 0,
        calc(var(--stripe-pw) - var(--chip-slope-run)) var(--chip-height),
        0 var(--chip-height)
    );
}
```

要点说明:

1. 子 `.stripe` 的 clip-path 与外层 chip 共用 `--chip-slope-run`,自动与凹口同斜率;
2. `padding-left: var(--chip-slope-run)` 把第一根 stripe 推到 chip 顶边可用区间的起点;
3. 6 根 stripe + 5 个 gap 的总宽度 = `6 × pw + 5 × gap`,加上左 padding 的 `s`,合计 `6 × pw + 5 × gap + s`,正好等于 `(W − s) + s = W`,自洽。

#### 方案 B 详细做法(repeating-linear-gradient,备选)

如果不想加子元素,把 `repeating-linear-gradient` 的参数算清楚也能得到 6 段。关键是要把"6 段沿水平方向铺满 chip 顶边可用区间"换算成沿"垂直于条纹方向"的周期:

设斜率 k = `--notch-depth / --notch-run-x`,条纹倾角 θ = atan(k)(条纹方向相对水平方向的夹角)。"沿水平方向跨度 ΔX"对应"沿垂直于条纹方向跨度" ΔP⊥ = ΔX × sin(θ)。

要让 6 个周期正好填满顶边可用宽度 (W − s):

```
6 × P⊥ = (W − s) × sin(θ) = (W − s) × k / √(1 + k²)
P⊥ = (W − s) × k / [6 × √(1 + k²)]
```

把这个 P⊥ 拆成 stripe + gap 两段(常用 stripe : gap = 2 : 1 或 3 : 2),即可得到 `repeating-linear-gradient` 的 4 个色标位置:

```css
background: repeating-linear-gradient(
    /* 角度 = -(90° − θ) = θ − 90°,即垂直于条纹方向且向"右下→左上"方向递进 */
    /*   slope=1 时为 -45deg;slope=0.5 时为 -atan(0.5) − 90° ≈ -116.57°,等价于 +63.43° */
    /* 注意:CSS 中负角度与 (-θ + 360°) 等价,以视觉容易判断方向为准 */
    calc(atan2(var(--notch-depth), var(--notch-run-x)) - 90deg),
    transparent 0,
    transparent calc(var(--gap-perp)),
    var(--border) calc(var(--gap-perp)),
    var(--border) calc(var(--period-perp))
);
```

其中:

```css
--period-perp: calc(
    (var(--chip-width) - var(--chip-slope-run))
    * var(--notch-depth)
    / 6
    / sqrt(var(--notch-depth) * var(--notch-depth) + var(--notch-run-x) * var(--notch-run-x))
);
--gap-perp: calc(var(--period-perp) / 3);    /* stripe : gap = 2 : 1 */
```

> CSS Values Level 4 的 `atan2()` / `sqrt()` / `pow()` 已在主流浏览器(Chrome 111+、Safari 15.4+)落地,但若要兼顾老浏览器,建议直接把数值算好写成具体值,而不是依赖 CSS 三角函数。

可见相比方案 A,方案 B 写起来短但耦合更深;一旦凹口斜率变化、chip 宽度变化或 stripe:gap 比例变化,公式就要重新代入。**当 6 段是硬约束时,推荐直接选方案 A。**

## 5. 视觉验收清单

完成上述修改后,在浏览器里按下面顺序自检:

- [ ] **凹口斜率**:label 顶部凹口斜边的"水平延伸量 / 深度"与 `label.png` 中目测一致(可用浏览器截图后再次叠图)。
- [ ] **底部凹口对称**:label 底部凹口与顶部凹口斜率一致;深度也对称。
- [ ] **chip 整体形态**:chip 是平行四边形,**左上角和右下角**被切角,左下与右上保持直角(注意:不应是切了 3 个角的六边形)。
- [ ] **chip 内部 6 段**:能数出**正好 6 个**平行四边形;两两之间有清晰的间隙;每个平行四边形的斜边与 chip 整体斜边平行。
- [ ] **chip 与凹口斜率一致**:chip 整体外形的斜边、内部 6 段的斜边、label 凹口的斜边——三者目测平行。
- [ ] **右侧渐变连续**:在 label 右外侧,从 y=0 到 y=286 沿垂直方向扫视右侧梯形 → 右边框,亮度变化是单条平滑曲线(亮 → 暗 → 亮),没有局部亮带或暗带,也没有突然的颜色断裂。
- [ ] **左侧渐变连续**:同理,沿 y 方向扫视左侧轨道三段(top / middle / bottom)以及小矩形,亮度变化也是单条平滑曲线。
- [ ] **内部装饰梯形渐变正确**:左侧竖梯形(`Trapezoid`)所处 y 位置(26 ~ 59)所对应的渐变颜色,与同 y 位置的左侧轨道颜色一致(因为它们采样的是同一条画布)。
