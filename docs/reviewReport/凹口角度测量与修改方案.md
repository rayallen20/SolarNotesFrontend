# 凹口角度测量与修改方案

> 本文档基于 `label.png` 设计稿测量凹口的真实斜率,并给出
> (1) 边框层 SVG(顶部线 + 底部线),
> (2) 斜纹条
> 三处的具体修改方案。
>
> 底部凹口必须为按钮预留 146 像素的中段空缺,本文档已在所有计算中保留该约束。

---

## 1. 测量结果

### 1.1 测量方法

`label.png` 是设计稿截图,像素尺寸与 label 实际尺寸(426 × 286)不一致,但**斜率(rise / run)与缩放无关**——只要在同一张图上测量两个像素差,比值即等于设计中的真实斜率。

测量步骤:

1. 在 `label.png` 中找到顶部凹口的左斜边;
2. `P1` = 凹口起点(label 顶边水平线最右端,斜边的起点 — 视觉上 y=0 处);
3. `P2` = 凹口斜边到达水平段的拐点(斜边的终点 — 视觉上 y=深度处);
4. 读出像素差 `Δx = P2.x − P1.x`、`Δy = P2.y − P1.y`;
5. **真实斜率 k = Δy / Δx**。

### 1.2 我的测量

对 `label.png` 顶部凹口左斜边进行目测:

| 测量项 | 值 |
| --- | --- |
| 整个凹口的水平占用(slant + 平段 + slant)与 label 总宽的比例 | ≈ 70% |
| 平段(凹口底部水平线)与凹口总水平占用的比例 | ≈ 70% |
| 单侧斜边(slant)与凹口总水平占用的比例 | ≈ 15% |
| 凹口深度(slant 的垂直差)与 label 总高的比例 | ≈ 5.5% |

回推到设计坐标(label 宽 426,高 286):

| 测量量 | 估算值(设计坐标) |
| --- | --- |
| 凹口总水平占用 | ≈ 0.70 × 426 ≈ 298 px |
| 单侧斜边水平延伸 `Δx` | ≈ 0.15 × 298 ≈ **45 px** |
| 凹口深度 `Δy` | ≈ 0.055 × 286 ≈ **16 px** |
| **真实斜率 k = Δy / Δx** | ≈ **16 / 45 ≈ 0.35** |

### 1.3 推荐采用值

测量精度 ±20% 是合理的目测误差;为了得到一组**人类可读的整数**(便于后续手测和 hardcode 进 SVG),建议把斜率收敛到 `1 : 2` 或 `1 : 3` 这类干净比例。结合上面的测量:

| 候选 | --notch-depth | --notch-run-x | 斜率 k | 角度(相对水平方向) | 备注 |
| --- | --- | --- | --- | --- | --- |
| A(**推荐**) | 16 px(不动) | **48 px** | 1/3 ≈ 0.333 | ≈ 18.4° | 与目测最接近;run 是 depth 的 3 倍,记忆友好 |
| B | 16 px(不动) | 32 px | 1/2 = 0.5 | ≈ 26.6° | 偏陡一些,但与最初实现 16:16 跨度合理 |
| C | 16 px(不动) | 16 px(不动) | 1 | 45° | 当前值,**与设计稿明显不符,弃用** |

> **建议先以 A 落地**(`--notch-run-x: 48px`),改完在浏览器中与 `label.png` 叠图对比;
> 如视觉偏陡,再换 B(`32px`)。
> 全文的具体路径坐标都按 A 的取值给出。换 B 时只要重新代入 run = 32 即可。

### 1.4 该测量影响哪些可见区域

更新 `--notch-run-x` 之后,下列已经直接或间接绑定到这两个变量的几何会自动跟随:

- `label-shape` 的 `clip-path`(顶部凹口 + 底部凹口的两个斜边自动重算);
- `--top-notch-*` / `--bottom-notch-*` 一系列计算变量;
- 如果按本文档第 4 节把 `--chip-slope-run` 也改成"按比例"表达,斜纹条 chip 整体形状以及内部 6 个平行四边形的斜率全部自动同步。

**唯一不会自动跟随、必须手动改的**只有顶部线 / 底部线两个 SVG 里硬编码的 `<path d="...">` 数值——这正是第 3 节的内容。

## 2. 唯一需要改动的 CSS 变量

只改下面这 1 行:

```css
.solar-label {
    /* ... */
    --notch-run-x: 48px;     /* 由 16px 改为 48px */
    /* ... */
}
```

`--notch-depth` 保持 16 px 不变,因此:

- SVG 的 `viewBox="0 0 426 17"`(17 = depth 16 + 描边 1)**不需要改**;
- `.border-layer .top-line` / `.bottom-line` 的 `height: 17px`**不需要改**。

## 3. 边框层 SVG 修改

### 3.1 顶部线(`.top-line .top-svg`)

#### 关键坐标推导

在 SVG 的 `viewBox` 坐标系下,run 由 16 改为 48 后:

| 计算项 | 公式 | 旧值(run=16) | 新值(run=48) |
| --- | --- | --- | --- |
| 左斜边终点 X | `--notch-start-x + run` = `60 + run` | 76 | **108** |
| 凹口水平线宽度 | `426 − 2 × 60 − 2 × run` | 274 | **210** |
| 水平线终点 X | `60 + run + 水平线宽度` = `366 − run` | 350 | **318** |
| 右斜边终点 X | `366 − run + run` = 常数 366 | 366 | 366(不变) |

#### 新的路径 d 值(直接替换即可)

```svg
<!-- 1. 背景暗色带 (不变) -->
<rect x="0" y="0" width="426" height="2" fill="url(#bg-grad-top)"></rect>

<!-- 2.1 左直线: (0, 0.5) -> (60, 0.5)  不变 -->
<path d="M0 0.5 H60" .../>

<!-- 2.2 凹口: 右斜下 -> 水平 -> 右斜上
        旧: (60, 0.5) -> (76, 16.5) -> (350, 16.5) -> (366, 0.5)
        新: (60, 0.5) -> (108, 16.5) -> (318, 16.5) -> (366, 0.5) -->
<path d="M60 0.5 L108 16.5 H318 L366 0.5" .../>

<!-- 2.3 右直线: (366, 0.5) -> (426, 0.5)  不变 -->
<path d="M366 0.5 H426" .../>
```

只改一段(凹口段),首尾两段不变。

### 3.2 底部线(`.bottom-line .bottom-svg`)— 必须保留 146 px 按钮间隙

#### 按钮间隙推导

当前底部线分成 4 段;**两段中间留 146 px 给按钮**,按钮以 `--btn-center-x: 213px` 为中心,所以:

```
按钮左缘 = 213 − 146/2 = 140
按钮右缘 = 213 + 146/2 = 286
```

**重要发现:140 与 286 这两个边界是按钮约束,与 run 无关,改 run 时它们保持不变。**

#### 关键坐标推导(run = 48 时)

底部凹口与顶部凹口对称(只是上下反过来),所以斜边坐标和顶部相同:左斜 60→108,右斜 318→366。

| 段位 | 旧值(run=16) | 新值(run=48) |
| --- | --- | --- |
| 左直线 | M0 16.5 H60 | M0 16.5 H60(不变) |
| 左斜上 + 左半水平 | M60 16.5 L76 0.5 H140 | **M60 16.5 L108 0.5 H140** |
| 右半水平 + 右斜下 | M286 0.5 H350 L366 16.5 | **M286 0.5 H318 L366 16.5** |
| 右直线 | M366 16.5 H426 | M366 16.5 H426(不变) |

#### 新的路径 d 值(直接替换即可)

```svg
<!-- 1. 背景暗色带 (不变) -->
<rect x="0" y="15" width="426" height="2" fill="url(#bg-grad-bottom)"></rect>

<!-- 2.1 左直线 (不变) -->
<path d="M0 16.5 H60" .../>

<!-- 2.2.1 右斜上 -> 右水平: (60,16.5) -> (108, 0.5) -> (140, 0.5) -->
<path d="M60 16.5 L108 0.5 H140" .../>

<!-- 2.2.2 右水平 -> 右斜下: (286, 0.5) -> (318, 0.5) -> (366, 16.5) -->
<path d="M286 0.5 H318 L366 16.5" .../>

<!-- 2.3 右直线 (不变) -->
<path d="M366 16.5 H426" .../>
```

#### 几何自检

```
左半可见水平段宽度 = 140 − 108 = 32 px(原来是 140 − 76 = 64 px)
按钮间隙宽度       = 286 − 140 = 146 px(不变,符合按钮约束)
右半可见水平段宽度 = 318 − 286 = 32 px(原来是 350 − 286 = 64 px)
凹口总水平占用     = 32 + 146 + 32 = 210 px(== 顶部凹口的水平线宽度,自洽)

凹口总宽 + 两端斜边 + 两端直线 = 48 + 210 + 48 + 60 + 60 = 426 ✓
```

按钮(146 px)与可见水平段(2 × 32 = 64 px)合计 210 px——正好是凹口的水平段总宽。

> **若选 B 方案(run=32)**:把上面所有 `108` 换成 `92`,所有 `318` 换成 `334`;按钮边界 140 / 286 不变;左/右半可见水平段变为 48 px。

> **若选其他 run**(例如 run = 40):必须满足 `run < 80`,否则 `80 − run = 0`(可见水平段消失,凹口直接撞上按钮边界)。

## 4. 斜纹条修改

### 4.1 让 chip 的斜率自动跟随 `--notch-run-x`

```css
.outer-decor-layer .stripe-chip {
    --chip-width: 85px;
    --chip-height: 6px;

    /* 旧:--chip-slope-run: var(--chip-height);     /* 假设 slope = 1 */
    /* 新:斜率与凹口同步 */
    --chip-slope-run: calc(
        var(--chip-height) * var(--notch-run-x) / var(--notch-depth)
    );
    /* ... */
}
```

代入 chip-height = 6, notch-run-x = 48, notch-depth = 16:

```
chip-slope-run = 6 × 48 / 16 = 18 px
```

也就是说,chip 整体平行四边形的两端斜边水平延伸为 **18 px**。

chip 内部"可放平行四边形"的有效水平长度:

```
W − chip-slope-run = 85 − 18 = 67 px
```

### 4.2 6 个有间隙平行四边形的参数

**约束**:`6 × pw + 5 × gap = 67`,其中 pw = 单条平行四边形顶边宽,gap = 相邻顶边水平间距。

| 候选 | pw | gap | 验算 6×pw + 5×gap |
| --- | --- | --- | --- |
| **推荐** | 7 px | 5 px | 42 + 25 = **67** ✓ |
| 备选 | 8 px | 3.8 px | 48 + 19 = **67** ✓ |
| 备选 | 6 px | 6.2 px | 36 + 31 = **67** ✓ |

推荐 `pw=7, gap=5`,均为整数像素,渲染清晰。

### 4.3 模板与样式(完整替换 chip 部分)

#### 模板

把 `.stripe-chip` 改成有 6 个子节点的容器:

```vue
<!-- 斜纹条开始 -->
<div class="stripe-chip">
    <div
        class="stripe"
        v-for="n in 6"
        :key="n"
        :style="`--i: ${n - 1}`"
    ></div>
</div>
<!-- 斜纹条结束 -->
```

#### 样式

```css
/* 斜纹条开始 */
.outer-decor-layer .stripe-chip {
    --chip-width: 85px;
    --chip-height: 6px;
    /* chip 斜率与凹口同步 */
    --chip-slope-run: calc(
        var(--chip-height) * var(--notch-run-x) / var(--notch-depth)
    );
    /* 6 段平行四边形参数:6×pw + 5×gap = chip-width − chip-slope-run = 67 */
    --stripe-width: 7px;
    --stripe-gap: 5px;

    position: absolute;
    top: 8px;
    right: 80px;
    width: var(--chip-width);
    height: var(--chip-height);

    /* chip 整体平行四边形(切左上 + 右下两角,注意末尾无逗号) */
    clip-path: polygon(
        var(--chip-slope-run) 0,
        var(--chip-width) 0,
        calc(var(--chip-width) - var(--chip-slope-run)) var(--chip-height),
        0 var(--chip-height)
    );
}

/* 内部 6 个平行四边形 */
.outer-decor-layer .stripe-chip .stripe {
    position: absolute;
    top: 0;
    height: 100%;

    /*
        每条 stripe 的盒子宽度 = 顶边宽 + 斜边水平延伸量
        因为 stripe 是平行四边形,顶边比底边偏右 chip-slope-run 像素
    */
    width: calc(var(--stripe-width) + var(--chip-slope-run));

    /*
        --i 由模板提供(0 ~ 5),决定该 stripe 在水平方向上的位置
        相邻 stripe 的盒子起点相距 (pw + gap)
    */
    left: calc(var(--i) * (var(--stripe-width) + var(--stripe-gap)));

    background: var(--border);

    /* 内部平行四边形与外层 chip 同斜率 */
    clip-path: polygon(
        var(--chip-slope-run) 0,
        100% 0,
        calc(100% - var(--chip-slope-run)) 100%,
        0 100%
    );
}
/* 斜纹条结束 */
```

### 4.4 几何自检(代入 run=48 后)

| 项 | 计算 | 结果 |
| --- | --- | --- |
| chip 顶边可用范围 | x ∈ [chip-slope-run, chip-width] = [18, 85] | 长 67 px |
| chip 底边可用范围 | x ∈ [0, chip-width − chip-slope-run] = [0, 67] | 长 67 px |
| 第 1 条 stripe 盒子 | left=0,宽=`pw+slope-run`=7+18=25 | x ∈ [0, 25] |
| 第 1 条 stripe 顶边(clip 后) | x ∈ [18, 25] | 长 7 px ✓(=pw) |
| 第 1 条 stripe 底边(clip 后) | x ∈ [0, 7] | 长 7 px ✓ |
| 第 6 条 stripe 盒子 | left=5×(7+5)=60,宽=25 | x ∈ [60, 85] |
| 第 6 条 stripe 顶边(clip 后) | x ∈ [78, 85] | 长 7 px ✓,正好抵 chip 顶边右端 |
| 第 6 条 stripe 底边(clip 后) | x ∈ [60, 67] | 长 7 px ✓,正好抵 chip 底边右端 |
| 顶边相邻间隙 | (60+18) − (0+25) = 53 → 等差 13 验证 | 每对相邻顶边间隙 = (pw+gap) − pw = gap = 5 px ✓ |

> **若选 B 方案(run=32)**:chip-slope-run 自动算成 12;有效水平长度变 73;按 `6×pw + 5×gap = 73` 重新选参数(例如 `pw=8, gap=5`,验算 48+25=73 ✓)。

## 5. 实施顺序

按依赖顺序排列:

| 步骤 | 内容 | 影响范围 |
| --- | --- | --- |
| 1 | `--notch-run-x` 由 16 改为 48 | label-shape 的 clip-path 与 chip 的 chip-slope-run 自动跟随;SVG 路径暂时仍是旧的(下一步处理) |
| 2 | 顶部线 SVG:把第 2 条 path 的 d 值替换为 `M60 0.5 L108 16.5 H318 L366 0.5` | 顶部边框线条与 label-shape 的顶部凹口对齐 |
| 3 | 底部线 SVG:把第 2、3 条 path 替换为 `M60 16.5 L108 0.5 H140` 和 `M286 0.5 H318 L366 16.5` | 底部边框线条与 label-shape 的底部凹口对齐;按钮间隙保持 146 px |
| 4 | `.stripe-chip` 的 `--chip-slope-run` 改成按比例计算;模板加入 6 个子 div;按 4.3 节填入 stripe 样式 | chip 形状变为正确的 6 段平行四边形,斜率与凹口同步 |
| 5 | 浏览器验证:把页面截图与 `label.png` 叠图比对凹口斜率;若偏陡或偏缓,微调 `--notch-run-x` 后重新跑步骤 2、3(只需要替换 SVG 中的 `108` 与 `318` 这两个数) | — |

## 6. 验收清单

完成上述改动后,在浏览器中按下面顺序自检:

- [ ] **顶部线条贴合 label-shape**:label-shape 的顶部凹口边界与 top-line SVG 中的折线**完全重合**(没有错位的"双重边框")。
- [ ] **底部线条贴合 label-shape**:同理,底部凹口的折线与 label-shape 凹口完全重合。
- [ ] **按钮间隙正确**:底部凹口的水平线在 x ∈ [140, 286] 内**完全空缺**,可以直接放下 146 px 宽的按钮。
- [ ] **凹口斜率与设计稿一致**:把浏览器渲染结果截屏,与 `label.png` 叠加,凹口的两条斜边目测平行(误差 ≤ 2°)。
- [ ] **顶/底凹口对称**:顶部凹口的左斜边与底部凹口的右斜边平行,顶部凹口的右斜边与底部凹口的左斜边平行(因为它们斜率绝对值相同,符号相反)。
- [ ] **chip 整体形态**:chip 是平行四边形,**左上和右下被切角**,左下与右上保持直角。
- [ ] **chip 内部 6 段**:能数出**正好 6 个平行四边形**;两两之间有清晰的水平间隙(约 5 px)。
- [ ] **chip 与凹口斜率一致**:chip 整体外形的斜边、内部 6 段的斜边、label 顶部凹口的斜边——三者目测平行。

## 7. 备注

- 测量值 1/3(run=48)是基于 `label.png` 截图的目测估计;如果有原始矢量稿(Figma / Sketch / Adobe XD 文件),建议直接读取凹口的 path 节点坐标得到精确斜率,再回填进 `--notch-run-x`。
- 若日后斜率再次变更,**只需要改两处**:CSS 里的 `--notch-run-x`,以及 SVG 两条 path 中的 4 个数(顶部线 `108` / `318`,底部线 `108` / `318`)。其它一切几何会沿着 CSS 变量自动重算。
- 如果 `--notch-depth` 也需要更改(例如 depth 改为 12 或 20),需要额外同步:
    - SVG `viewBox` 的高度(由 17 改为 `depth + 1`);
    - `.top-line` / `.bottom-line` 的 `height`;
    - SVG path 中所有 `16.5` / `0.5` 的 y 坐标(改为 `depth + 0.5` / `0.5`)。
- 当前 chip 实现里如果还残留上一轮文档指出的 `clip-path` **尾随逗号**问题,本文档第 4.3 节给出的样式已经是正确版本,直接替换即可顺带修复。
