## 2. 问题 1:垂直方向"整体"线性渐变缺失

### 2.1 现状

水平方向(顶部/底部线条)已通过 SVG `<linearGradient gradientUnits="userSpaceOnUse">` 实现 0% → 50% → 100% 的"亮 → 暗 → 亮"渐变。

垂直方向上,以下元素当前都用 `var(--border)` 纯色:

|                 元素                  |              位置(相对 label 顶)               |
|:-----------------------------------:|:---------------------------------------------:|
|       `.left-rail .seg.top`         |             y = 0..162                        |
|      `.left-rail .seg.middle`       |             y = 162..215                      |
|      `.left-rail .seg.bottom`       |             y = 215..286                      |
| `.inner-decor-layer .left`(Trapezoid) |          y = 26..59                       |
|  `.outer-decor-layer .rectangle`    |             y = 163..170                      |
| `.outer-decor-layer .right-trapezoid` |             y = 0..123                       |
|     `.outer-decor-layer .right-bar`     |             y = 110..286                     |

### 2.2 「整体渐变」的含义

水平方向已经是「单条渐变在 0..426 走完一圈」:左端亮 → 中间暗 → 右端亮。

同理,垂直方向应在 0..286(label 高度)走完一圈:**顶端亮 → 中间暗 → 底端亮**。

关键约束:每段 / 每个装饰件**只画自己负责的那一段切片**,而不是各自从 0 重新走一遍。

### 2.3 朴素做法为什么不行

如果给每个段直接写:

```css
.seg {
    background: linear-gradient(180deg,
        rgba(81,188,255,1) 0%,
        rgba(81,188,255,0.1) 50%,
        rgba(81,188,255,1) 100%);
}
```

每段会**基于自身 bounding box** 解析渐变,意味着:

- 顶段在 y = 81 处出现暗谷
- 中段在 y ≈ 188 处再来一个暗谷
- 底段在 y ≈ 250 处又一个暗谷

视觉上看到三轮"亮 - 暗 - 亮"循环,而不是设计稿想要的一条贯穿。

### 2.4 解决方案 A:CSS 背景画布映射(推荐)

核心思路:让每个元素的 **背景图像大小固定为 label 总高**,再用 `background-position` 把当前元素对应的"切片"挪到自身可见区域。

```css
.solar-label {
    --vertical-grad: linear-gradient(180deg,
        rgba(81,188,255,1) 0%,
        rgba(81,188,255,0.1) 50%,
        rgba(81,188,255,1) 100%);
}

/* 左侧轨道 3 段 */
.seg {
    position: absolute;
    background-image: var(--vertical-grad);
    background-size: 100% var(--height);
    background-repeat: no-repeat;
}

.left-rail .top    { background-position: 0 0; }
.left-rail .middle { background-position: 0 calc(-1 * var(--left-rail-top-height)); }
.left-rail .bottom { background-position: 0 calc(-1 * (var(--height) - var(--left-rail-bottom-height))); }
```

**原理**:`background-size: 100% 286px` 把渐变图绘成全 label 高;`background-position: 0 -162px`(中段例)再把图像向上平移 162 像素,中段就只露出"渐变图 y = 162..215"那 53 像素切片——正好是它在整体渐变上应该显示的部分。

**对外部装饰件层** 同理(三个元素都基于 `.outer-decor-layer` 定位,而 `.outer-decor-layer` 又 `inset: 0`,坐标系 = label 全高):

```css
.outer-decor-layer .seg,
.outer-decor-layer .right-trapezoid,
.outer-decor-layer .right-bar {
    background-image: var(--vertical-grad);
    background-size: 100% var(--height);
    background-repeat: no-repeat;
}

.outer-decor-layer .rectangle      { background-position: 0 calc(-1 * (var(--left-rail-top-height) + 1px)); }
.outer-decor-layer .right-trapezoid { background-position: 0 0; }
.outer-decor-layer .right-bar      { background-position: 0 -110px; }
```

clip-path 不影响背景渲染顺序(背景先画好再被 clip 裁剪),所以 `right-trapezoid`(带 `polygon(...)` clip-path)和后面问题 2 中要新加 clip-path 的 `stripe-chip` 都适用。

### 2.5 关于 `Trapezoid` 组件的复用

约束:Trapezoid 在两处复用——

- **label** 内部装饰件层(`top: 26px; height: 33px`,要分享 label 的 286px 整体渐变)
- **panel** 长内容区列表项(每个 `flexItem` 一个,各自独立显示,不需要外部坐标系)

不能在 Trapezoid 内部硬编码 `286` / `26` 这种和 label 紧耦合的常量。

**API 方案**:Trapezoid 内部预留两个 CSS 变量,有默认值(本地渐变),调用方按需覆盖即可:

```css
/* Trapezoid.vue (scoped) */
.trapezoid {
    /* 默认:渐变范围 = 元素自身,等同"局部渐变",panel 中的列表项直接生效 */
    --gradient-height: 100%;
    --gradient-offset: 0px;

    width: 8px;
    height: 33px;
    background-image: var(--vertical-grad,
        linear-gradient(180deg,
            rgba(81,188,255,1) 0%,
            rgba(81,188,255,0.1) 50%,
            rgba(81,188,255,1) 100%));
    background-size: 100% var(--gradient-height);
    background-position: 0 calc(-1 * var(--gradient-offset));
    background-repeat: no-repeat;
    clip-path: polygon(0 0, 8px 5px, 8px 28px, 0 33px);
}
```

```css
/* SolarLabel.vue */
.label-shape .inner-decor-layer .left {
    position: absolute;
    top: 26px;
    left: 3px;
    --gradient-height: var(--height);   /* 286 */
    --gradient-offset: 26px;            /* 自身 top */
}
```

panel 中将来不传任何变量,自动使用本地渐变。

> **为什么用 CSS 变量而不是 prop**:CSS 变量天然走 cascade,scoped 样式不阻断变量继承,父组件只需在选择器里声明,子组件自动收到。这避免了"凡是要传渐变参数都得加一对 prop"的样板代码,保留了 Trapezoid 作为纯样式组件的简洁性。

### 2.6 解决方案 B:SVG 路径(备选)

把所有需要垂直渐变的元素都改造成 SVG `<rect>` / `<polygon>`,放进一个共享 `<defs><linearGradient gradientUnits="userSpaceOnUse" x1="0" y1="0" x2="0" y2="286">` 的 SVG 里。

|     维度     |              方案 A(CSS)              |              方案 B(SVG)              |
|:----------:|:--------------------------------------:|:--------------------------------------:|
|  实现成本    |             低(纯 CSS,几行)               |             高(每元素重画 SVG)             |
|   几何精度   |  依赖浏览器对 background-position 的子像素处理   |  矢量精确,与水平 SVG 渐变方案对称                |
|  Trapezoid 复用 |        CSS 变量级联,自动继承                |   要么传 SVG 坐标 prop,要么再做一层封装         |
|   维护成本   |             低                           | 高(label / panel 用同一组件时还要分别处理 viewBox) |

推荐先走 A,只有在调试时发现段交界处出现可见亮度跳变 / 子像素错位时再升级为 B。

### 2.7 推荐落地顺序

1. 在 `.solar-label` 上提取 `--vertical-grad` 集中管理"亮 → 暗 → 亮"渐变定义
2. `.seg` / `.right-trapezoid` / `.right-bar` 改用 `background-image: var(--vertical-grad)` + `background-size: 100% var(--height)` + 各自的 `background-position`
3. `Trapezoid.vue`:把硬编码的 `var(--border)` 换成方案 A 写法,默认 `--gradient-height: 100%; --gradient-offset: 0;`
4. `SolarLabel.vue` 在 `.label-shape .inner-decor-layer .left` 选择器中注入 `--gradient-height: var(--height); --gradient-offset: 26px;`
5. 浏览器肉眼验证:label 顶端 / 底端最亮,垂直中线(y = 143)最暗;三段左轨道在 y = 162 / 215 交界处亮度**连续**(没有跳变),与水平方向渐变形成"四角最亮、中心最暗"的对称视觉

## 3. 问题 2:斜纹条样式与设计稿不符

### 3.1 现状

```css
.outer-decor-layer .stripe-chip {
    position: absolute;
    top: 8px;
    right: 80px;
    width: 90px;
    height: 6px;
    background: repeating-linear-gradient(
        -40deg,
        transparent 0,
        transparent 1.2px,
        var(--border) 1.2px,
        var(--border) 9.64px
    );
}
```

两处偏差:

|                偏差                |                              说明                              |
|:--------------------------------:|:-------------------------------------------------------------:|
|         角度 `-40deg`          |             估算值,无几何依据,设计稿主凹口是 1:1 即 45°            |
| 没有给 stripe-chip 加 `clip-path` | 设计稿里 chip 实际是带斜切边的**平行四边形**,所以两端的"凹口"完全没体现 |

### 3.2 设计稿真相

`label.png` 中 stripe-chip 的形状是**平行四边形**:左下 / 右上两端各被斜切掉一个三角。
两端斜切边的斜率与内部斜纹的斜率**完全一致**——这就是用户描述的"斜纹条右侧凹口的斜率"。

斜率来源:label 上下凹口的几何参数 `--notch-run-x: 16px`、`--notch-depth: 16px`,即 1:1,对应 45°。stripe-chip 沿用这一斜率以视觉一致。

### 3.3 关键洞察:角度 = 斜切边角度,二者必须联动

无论用 `repeating-linear-gradient` 还是 SVG `<pattern>`,**斜纹的方向必须等于 clip-path 斜切边的方向**。否则斜纹和"凹口"会"打架"——一个朝左,一个朝右,视觉错乱。

数学上:

|     量     |               值                |
|:--------:|:------------------------------:|
| chip 高度  |             6 px              |
| 斜率(rise/run) |             1                  |
| 斜切边水平投影 |   chip-height ÷ 斜率 = 6 ÷ 1 = 6 px |
|    角度    |          atan(1) = 45°         |

### 3.4 解决方案

```css
.outer-decor-layer .stripe-chip {
    position: absolute;
    top: 8px;
    right: 80px;
    width: 90px;
    height: 6px;

    /* 平行四边形:两个相对的斜切边斜率均为 1 */
    clip-path: polygon(
        6px 0,            /* 上左:从 x=6 起 */
        90px 0,           /* 上右 */
        84px 6px,         /* 下右:相对上右向左 6px */
        0 6px             /* 下左 */
    );

    background: repeating-linear-gradient(
        -45deg,           /* 斜纹方向 = 斜切边方向 */
        transparent 0,
        transparent 1.2px,
        var(--border) 1.2px,
        var(--border) 9.64px
    );
}
```

**关于角度方向**:`-45deg` 等同于 `315deg` / `135deg`(repeating-linear-gradient 旋转 180° 后视觉一致)。`label.png` 中斜纹观感是 `/` 方向(从左下到右上),所以选 `-45deg`;若实测发现是 `\` 方向,改用 `45deg`,**clip-path 也要同步翻转为** `polygon(0 0, 84px 0, 90px 6px, 6px 6px)`(把斜切边反过来)。

### 3.5 几何参数化(可选优化)

为了让斜率以后改起来不用动多个值,可以把几何抽到 CSS 变量:

```css
.outer-decor-layer .stripe-chip {
    --chip-w: 90px;
    --chip-h: 6px;
    --chip-slope-run: var(--chip-h);   /* = chip-h / slope = 6 / 1 = 6px */

    width: var(--chip-w);
    height: var(--chip-h);
    clip-path: polygon(
        var(--chip-slope-run) 0,
        var(--chip-w) 0,
        calc(var(--chip-w) - var(--chip-slope-run)) var(--chip-h),
        0 var(--chip-h)
    );
}
```

这样将来若设计师把斜率改成 1:2,只改 `--chip-slope-run: calc(var(--chip-h) * 2);`,clip-path 自动跟随。`repeating-linear-gradient` 的角度还是要单独算(`atan2(chip-h, chip-slope-run)`),这一项 CSS 不能完全自动化。

### 3.6 备选:SVG 实现

CSS `repeating-linear-gradient` 在亚像素尺度受浏览器锯齿影响,且和 clip-path 边缘可能存在 1px 左右的错位。如果调试时肉眼能看出错位:

- 用 SVG 画一个底图 polygon,用 `<defs><pattern>` 定义斜纹,polygon `fill="url(#pattern-id)"`
- pattern 的 patternTransform 旋转角度严格匹配斜切边

精确度更高但工作量更大。建议先走 CSS 方案,有问题再升级。
